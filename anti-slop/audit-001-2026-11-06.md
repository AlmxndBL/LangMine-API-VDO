- ตรวจ SCRIPT.md, STORYBOARD.md, video/index.html, video/motion.js, evidence/ASSETS-v1.md, voice-timing.json และ REVIEW-v1.md
- ดู mobile-frames.jpg จริงในรอบตรวจ EP01 ต่อเนื่องนี้

- ผู้ใช้รายงานว่าเสียงฟังแล้วอยากปิด ถือเป็น feedback ของผู้ชม ไม่ใช่ข้อสรุปจาก waveform
- 33.16 วินาทีคือ sample B04–B05 ไม่ใช่เพดานทั้งตอน ผู้ใช้กำหนดให้ความเข้าใจเป็นเกณฑ์ ความยาว 80–100 วินาทีในบทเดิมเป็นประมาณการ ไม่ใช่ requirement

## Findings

1. HIGH, R-35 (การตรวจสื่อจริง), workflow Audio gate: ยังไม่มีหลักฐานการฟังทวนก่อนเสนอขยายการผลิต
   REVIEW-v1 ระบุเองว่ายังค้างการฟังเสียง การออกเสียง LangMind/API และอ่านซับพร้อมภาพ ข้อมูล PCM และการมี AAC ไม่รับรองคุณภาพการเล่า วิธีแก้: ผ่านการฟัง voice audition และ sample พร้อมภาพก่อนล็อก timeline เต็ม เกณฑ์ click-through ของแอปไม่ใช้กับ MP4

2. MEDIUM, R-19/R-31 (purpose ของจังหวะ), workflow Audio gate: การพักเสียงซ้อนทำให้จังหวะขาดช่วง
   บัญชี assets ระบุ Edge TTS th-TH-NiwatNeural rate -6% แบ่ง 7 วลี และ holds รวม 7.6 วินาที ผลวัด silence ที่ -40 dB ขั้นต่ำ 0.3 วินาทีพบ 7 ช่วงรวม 15.289667 วินาที ประมาณ 46.1% ของไฟล์ ไม่ใช่ค่ามาตรฐานตัดสินเสียงดีหรือเสีย แต่เป็นหลักฐานว่าต้องทวนจุดพักรายจังหวะ ช่วงเงียบเริ่มก่อนจบวลีตาม metadata จึงสอดคล้องกับการมี padding ในไฟล์วลีแล้วเติม hold อีกชั้น ยังไม่มี generation script ให้ยืนยันต้นเหตุทุกขั้น วิธีแก้: ตรวจขอบเสียงจริง trim เฉพาะ padding รักษาพยัญชนะท้ายและลมหายใจ แล้วกำหนด pause ตามความหมาย/เวลาอ่านภาพ ไม่ใช้ความยาวไฟล์เป็นเวลาพูดทั้งหมด

3. HIGH, R-02 (ภาษาธรรมชาติ), copywriting rhythm: บท sample เป็นคำอธิบายแบบป้ายมากกว่าบทพูดต่อเนื่อง
   ตัวอย่าง “หน้าจอกับการเชื่อมต่อ เป็นส่วนที่เราทำ” กระชับแต่ยังนามธรรมสำหรับผู้เริ่มต้น และคำ แอป/ระบบของแอป/คำถาม/คำตอบ ถูกกล่าวติดกันหลายวลี ทำให้ต้องจำศัพท์แทนเห็นเหตุผล วิธีแก้: เขียนเป็นย่อหน้าภาษาพูดที่อธิบายเหตุการณ์และเหตุผลให้ครบก่อนค่อยแบ่งซับ ใช้คำชี้ที่มีภาพรองรับ ไม่สังเคราะห์แยกตามบรรทัดซับโดยอัตโนมัติ การตัดสินจังหวะพูดจริงยังรอฟัง

4. MEDIUM, R-19/R-31: เสียงร่างถูกผูกกับ timing ละเอียดก่อนยืนยัน delivery
   index.html และ motion.js ฝังเวลาจากเสียงร่างถึงระดับทศนิยม การเปลี่ยนเสียงหรือ pause จะกระทบซับ เส้นทาง และการเปลี่ยนภาพ วิธีแก้: ทำเสียงที่ฟังต่อเนื่องและเข้าใจได้ก่อน จากนั้นใช้เสียงเป็นฐานปรับภาพและซับ พร้อมเว้นจุดให้มองภาพ ไม่เร่งหรือยืดเสียงเพื่อให้ลงเวลาเดิม

## สมมติฐานที่ต้องทดลอง ไม่ใช่ข้อกล่าวหาตัว provider

เสียง NiwatNeural อาจไม่เข้ากับโทนผู้เล่า ภาษาไทยปน LangMind/AI/API อาจออกเสียงหรือลงน้ำหนักไม่ตรงเจตนา และการสร้างทีละวลีอาจ reset น้ำเสียงทุกช่วง Metadata ไม่พิสูจน์ว่าเกิดข้อใดจริง ต้องฟังเปรียบเทียบย่อหน้าเดียวกันทั้งแบบต่อเนื่องกับแยกวลี และเปรียบเทียบ candidate voices ก่อนเลือก ไม่สรุปว่าทุกเสียง TTS ใช้ไม่ได้ หรือการเปลี่ยน provider จะแก้ทั้งหมด

## แนวทางแก้ตามลำดับ

1. รักษาภาษาภาพกระดาษ/เส้นวาด/หน้าจอที่มีอยู่ ปรับเฉพาะจังหวะที่รองรับความเข้าใจ
2. เขียนบทร่างแบบพูดจริงทั้งเรื่อง ไม่ล็อก 33 วินาทีหรือ 80–100 วินาที แยกความหมายของ API, งานแอป และงาน LangMind ให้เห็นเหตุผล
3. ทดลองเสียงจากย่อหน้าที่มีคำถาม คำอังกฤษ และจุดเน้นครบ ให้ฟังต่อเนื่องก่อนทำทั้งตอน การสร้างตัวอย่างเสียงใหม่ยังไม่ได้ทำในงาน audit นี้
4. ตรวจ padding และ pause ในเสียงที่เลือก แล้วค่อยจัดภาพ ซับ และ hold ตามเสียง/เวลาอ่านที่ตรวจจริง
5. ฟังบนมือถือพร้อมภาพ ทดสอบผู้เริ่มต้นเล่าย้อนโดยไม่ใช้คำตอบนำ: API คืออะไร ใครส่งคำถาม ใครแสดงผล และ developer ยังต้องทำอะไร

ไม่เติมเพลงหรือ EQ เพื่อกลบ delivery ที่ยังไม่ผ่าน ไม่เพิ่มความยาวด้วยความเงียบหรือคำอธิบายซ้ำ

## Delivery gate ของรายงาน

- PASS, evidence honesty (R-17/R-36): ตัวเลขมาจากไฟล์และคำสั่งจริง แยก feedback, observed และ hypothesis
- PASS, scope: เพิ่มเฉพาะ audit report ไม่แก้ production files ไม่สร้างเสียงใหม่ ไม่เรียก paid/live API
- PASS, applicability: ใช้กฎด้านภาพ/ข้อความ/จังหวะกับสื่อ ไม่บังคับ keyboard, nav, form หรือ theme controls ใน MP4
