# EP11 — บทสำหรับสร้างเสียง (Agents & Versioning API)

เมื่อพร้อมสร้างเสียง ให้ใช้บทนี้สร้างไฟล์ wav/mp3 ใส่ใน `assets/voice/` แล้วรัน `node build.mjs`

## b1 → assets/voice/b1.wav
เวลาที่เรามี Agent ใช้งานจริงอยู่ แล้วอยากปรับปรุง Prompt หรือเปลี่ยนค่าโมเดล จะทำอย่างไรไม่ให้กระทบลูกค้าที่กำลังคุยอยู่ และถ้าปรับแล้วผลลัพธ์ไม่เป็นไปตามคาด จะย้อนกลับไปเวอร์ชันเดิมทันทีได้อย่างไร ถ้าอยากจัดการรุ่นของ Agent แบบมืออาชีพ ต้องเตรียมอะไร เชื่อมตรงไหน และเอาผลไปใช้ยังไง มาดูกันครับ

## b2 → assets/voice/b2.wav
ภาพรวมของฟีเจอร์นี้คือการแยกเวอร์ชันที่ใช้งานจริง หรือ published ออกจากฉบับร่าง หรือ draft โดยระบบหลังบ้านของเราจะเรียก Agents API สามขั้นตอนหลัก คือ เช็กโมเดลและสร้าง Agent บันทึกการแก้ไขเป็นเวอร์ชันร่าง และสั่ง publish เพื่อเปิดใช้งานจริง หรือสั่ง rollback เพื่อย้อนกลับครับ

## b3 → assets/voice/b3.wav
เริ่มจากสิ่งที่ต้องเตรียม อย่างแรกคือตั้งค่า Credential ของโมเดลบนเว็บให้พร้อม อย่างที่สองคือ API Key ที่มีสิทธิ์ agents read สำหรับอ่านข้อมูลโมเดลและประวัติเวอร์ชัน และสิทธิ์ agents write สำหรับสร้าง แก้ไข และเปลี่ยนเวอร์ชัน อย่างที่สามคือระบบหลังบ้านหรือสคริปต์ที่เก็บ Key ไว้อย่างปลอดภัยครับ

## b4 → assets/voice/b4.wav
มาดูการเชื่อมครั้งที่หนึ่ง การเช็กโมเดลและสร้าง Agent ก่อนสร้างให้เรียก GET ไปที่ providers models เพื่อดูรายชื่อ provider และโมเดลที่เราได้รับสิทธิ์ใช้งานในคำตอบเดียว จากนั้นนำค่า provider type เช่น openrouter และ model name มาส่ง POST ที่ agents พร้อมชื่อและคำสั่งเริ่มต้น ระบบจะสร้าง Agent และ publish เวอร์ชันที่หนึ่งให้อัตโนมัติครับ

## b5 → assets/voice/b5.wav
ครั้งที่สอง การบันทึกเวอร์ชันใหม่เป็นฉบับร่าง เมื่อต้องการปรับ Prompt หรือค่า generation อย่าง temperature และ max tokens ให้ส่ง POST ไปที่ agents ตามด้วย ID และ versions พร้อมระบุหมายเหตุ note และตั้งค่า publish เป็น false ระบบจะตรวจสอบค่ากับ context window ของโมเดล แล้วบันทึกเป็นเวอร์ชันที่สองในสถานะฉบับร่าง โดยยังไม่กระทบลูกค้าที่ใช้งานเวอร์ชันหนึ่งอยู่ครับ

## b6 → assets/voice/b6.wav
ครั้งที่สาม การสั่งเปิดใช้งานจริง หรือย้อนกลับ เมื่อตรวจฉบับร่างจนมั่นใจแล้ว ให้ส่ง POST ไปที่ publish โดยระบุ version ID หรือส่งว่างเพื่อให้ระบบ publish ร่างล่าสุดให้อัตโนมัติ และถ้าเปิดใช้แล้วอยากย้อนกลับไปเวอร์ชันก่อนหน้า ก็ส่ง POST ไปที่ rollback ได้ทันทีโดยไม่ต้องส่งข้อมูลใน body เลยครับ

## b7 → assets/voice/b7.wav
นอกจากนี้ยังมีรายละเอียดที่ช่วยให้จัดการผ่านโค้ดได้ครบวงจร คือถ้าต้องการแก้เฉพาะชื่อ คำอธิบาย ไอคอน หรือการมองเห็น ให้เรียกที่ PATCH agents ID แต่ถ้าแก้ Prompt หรือโมเดลต้องผ่าน versions เสมอ รวมถึงสามารถคัดลอก Agent ทั้งตัวด้วยคำสั่ง duplicate และผูกคลังความรู้ เครื่องมือ หรือ credential ผ่านคำสั่ง PUT ได้ทั้งหมดครับ

## b8 → assets/voice/b8.wav
สรุปครับ เตรียม API Key สิทธิ์ agents read และ write เชื่อมสามขั้นตอน คือดูโมเดลแล้วสร้าง Agent บันทึกร่างใหม่ที่ versions และสั่งเปิดใช้ที่ publish หรือย้อนกลับที่ rollback ช่วยให้ทีมของคุณอัปเกรด AI ได้อย่างปลอดภัยทุกครั้งครับ

## b9 → assets/voice/b9.wav
คลิปนี้สนับสนุนโดย LangMind เริ่มสร้างและบริหารจัดการ Agent ของคุณได้ที่ LangMind ดอท อิน ดอท ทีเอช
