# EP04 — บทร่าง v2 (Voice API: คุยกับ AI ด้วยเสียงพูด)

> v2 (7 พ.ย. 2026): แก้ให้ตรงคู่มือ — API Key ต้องมี `voice:invoke` และ `chat:invoke`, เปิดโหมดเสียงแล้วต้อง publish, ระบุ endpoint สเต็ป 2, ไฟล์เสียงตอบกลับเป็น MP3 หรือ WAV, ตัดคำว่า "ทันที" บทของทุก Beat (B01–B06) ที่ใช้ทำเสียงจริงอยู่ใน [video/timing.json](video/timing.json) และ [video/VOICE-SCRIPT.md](video/VOICE-SCRIPT.md)

ผู้ชม: Developer และผู้พัฒนาแอปพลิเคชันที่ต้องการสร้าง Voice Agent ในแอปของตนเอง  
เวลาเป้าหมายสำหรับการทดลอง: ประมาณ 90–110 วินาที (อ่านออกเสียงแบบภาษาพูด ไม่เร่งศัพท์เทคนิค)  
ภาษา: ไทย โทนสนทนา อธิบายหนึ่งเหตุการณ์ต่อเนื่องตั้งแต่ลูกค้ากดอัดเสียงจนถึงได้ยินเสียง AI ตอบกลับ

## 1. บทเต็มและจุดแบ่งจังหวะ (Full Script & Beats)

| Beat | บทบรรยายภาษาพูด | ข้อความเน้นบนจอ (แยกจากซับ) |
|---|---|---|
| **B01** | เคยไหมครับ ผู้ใช้พิมพ์ไม่สะดวก เช่น กำลังขับรถ หรือมือไม่ว่าง ถ้าแอปของเราคุยด้วยเสียงได้ ก็จะใช้งานง่ายขึ้นมาก แต่เบื้องหลัง ต้องเชื่อมต่อระบบอย่างไร? | สั่งงานด้วยเสียงในแอป |
| **B02** | เราไม่ต้องสร้างหรือเทรนโมเดลเสียงเองตั้งแต่ต้น LangMind มี Voice API สำหรับถอดเสียงและอ่านออกเสียง ใช้คู่กับ Chat API ของ Agent ต่อกันเป็นท่อสามสเต็ป ฟัง คิด และพูด | ฟัง → คิด → พูด |
| **B03** | สเต็ปแรกคือการฟัง ผู้ใช้กดไมค์แล้วพูดว่า ขอสั่งอเมริกาโน่เย็นหนึ่งแก้วครับ ระบบหลังบ้านของแอป ส่งไฟล์เสียงขนาดไม่เกินสี่เมกะไบต์ ไปที่ Voice Transcribe ของ LangMind แล้วได้ข้อความที่ถอดจากเสียงกลับมา | 1. ฟัง: Voice Transcribe<br>`POST /api/v1/agents/{id}/voice/transcribe` · สิทธิ์ `voice:invoke` |
| **B04** | สเต็ปที่สองคือการคิด ส่งข้อความนี้เข้า Chat API ของ Agent พร้อมระบุ input mode เป็น voice Agent ที่ใส่ข้อมูลเมนูร้านไว้ จะตอบสั้น กระชับ เป็นภาษาพูด และส่ง conversation ID กลับมา ไว้ใช้คุยต่อในรอบถัดไป | 2. คิด: Chat Agent<br>`POST /api/chat/message/blocking` + `"input_mode": "voice"` · สิทธิ์ `chat:invoke` |
| **B05** | สเต็ปสุดท้ายคือการพูด ส่งคำตอบเข้า Voice Speech ของ LangMind จะได้ไฟล์เสียงกลับมา เป็น MP3 หรือ WAV ตามที่ตั้งค่าไว้ แล้วแอปก็เปิดเสียงนั้นให้ผู้ใช้ฟัง | 3. พูด: Voice Speech<br>`POST /api/v1/agents/{id}/voice/speech` → `audio/mpeg` หรือ `audio/wav` · สิทธิ์ `voice:invoke` |
| **B06** | สรุปสามสิ่งที่ต้องเตรียม หนึ่ง เปิดสนทนาด้วยเสียงใน Agent แล้วกด publish สอง API Key ต้องมีสิทธิ์ทั้ง voice invoke และ chat invoke สาม เก็บ API Key ไว้ที่ server ของแอปเท่านั้น เพียงเท่านี้ แอปของคุณก็พร้อมคุยกับผู้ใช้ด้วยเสียงแล้วครับ | เช็กลิสต์สำหรับ Developer:<br>1. เปิดโหมดเสียง + publish 2. `voice:invoke` + `chat:invoke` 3. เก็บ Key ฝั่ง Server |

## 2. ข้อมูลตัวอย่างสำหรับหน้าจอและเสียง (illustrative)

* **แอปสมมติ**: "Cafe Assistant" (แอปสั่งเครื่องดื่มในร้านกาแฟ)
* **เสียงคำพูดลูกค้า (Input)**: *"ขอสั่งอเมริกาโน่เย็น 1 แก้วครับ"* (ไฟล์จำลอง `order.wav`, ส่งเป็น `type=audio/wav` ตามตัวอย่างในคู่มือ)
* **ข้อความที่ถอดได้จาก Transcribe**: `"ขอสั่งอเมริกาโน่เย็น 1 แก้วครับ"`
* **คำตอบจาก Agent (Voice-optimized answer)**: `"รับอเมริกาโน่เย็น 1 แก้วครับ ทั้งหมด 65 บาท รับหวานกี่เปอร์เซ็นต์ดีครับ?"`
* **เสียงที่ได้รับกลับจาก Speech (Output)**: ไฟล์เสียงจำลอง (`audio/mpeg` หรือ `audio/wav` ตาม `format` / โมเดลของ Agent) ไม่ระบุความยาว
* *หมายเหตุ*: นี่คือข้อมูลจำลองเพื่ออธิบายท่อการทำงาน ไม่อ้างว่าเป็นผลทดสอบ live API และไม่ใส่ตัวเลขความเร็ว latency ปลอม

## 4. ข้อกำหนดซับไตเติลและจังหวะเสียง

* ซับไตเติลแสดงทีละ 1–2 บรรทัด จัดกึ่งกลางกรอบแนวตั้ง (แกน y ล่าง 1540–1720px) ใช้ฟอนต์ Sarabun มีหัวอ่านง่าย
* ซับขึ้นตรงกับเสียงพูด ไม่แสดงประโยคทั้งท่อนค้างไว้ล่วงหน้า
* เว้นจังหวะหยุดพัก (Pause) ประมาณ 0.3–0.5 วินาที ระหว่างแต่ละสเต็ป (ฟัง -> คิด -> พูด) เพื่อให้คนดูประมวลผลแผนภาพทัน
