## 1. แนวภาพและระบบการแสดงผล (Visual System)

* **สไตล์หลัก**: Editorial Paper & Sage Ink — สะอาด ชัดเจน ให้ความรู้สึกเหมือนอินโฟกราฟิกเทคนิคที่เข้าใจง่าย
* **สัดส่วนและขนาด**: 9:16 (1080×1920 พิกเซล, 30 fps) สำหรับหน้าจอมือถือ
* **ชุดสี (Palette)**:
  * พื้นหลัง: กระดาษนวล `#F5F1E7`
  * ตัวอักษรและเส้นขอบหลัก: หมึกเข้ม `#202824`
  * สีเน้นขาเข้า (Input / Transcribe): เขียวเซจ `#38815A`
  * สีเน้นขาออก (Output / Speech): ฟ้าอมเขียว (Teal) `#1E7578`
* **ระบบตัวอักษร**: ฟอนต์ Sarabun (มีหัว อ่านง่ายบนมือถือ)
  * หัวเรื่องหลัก: 64–72px
  * ข้อความป้ายกำกับ: 40–48px
  * ซับไตเติล: 44–48px (จัดกึ่งกลางกรอบแนวตั้ง y=1540–1720px)
* **พื้นที่ปลอดภัย (Safe Area)**: x=108–972, y=192–1500 (ไม่วางข้อความสำคัญหรือปุ่มไมค์ชิดขอบจอ)

## 2. รายละเอียด Storyboard ราย Beat (B01 – B06)

| Beat / เวลาประมาณ | สงสัยก่อน → เข้าใจหลัง | ภาพเริ่ม → การเคลื่อนไหว → ภาพจบ | บทพากย์และข้อความเน้น | Assets / Catalog / Robot |
|---|---|---|---|---|
| **B01** (12–15s) | พิมพ์ไม่สะดวก คุยด้วยเสียงได้ไหม? → คุยได้ แต่เบื้องหลังเชื่อมต่ออย่างไร | จอแอป Cafe Assistant (APP-VOICE-Q) เด่นกลางเฟรม → ผู้ใช้กดปุ่มไมค์มีคลื่นเสียงขึ้น → ซูมถอยออกมาเห็นขอบเขตที่ยังว่างด้านหลัง | **บท**: เคยไหมที่ผู้ใช้พิมพ์ไม่สะดวก... แต่คำถามคือเบื้องหลังเชื่อมต่อระบบอย่างไร?<br>**ข้อความ**: "สั่งงานด้วยเสียงในแอป" | • `Browser Device Stage`<br>• ภาพ `APP-VOICE-Q`<br>• Robot ท่า `01-question` (ซ้ายล่าง ไม่บังซับ) |
| **B02** (14–16s) | ต้องเทรนโมเดลเองไหม? → ไม่ต้อง LangMind มีท่อ 3 สเต็ปครบวงจร | ย่อหน้าจอไปด้านซ้าย → เผยบล็อก 3 สเต็ป: **1.ฟัง (STT) → 2.คิด (Agent) → 3.พูด (TTS)** เรียงจากบนลงล่าง พร้อมลูกศรเชื่อม | **บท**: เราไม่ต้องสร้างโมเดลเสียงเอง LangMind มีท่อ Voice API ครบ 3 สเต็ป...<br>**ข้อความ**: "1.ฟัง → 2.คิด → 3.พูด" | • `hw-pipeline`<br>• ไม่ใช้ Robot (ให้โฟกัสที่ 3 สเต็ป) |
| **B03** (18–20s) | สเต็ป 1 ส่งเสียงไปถอดความอย่างไร? → ส่ง Multipart audio เข้า `/voice/transcribe` | ซูมเข้าไปที่สเต็ป 1 (กล่องเขียว) → ไฟล์เสียง `order.m4a` วิ่งเข้า `POST /voice/transcribe` → ถอดออกมาเป็นข้อความตัวหนังสือ | **บท**: สเต็ปแรกคือการฟัง ส่งไฟล์เสียงไม่เกิน 4 MB... ถอดเป็นข้อความให้อัตโนมัติ<br>**ข้อความ**: `POST /voice/transcribe` + ป้าย `<= 4 MB` | • `hw-pipeline` + connector<br>• `Code Snippet`<br>• Robot ท่า `05-point-up` ชี้ Endpoint |
| **B04** (16–18s) | สเต็ป 2 ทำไม AI ตอบกระชับ? → เพราะใส่ `"input_mode": "voice"` | ข้อความคำถามวิ่งเข้ากล่อง Agent → ไฮไลต์พารามิเตอร์ `input_mode: "voice"` → กล่องคำตอบแสดงข้อความสั้นกระชับ | **บท**: สเต็ปต่อมาคือการคิด ส่งข้อความเข้า Agent ใส่ input_mode voice สรุปสั้นเหมาะกับการฟัง<br>**ข้อความ**: `input_mode: "voice"` (ไฮไลต์เขียว) | • `hw-pipeline`<br>• `Marker Highlight`<br>• ไม่ใช้ Robot |
| **B05** (18–22s) | สเต็ป 3 แปลงคำตอบเป็นเสียงอย่างไร? → ส่งเข้า `/voice/speech` ได้ MP3 มาเล่นในแอป | ข้อความคำตอบวิ่งเข้าสเต็ป 3 `POST /voice/speech` → กลายเป็นไฟล์เสียง MP3 วิ่งกลับเข้ามือถือ (สลับเป็น APP-VOICE-A) คลื่นเสียงเล่น | **บท**: สเต็ปสุดท้ายคือการพูด ส่งเข้า Voice Speech API ได้ไฟล์ MP3 กลับมาเล่นในแอปทันที<br>**ข้อความ**: `POST /voice/speech` → `audio/mpeg` | • `hw-pipeline`<br>• `Browser Device Stage`<br>• ภาพ `APP-VOICE-A`<br>• `Oscilloscope Trace` คลื่นเสียง |
| **B06** (14–16s) | สรุปสิ่งที่ต้องเตรียม? → เช็กลิสต์ 3 ข้อพร้อมเริ่มพัฒนา | ถอยภาพกว้าง สรุปเช็กลิสต์ 3 ข้อ: 1. เปิดโหมดเสียงใน Agent 2. Scope `voice:invoke` 3. เก็บ Key ที่ Server ปลอดภัย | **บท**: สรุป 3 สิ่งสำคัญ: เปิดโหมดเสียง, voice:invoke, และเก็บ Key ฝั่ง Server... พร้อมคุยด้วยเสียงแล้วครับ<br>**ข้อความ**: "เช็กลิสต์: โหมดเสียง / voice:invoke / เก็บ Key ที่ Server" | • Robot ท่า `04-open-arms` กลางล่าง<br>• เช็กลิสต์ 3 ข้อ |

## 3. การเลือกฉากตัวอย่างสำหรับทำ Sample (W5)

* **ช่วงที่เลือกทำ Sample**: **B03 – B05 (The 3-Step Voice Pipeline)**
  * **เหตุผล**: เป็นช่วงหัวใจหลักที่ต้องพิสูจน์ทั้ง 3 มิติ:
    1. การเชื่อมต่อบล็อกข้อมูล (Diagram pipeline)
    2. การแสดงโค้ด Endpoint ควบคู่กับภาพจำลอง
    3. การเปลี่ยนสถานะของหน้าจอมือถือจาก "รับเสียงคำถาม" ไปสู่ "เล่นเสียงคำตอบ"
  * **ความยาวของ Sample**: ประมาณ 35–45 วินาที

## 4. แบบกำหนดหน้าจอ Mockup ก่อนเจนรูป (Screen Specifications)

ตามเกณฑ์ [STORYBOARD_GUIDELINES.md](../../docs/STORYBOARD_GUIDELINES.md) ภาพหน้าจอแอปต้องมีสเปกชัดเจนก่อนเจนเป็นภาพ Raster (ห้ามใช้ HTML วาด UI แบนๆ ทับ):

### หน้าจอ 1: APP-VOICE-Q (สถานะลูกค้ากดไมค์พูดสั่งกาแฟ)
* **ขนาดไฟล์ภาพ**: 1440×1800 พิกเซล (อัตราส่วน 4:5)
* **หัวข้อหน้าจอ (Header)**: "Cafe Assistant" + ไอคอนแก้วกาแฟเล็กๆ
* **องค์ประกอบและ Layout**:
  * ขอบเขต Header: y=0.06–0.14
  * กล่องการสั่งซื้อ / ประวัติสั้น: y=0.18–0.40 (แสดงเมนูแนะนำ)
  * พื้นที่แสดงสถานะเสียง: y=0.45–0.70 มีปุ่มไมโครโฟนกลมสีเขียวเซจ พร้อมเส้นคลื่นเสียง (Waveform) และข้อความที่กำลังถอดความ: *"ขอสั่งอเมริกาโน่เย็น 1 แก้วครับ"*
  * ป้ายกำกับสถานะ: *"กำลังฟังเสียงพูด..."* (y=0.72–0.77)
  * ป้ายถาวร (Mandatory): ป้ายข้อความมุมขวาล่าง *"ภาพจำลอง"* (y=0.88–0.93)
* **สี**: พื้นแอปสีครีมขาวสะอาด ปุ่มและคลื่นเสียงสีเขียว `#38815A` ตัวหนังสือเข้ม คมชัด

### หน้าจอ 2: APP-VOICE-A (สถานะ AI กำลังตอบกลับด้วยเสียง)
* **ขนาดไฟล์ภาพ**: 1440×1800 พิกเซล (อัตราส่วน 4:5)
* **สืบทอดโครงสร้างจาก APP-VOICE-Q**: คง Header, เมนู และป้ายภาพจำลองไว้ที่เดิมทุกพิกเซล
* **ส่วนที่เปลี่ยน**:
  * บริเวณ y=0.45–0.80: ปุ่มไมค์เปลี่ยนเป็นไอคอนลำโพงเล่นเสียง มีคลื่นเสียงสีฟ้าอมเขียว (Teal)
  * กล่องข้อความคำตอบ AI ปรากฏขึ้น: *"รับอเมริกาโน่เย็น 1 แก้วครับ ทั้งหมด 65 บาท รับหวานกี่เปอร์เซ็นต์ดีครับ?"*
  * ป้ายสถานะเปลี่ยนเป็น: *"กำลังเล่นเสียงตอบกลับ..."*
* **ข้อห้าม**: ห้ามเพิ่ม badge ทางการ, ห้ามใส่เลข latency หรือเปอร์เซ็นต์คะแนนปลอม
