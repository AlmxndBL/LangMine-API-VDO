# EP04 — Voice API: คุยกับ AI ด้วยเสียงพูด (Speech-to-Text & Text-to-Speech)

สถานะ: จัดทำข้อเสนอ W3 สำหรับพิจารณาแนวทางเล่าเรื่อง ยังไม่เริ่ม W4 (บท/Storyboard), ไม่เจนภาพ/สร้าง assets และไม่ render วิดีโอ  
อ้างอิง: [Workflow](../../docs/WORKFLOW.md), [ข้อกำหนด Storyboard](../../docs/STORYBOARD_GUIDELINES.md) และคู่มือ [langmind-api.md](../../langmind-api.md)

## 1. โจทย์จากมุมคนดู (Audience & Purpose)

* **ผู้ชมเป้าหมาย**: Developer, นักศึกษา หรือผู้พัฒนาแอปพลิเคชัน ที่มีแอป (เว็บหรือมือถือ) และอยากเพิ่มฟีเจอร์ "คุยโต้ตอบด้วยเสียง" กับ AI
* **พื้นฐานเดิมของผู้ฟัง**: รู้จักการเรียก API ทั่วไปและการส่งคำขอ HTTP รู้จักฟีเจอร์แชต AI แต่ยังไม่เคยทำระบบเสียง หรือกังวลว่าต้องเทรน AI ถอดเสียง/สังเคราะห์เสียงเองหรือไม่
* **ความต้องการหลัก**: อยากรู้ว่าถ้าจะทำให้แอป "ฟังเสียงผู้ใช้แล้วตอบกลับเป็นเสียงพูดได้" ต้องเชื่อมต่ออย่างไร และ LangMind มีเครื่องมืออะไรให้เรียกใช้บ้าง
* **จุดติดขัด (Friction)**: 
  * คิดว่าการทำ Voice Agent ซับซ้อน ต้องตั้ง Server แปลงเสียงขนาดใหญ่
  * ไม่เห็นภาพท่อเชื่อมต่อ (Flow) ว่าเสียงวิ่งไปไหน ใครถอดความ ใครคิดคำตอบ และใครเป็นคนออกเสียง
* **เหตุผลที่ดู**: เห็นภาพรวมท่อส่งข้อมูล 3 สเต็ป (ฟัง -> คิด -> พูด) เข้าใจหน้าที่ของ LangMind Voice API และรู้ว่าฝั่งแอปต้องเขียนโค้ดเตรียมอะไรบ้าง
* **สิ่งที่ดูจบแล้วนำไปทำต่อได้**: วางสถาปัตยกรรม (Architecture) ของฟีเจอร์ Voice Chat ในแอปตนเองได้ถูกต้อง รู้จัก Endpoint `/voice/transcribe` กับ `/voice/speech` และทราบข้อควรระวังเรื่องความปลอดภัยของ API Key

## 2. แกนคำอธิบายและ Use Case ตัวอย่าง

* **Use Case ตัวแทน**: **"ระบบสั่งเครื่องดื่มด้วยเสียงในแอปคาเฟ่ (Voice Ordering Assistant)"**
  * *เหตุการณ์*: ลูกค้ากดปุ่มไมค์ในแอปแล้วพูดว่า: *"ขอสั่งอเมริกาโน่เย็น 1 แก้วครับ"*
  * *ผลลัพธ์*: แอปประมวลผล แล้วมีเสียงพูดตอบกลับมาว่า: *"รับอเมริกาโน่เย็น 1 แก้วครับ ทั้งหมด 65 บาท รับหวานกี่เปอร์เซ็นต์ดีครับ?"*
* **ท่อการทำงาน 3 สเต็ป (The 3-Step Voice Loop)**:
  1. **สเต็ป 1: ฟัง (Transcribe / STT)**: แอปอัดเสียงลูกค้า ส่งไฟล์เสียงไปที่ LangMind Voice Transcribe API เพื่อถอดเสียงเป็นข้อความ
  2. **สเต็ป 2: คิด (Chat Agent with Voice Mode)**: ส่งข้อความที่ได้เข้า Chat API ของ Agent โดยระบุ `"input_mode": "voice"` เพื่อให้ AI ตอบแบบภาษาพูด กระชับ ไม่เวิ่นเว้อ
  3. **สเต็ป 3: พูด (Speech / TTS)**: ส่งข้อความคำตอบเข้า LangMind Voice Speech API เพื่อแปลงเป็นไฟล์เสียงกลับมา แล้วแอปนำไปสั่งเล่นให้ลูกค้าฟัง
* **การแบ่งหน้าที่ชัดเจน (Separation of Concerns)**:
  * **LangMind Voice API ทำหน้าที่**: ถอดเสียงภาษาไทย/สากล, ประมวลผลคำตอบตามฐานข้อมูลร้าน, และสังเคราะห์เสียงพูดตามโทนที่ตั้งไว้
  * **แอปพลิเคชัน (Developer) ทำหน้าที่**: ดึงเสียงจากไมโครโฟน, ส่ง Request ผ่าน Backend ปลอดภัย, และเล่นไฟล์เสียงที่ได้

## 3. ขอบเขตคำตอบและหลักฐาน (Claims & Evidence)

อ้างอิงจาก [langmind-api.md](../../langmind-api.md) ส่วน "Voice API" และ "Authentication/Scopes":

| ประเด็น / ข้อกล่าวอ้าง | สถานะหลักฐาน | วิธีนำเสนอในคลิป |
|---|---|---|
| ถอดเสียงพูดเป็นข้อความได้ด้วย `/voice/transcribe` | **documented**: รับ multipart audio (`wav, mp3, m4a` <= 4 MB) ส่งกลับเป็นข้อความ | แสดงไอคอนไฟล์เสียงวิ่งเข้า API แล้วแปลงเป็นข้อความจำลอง |
| อ่านออกเสียงข้อความกลับเป็นไฟล์เสียงด้วย `/voice/speech` | **documented**: รับข้อความ JSON (<= 4,000 ตัวอักษร) ส่งกลับเป็นไฟล์เสียง `audio/mpeg` หรือ `audio/wav` | แสดงข้อความคำตอบส่งเข้า API แล้วได้คลื่นเสียงส่งกลับมา |
| ส่ง `"input_mode": "voice"` เพื่อให้ Agent ตอบสั้นแบบภาษาพูด | **documented**: มีระบุใน Chat API เพื่อให้ Agent ใช้การตั้งค่า "ตอบแบบภาษาพูด" | เน้นความแตกต่างระหว่างคำตอบแชตยาวๆ กับคำตอบเสียงที่กระชับ |
| ต้องมีสิทธิ์เรียกใช้งาน Scope `voice:invoke` | **documented**: แยกจาก `chat:invoke` เพราะมีต้นทุนโมเดลเสียง | อธิบายสั้นๆ ในเชิงกติกาความปลอดภัย |
| Agent ต้องเปิดใช้งาน "สนทนาด้วยเสียง" ก่อน | **documented**: หากปิดอยู่จะได้ 403 `VOICE_DISABLED` | ระบุเป็น Tips สั้นๆ ว่าอย่าลืมเปิดสวิตช์ในระบบจัดการ Agent |
| ไม่มีการบันทึกไฟล์เสียงเก็บไว้บน Server | **documented**: LangMind ระบุว่าไม่มีการเก็บไฟล์เสียง | ให้ความมั่นใจเรื่อง Privacy ของผู้ใช้ |
| หน้าจอแอปสั่งกาแฟ และ UI บันทึกเสียง | **illustrative**: ภาพจำลองที่ออกแบบขึ้นเอง | ติดป้าย "ภาพจำลอง" ชัดเจน ไม่อ้างเป็น Official Template |
| Latency และความเร็วในการแปลงเสียง | **unknown**: ไม่มีการรับรองตัวเลขตายตัวในเอกสาร | ห้ามใส่ตัวเลขเสี้ยววินาที หรือคำว่า "เร็วที่สุด" โดยไม่มีผลวัดจริง |

*คำเตือนด้านความปลอดภัยที่ต้องย้ำในคลิป*: API Key ต้องเก็บไว้ที่ Backend ฝั่ง Server เท่านั้น ห้ามใส่ใน Frontend หรือ Mobile App โดยตรง

## 4. โครงเรื่องคร่าว ๆ (Rough Beat Outline)

| Beat | คำถามของคนดู | สิ่งที่ต้องเห็นในจอ (Visual) | หน้าที่เสียงพากย์ (Voice) | หน้าที่ข้อความ/ซับ | การเชื่อมโยงซีน |
|---|---|---|---|---|---|
| **B01** | อยากให้แอปคุยด้วยเสียงได้ ต้องเริ่มยังไง? | ลูกค้ากดปุ่มไมค์ในแอปสั่งกาแฟ พูดว่า *"ขออเมริกาโน่เย็น 1 แก้ว"* และเกิดคำถามว่าเบื้องหลังส่งข้อมูลอย่างไร | ชวนคิดถึง use case ที่การพิมพ์ไม่สะดวก เช่น ขับรถ หรือมือไม่ว่าง | ป้าย "ภาพจำลอง" + ข้อความคำพูดลูกค้า | จากหน้าจอแอป สู่การเปิดม่านเบื้องหลัง |
| **B02** | ท่อการทำงานเสียงมีขั้นตอนอะไรบ้าง? | แผนภาพ 3 สเต็ป: **1. ถอดเสียง (STT) -> 2. คิดคำตอบ (Agent) -> 3. พูดตอบ (TTS)** | อธิบายภาพรวมว่าเราไม่ต้องเทรนโมเดลเอง LangMind มีท่อครบวงจร | ข้อความเน้น "ฟัง -> คิด -> พูด" | เตรียมเจาะลึกทีละสเต็ป |
| **B03** | สเต็ป 1: แอปส่งเสียงไปถอดความอย่างไร? | ไฟล์เสียง (`.m4a`/`.wav`) วิ่งจาก Backend ของแอปเข้า Endpoint `/v1/agents/{id}/voice/transcribe` ได้ Text กลับมา | อธิบายการส่งไฟล์เสียงแบบ Multipart ไม่เกิน 4 MB ได้ข้อความทันที | ชื่อ Endpoint `/voice/transcribe` + ตัวอย่าง Text ที่ได้ | ส่งข้อความต่อไปยัง Agent |
| **B04** | สเต็ป 2: ทำไมคำตอบถึงกระชับเหมาะกับการพูด? | ข้อความส่งเข้า Chat API พร้อม parameter `"input_mode": "voice"` เพื่อตัดคำตอบให้สั้นลงเป็นภาษาพูด | อธิบายว่าเสียงพากย์ที่ดีต้องไม่ตอบยาวเหมือนบทความ Agent จะสรุปเฉพาะใจความสำคัญ | `"input_mode": "voice"` + กล่องคำตอบกระชับ | ส่งคำตอบไปสร้างเสียง |
| **B05** | สเต็ป 3: แปลงข้อความเป็นเสียงพูดอย่างไร? | ข้อความคำตอบส่งเข้า `/v1/agents/{id}/voice/speech` แล้วได้ไฟล์เสียงส่งกลับมา แอปสั่งเล่นเสียงออกลำโพง | อธิบายว่า API คืนค่าเป็นไฟล์เสียงตามสำเนียงและโทนเสียงของ Agent ที่ตั้งค่าไว้ | ชื่อ Endpoint `/voice/speech` + ไอคอนเสียงพูด | จบลูปการทำงานครบ 1 รอบ |
| **B06** | สรุป: ถ้าจะนำไปใช้จริง ต้องเตรียมอะไรบ้าง? | สรุป 3 สิ่งสำคัญ: 1. เปิดสวิตช์โหมดเสียงใน Agent 2. Scope `voice:invoke` 3. เก็บ API Key ไว้ที่ Backend ปลอดภัย | สรุปสิ่งที่ Developer ต้องนำไปทำต่อในแอปของตนเอง ให้กำลังใจเริ่มลงมือทำ | เช็กลิสต์ 3 ข้อสั้นๆ | จบคลิปด้วยการต่อยอด |

## 5. การวางตัวละคร Robot และ Motion

* **Robot กลาง**: เลือกจาก `shared/assets/characters/robot/` ใช้เป็นตัวประกอบช่วยชี้นำสายตา
  * จังหวะ B01: ท่ายืนฟัง / เอียงหูรับเสียง
  * จังหวะ B02: ท่าชี้ไปที่แผนภาพ 3 สเต็ป
  * จังหวะ B05: ท่าผายมือพูด / อธิบาย
  * ไม่ใช้ Robot เป็นตัวกำหนดทิศทางภาพหรือเล่าเรื่องคนเดียว
* **Catalog Motion**:
  * ใช้บล็อกจำพวก Data Flow / Directional Connector เพื่อแสดงทิศทางการวิ่งของไฟล์เสียงและข้อความ
  * ใช้ Device Frame (มือถือ) จำลองการใช้งานแอปสั่งกาแฟ
