# EP14 — Errors / Rate Limit & Quota: อ่าน error ให้เป็น รับมือให้ถูก

อัปเดต 10 พฤศจิกายน 2026 (Asia/Bangkok) · v1 ครอบคลุมหมวด Errors และ Rate Limit & Quota ในคู่มือครบ: error envelope, code ทั้ง 10 ตัว, โควตาบัญชี, ลิมิตของ Voice และแนวทางใช้ API Key อย่างปลอดภัย 5 ข้อ · ใช้ engine เดียวกับ EP12/EP13 แต่เปลี่ยนแถบความคืบหน้าเป็น **อ่าน → รับมือ → ป้องกัน**

## 1. โจทย์จากมุมคนดู (Audience & Purpose)
- **คนดู**: dev / ทีมที่ดูแลระบบหลังบ้านซึ่งเรียก LangMind API อยู่แล้ว (ต่อจาก EP04, EP12, EP13)
- **ปัญหา**: ระบบเรียก API แล้วพัง หน้าจอขึ้นแค่ “เกิดข้อผิดพลาด” ทีมไม่รู้ว่าพังเพราะอะไร ต้องแก้ตรงไหน หรือแค่รอแล้วลองใหม่
- **ดูจบแล้วต้องตอบได้**
  1. error ของ LangMind หน้าตาเดียวกันทุกตัว (`status`, `code`, `message`, `message_en`, `request_id`) และต้องเช็กที่ `code` ไม่ใช่ข้อความ
  2. code ทั่วไป 5 ตัว (401/403/404/422/429) และ code ของ Voice 5 ตัว แปลว่าอะไร แก้อย่างไร
  3. HTTP เดียวกันอาจคนละความหมาย (403 FORBIDDEN / VOICE_DISABLED / VOICE_NOT_IN_PLAN · 429 RATE_LIMIT_EXCEEDED / VOICE_QUOTA_EXCEEDED)
  4. แบ่งการรับมือเป็น 3 กลุ่ม: รอแล้วลองใหม่ · แก้คำขอ · ตั้งค่าในเว็บ/ดูแพ็กเกจ
  5. โควตา API Key ใช้ร่วมกับเว็บ · Voice มีลิมิตของตัวเอง (60 / 300 ครั้งต่อนาที)
  6. แนวทางใช้ API Key อย่างปลอดภัย 5 ข้อ + API Key จัดการ Key อื่นไม่ได้

## 2. Use case
ระบบหลังบ้านของร้านกาแฟ (ร้านเดียวกับ EP12/EP13) วันหนึ่งหน้ากล่องแชทขึ้น “เกิดข้อผิดพลาด” → ตอนจบทีมมีหน้า “บันทึก error” และหน้ากล่องแชทที่บอกทางแก้ (`403 FORBIDDEN` เพราะ Key ไม่มี `inbox:read`)

## 4. สิ่งที่คู่มือไม่ได้ระบุ และคลิปไม่อ้าง
- ตัวเลข rate limit ของ chat และ endpoint อื่นที่ไม่ใช่ Voice
- header อย่าง `Retry-After` หรือเวลาที่ต้องรอหลัง 429 → คลิปบอกบนจอว่า “ตัวเลขเป็นตัวอย่าง · คู่มือไม่ได้ระบุเวลารอ”
- ความหมาย/การใช้ `request_id` ฝั่ง LangMind (คลิปแนะนำแค่ให้เก็บไว้ใน log ของระบบเรา — เป็นแนวทาง ไม่ใช่ข้อกำหนด)
- scope ที่ `GET /api/me/voice-quota` ต้องใช้ → คลิปแสดงแค่ path
- ว่าแก้ scope ของ Key เดิมได้หรือไม่ → คลิปพูดแค่ “ใช้ Key ที่มี scope ตรง”
- การแบ่ง 3 กลุ่มเป็นข้อสรุปของคลิปจากความหมายในคู่มือ (ติดหมายเหตุบนจอ)
