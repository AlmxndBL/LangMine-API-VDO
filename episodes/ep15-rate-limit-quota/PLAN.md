# EP15 — Rate Limit & Quota: โควตานับยังไง ลิมิตเท่าไร ดูยอดที่ไหน

อัปเดต 10 พฤศจิกายน 2026 (Asia/Bangkok) · v1 · แยกมาจากหัวข้อ Errors ([EP14](../ep14-errors/README.md)) · เป้าความยาวไม่เกิน 3 นาที (draft ก่อนใส่เสียง 2:26)
ครอบคลุมหมวด Rate Limit & Quota และแนวทางการใช้งานที่ปลอดภัยในคู่มือครบ รวมโควตาเฉพาะของ Voice และ Short Links · ใช้ engine เดียวกับ EP12–EP14 · แถบความคืบหน้า **โควตา → ลิมิต → รับมือ**

## 1. โจทย์จากมุมคนดู (Audience & Purpose)
- **คนดู**: dev / ทีมที่ระบบหลังบ้านใช้หลาย API (แชท เสียง ลิงก์ย่อ) และเริ่มเจอ 429 หรือโควตาเต็ม
- **ปัญหา**: ไม่รู้ว่าโควตานับรวมกับอะไร ลิมิตเท่าไร ต้องดูยอดที่ไหน และจะป้องกันไม่ให้โควตาหมดเร็วยังไง
- **ดูจบแล้วต้องตอบได้**
  1. การเรียกผ่าน API Key นับรวมโควตาบัญชีเดียวกับเว็บ (โทเค็น LLM + rate limit การสนทนา คิดจากผู้ใช้คนเดียวกัน) · ดูที่หน้า Credentials
  2. Voice มีลิมิตต่อผู้ใช้ของตัวเอง (ค่าเริ่มต้น 60 / 300 ครั้งต่อนาที) ไม่ผูกแพ็กเกจ · ค่าใช้จ่ายตามโมเดลเสียง · ข้อความที่ถอดแล้วส่ง chat ยังนับโควตา chat
  3. โควตาเสียง: ถอดเสียงนับนาที อ่านนับตัวอักษร · ไม่พอ → `VOICE_QUOTA_EXCEEDED` · ดูยอดที่ `GET /api/me/voice-quota`
  4. ลิงก์ย่อนับโควตาเดียวกับหน้า “ลิงก์ย่อ” · เช็กที่ `GET /api/short-links/usage` · เกิน → 422 / 429
  5. เจอ `RATE_LIMIT_EXCEEDED` → รอแล้วลองใหม่แบบเว้นนานขึ้น · เช็กยอดก่อนงานใหญ่
  6. Key ที่หลุดใช้โควตาบัญชีได้ → แนวทางใช้ Key อย่างปลอดภัย 5 ข้อ

## 2. Use case
ระบบหลังบ้านร้านกาแฟ (ร้านเดียวกับ EP12–EP14) ใช้แชท เสียง และลิงก์ย่อ · ตอนจบทีมมีหน้า “การใช้งาน API ของร้าน” ที่รวมยอดเสียงและลิงก์ย่อ และแจ้งเตือนเมื่อใกล้หมด

## 4. สิ่งที่คู่มือไม่ได้ระบุ และคลิปไม่อ้าง
- ตัวเลข rate limit ของ chat / endpoint อื่นนอกจาก Voice · header `Retry-After` / เวลารอ
- รูปแบบ response ของ `/me/voice-quota` และ `/short-links/usage` · scope ที่ `/me/voice-quota` ต้องใช้
- ขนาดโควตาของแต่ละแพ็กเกจ · ตัวเลขในหน้าจอจำลองเป็นข้อมูลสมมติ
- ข้อสรุปของคลิป (ติดสถานะใน claim ledger): “ทีมใช้เว็บเยอะ API ก็เหลือน้อยลง”, “Key หลุดใช้โควตาคุณได้”, backoff, เช็กยอดก่อนงานใหญ่
