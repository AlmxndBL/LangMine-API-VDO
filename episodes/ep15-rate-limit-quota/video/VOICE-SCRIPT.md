# EP15 Rate Limit & Quota — บทสำหรับสร้างเสียง

รัน `python make-voice-samples.py` (สร้างเสียงทีละประโยคจาก timing.json) แล้ว `node build.mjs`

## b1 → assets/voice/b1.wav
ระบบของร้านใช้ทั้งแชท เสียง และลิงก์ย่อผ่าน API วันหนึ่งก็เจอ 429 หรือโควตาเต็ม โควตานับยังไง ลิมิตเท่าไร และดูยอดได้ที่ไหน มาดูกันครับ

## b2 → assets/voice/b2.wav
อย่างแรก การเรียกผ่าน API Key นับรวมกับโควตาบัญชีเดียวกับตอนใช้งานผ่านเว็บ ถ้าทีมใช้เว็บเยอะ ระบบที่เรียกผ่าน API ก็เหลือโควตาน้อยลงด้วย

## b3 → assets/voice/b3.wav
ทั้งโควตาโทเค็นของ LLM และ rate limit ของการสนทนา คิดจากผู้ใช้คนเดียวกัน ไม่ว่าจะเรียกจาก browser หรือ API Key เช็กโควตาที่เหลือได้จากหน้า Credentials

## b4 → assets/voice/b4.wav
Voice API มีลิมิตต่อผู้ใช้ของตัวเอง ค่าเริ่มต้นคือ ถอดเสียง 60 ครั้งต่อนาที และอ่านออกเสียง 300 ครั้งต่อนาที ลิมิตนี้ไม่ผูกกับแพ็กเกจ ค่าใช้จ่ายคิดตามโมเดลเสียงที่ agent เลือก และข้อความที่ถอดแล้วส่งเข้า chat ยังนับโควตา chat ตามปกติ

## b5 → assets/voice/b5.wav
โควตาเสียงของแพ็กเกจและเครดิต ถอดเสียงนับเป็นนาที อ่านออกเสียงนับเป็นตัวอักษร ถ้าไม่พอ จะได้ VOICE QUOTA EXCEEDED ดูยอดคงเหลือได้ที่ me voice quota

## b6 → assets/voice/b6.wav
ลิงก์ย่อก็นับโควตาเดียวกับหน้าลิงก์ย่อในเว็บ เช็กได้ที่ short links usage เกินแล้วจะได้ LIMIT EXCEEDED รหัส 422 หรือ RATE EXCEEDED รหัส 429

## b7 → assets/voice/b7.wav
เมื่อเจอ RATE LIMIT EXCEEDED ให้รอแล้วลองใหม่ และเว้นให้นานขึ้นทุกครั้ง คู่มือไม่ได้บอกเวลารอ และเช็กยอดก่อนเรียกงานที่ใช้โควตาเยอะ

## b8 → assets/voice/b8.wav
Key ที่หลุดก็ใช้โควตาของบัญชีคุณได้ จึงควรให้ scope น้อยที่สุด และแยก Key ตามงาน ตั้งวันหมดอายุ และอย่า commit Key ลง repo สงสัยว่าหลุด เพิกถอนทันที มีผลในคำขอถัดไป

## b9 → assets/voice/b9.wav
เอาไปทำหน้าโควตาของร้าน ยอดเสียงจาก voice quota และลิงก์ย่อจาก usage ใกล้หมดก็แจ้งทีมล่วงหน้า ส่วนโควตาโทเค็น ให้ดูที่หน้า Credentials

## b10 → assets/voice/b10.wav
สรุปครับ โควตาบัญชีเดียวกับเว็บ Voice มีลิมิตของตัวเอง เช็กยอดก่อนใช้ และดูแล Key ให้ปลอดภัย

## b11 → assets/voice/b11.wav
คลิปนี้สนับสนุนโดย LangMind เริ่มเชื่อม API ได้ที่ LangMind ดอท อิน ดอท ทีเอช
