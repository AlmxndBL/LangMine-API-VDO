# EP01 — API คืออะไร แล้ว LangMind API ใช้ทำอะไรได้?

สถานะ: ผู้ใช้อนุมัติทิศทาง W3 และให้เริ่มทำต่อแล้ววันที่ 6 พฤศจิกายน 2026 ใช้ผู้เริ่มต้นที่ยังไม่รู้ว่า API คืออะไร โครงและตัวอย่างด้านล่างเป็นฐานให้ W4 ไม่ถือว่า storyboard/ภาพ/วิดีโอที่ทำต่อผ่านตรวจรับแล้ว
ใช้ [Workflow](../../docs/WORKFLOW.md) และ [ข้อกำหนด storyboard](../../docs/STORYBOARD_GUIDELINES.md)

## 1. โจทย์จากมุมคนดู
ผู้ชมที่ผู้ใช้กำหนด: คนที่ยังไม่รู้ว่า API คืออะไร ไม่จำเป็นต้องเขียนโปรแกรมเป็น
พื้นฐาน: เคยใช้เว็บหรือแอปและพิมพ์คำถามในแชต ไม่คาดหวังความรู้ server, JSON, agent หรือ RAG
ความต้องการที่เสนอ: เข้าใจว่าแอปหนึ่งใช้ความสามารถของอีกบริการได้อย่างไร และนำ AI มาเป็นส่วนหนึ่งของแอปได้อย่างไร
จุดติดขัด: เห็นผลบนหน้าจอ แต่ไม่เห็นการส่งข้อมูลระหว่างระบบ คำว่า API จึงยังเป็นศัพท์ลอย ๆ
เหตุผลที่ดู: เชื่อมศัพท์ API เข้ากับสิ่งที่มองเห็นได้ แล้วเห็นตัวอย่างการใช้ LangMind ที่จับต้องได้
ดูจบแล้วควรอธิบายด้วยคำของตนเองได้ว่า API คืออะไร แอปส่งอะไรไป รับอะไรกลับ และ LangMind รับหน้าที่ตรงไหน โดยยังไม่ต้องเรียก API เอง

คำถามหลัก: **API คืออะไร แล้วทำให้แอปของเราใช้ความสามารถของ LangMind ได้อย่างไร?**
คำสัญญา: เห็นตัวอย่างการขอใช้ความสามารถจากอีกระบบหนึ่งครบหนึ่งรอบ และแยกหน้าจอแอปออกจากบริการที่ช่วยประมวลผลได้
ระดับ: อธิบายแนวคิดและแนวทางใช้งานด้วยภาพจำลอง ยังไม่สอนเขียนโค้ดหรือเชื่อมระบบจริง

## 2. แกนคำอธิบายและตัวอย่างที่เสนอ
คำอธิบายตั้งต้น: API คือช่องทางพร้อมกติกาที่ซอฟต์แวร์ใช้ขอข้อมูลหรือเรียกใช้ความสามารถของกันและกัน เช่น ต้องส่งข้อมูลแบบไหน และจะได้รับผลกลับในรูปแบบใด
ไม่อธิบายว่า API คือ AI เพราะ API ใช้กับบริการชนิดอื่นได้ด้วย และไม่รับรองว่าเรียก API แล้วจะได้ผลตามต้องการทุกครั้ง
เสนอใช้แอปที่มีผู้ช่วยตอบคำถามการใช้งานบริการ ตัวอย่างคำถาม “จะเริ่มใช้บริการนี้ต้องเตรียมอะไร?” ยังไม่กำหนดคำตอบจนกว่าจะมีข้อมูลตั้งต้น
พาคนดูตามคำถามเดิมจากหน้าจอ ผ่านระบบของแอป ไปยัง LangMind แล้วนำคำตอบกลับมาแสดง ไม่เปลี่ยนตัวอย่างกลางเรื่อง
อธิบาย agent เมื่อจำเป็นว่าเป็น “ผู้ช่วย AI ที่ตั้งค่าไว้ใน LangMind” ก่อนใช้ชื่อศัพท์
ใช้ภาพการส่งคำขอและผลกลับโดยตรง ไม่เพิ่มเรื่องเปรียบเทียบอีกชุดจนคนดูต้องจำสองระบบพร้อมกัน

## 3. ขอบเขตคำตอบและหลักฐาน
อ้างอิง [คู่มือ API](../../langmind-api.md) เฉพาะส่วน “ต้นฉบับครบทุกหมวด” เป็น snapshot ที่ผู้ใช้ให้ ไม่ใช่ผลทดสอบ live ปัจจุบัน

| คำกล่าว | หลักฐาน | วิธีเล่าสำหรับผู้เริ่มต้น |
|---|---|---|
| API มีกติกาการส่งข้อมูลและรับผล | documented: ตัวอย่าง request/response ในหมวด Chat API รองรับกรณี LangMind | แสดงคำถามออกไปและผลกลับมา อธิบายกติกาด้วยภาษาธรรมดา |
| แอปส่งคำถามไปยังผู้ช่วยที่ตั้งค่าใน LangMind ได้ | documented: Chat API | ใช้ชื่อผู้ช่วยแทน agent_id บนภาพหลัก ไม่สอน field |
| API ส่งข้อมูลคำตอบกลับ แอปนำมาแสดงเอง | documented: ตัวอย่าง blocking response ที่มี answer | แยกข้อมูลที่รับกลับออกจากหน้าจอที่แอปจัดแสดง |
| การเรียกใช้งานต้องมีสิทธิ์ | documented: Authentication/Scopes | กล่าวเท่าที่จำเป็นว่า developer ต้องตั้งค่าการเข้าถึงอย่างปลอดภัย ไม่แสดง key หรือสอน header |
| หน้าจอและระบบของแอปตัวอย่าง | illustrative: flow ที่เราออกแบบ | ติดป้ายภาพจำลอง ไม่อ้างเป็น official UI หรือระบบที่ทำเสร็จแล้ว |
| คำตอบตัวอย่าง | illustrative; ยังไม่กำหนด | มีข้อมูลต้นทางก่อนเขียน ไม่อ้างว่าเป็นผลเรียกจริง |
| ความเร็ว ค่าใช้จ่าย คุณภาพ และความพร้อมบัญชีจริง | unknown | ไม่ใส่ตัวเลขหรือรับรองผล |

รายละเอียดสำหรับทีมผลิต ไม่ใช่เนื้อหาหลักบนจอ: เก็บ key ฝั่ง server; หากต่อยอดหลายข้อความต้องตรวจ conversation/user isolation ตาม contract; ยังไม่เลือก stream หรือ blocking สำหรับการผลิต
ไม่ครอบคลุม: โค้ด endpoint JSON ชื่อ field ขั้นสร้าง key ระบบ production รายการทุกฟีเจอร์ LINE/voice/MCP หรือการรับรอง citations และความถูกต้องทุกคำตอบ
หากเลือกให้ผู้ช่วยตอบจากเอกสาร ต้องตรวจ contract การนำเข้า/สถานะพร้อมใช้/การผูกฐานความรู้ก่อนล็อกคำกล่าว ไม่สมมติว่าเกิดขึ้นเองจากการเรียก API

## 4. โครงเรื่องคร่าว ๆ ก่อนเลือก Catalog
แถวคือหน้าที่การเล่า ยังไม่ล็อกจำนวนซีน วินาที layout หรือเอฟเฟกต์

| คำถามคนดู | สิ่งที่ต้องเห็น | หน้าที่เสียง | หน้าที่ข้อความ | การเชื่อมช่วง |
|---|---|---|---|---|
| ทำไมแอปถึงมีผู้ช่วยตอบเราได้? | คนพิมพ์คำถามในแอปตัวอย่าง และเส้นทางเบื้องหลังที่ยังไม่เปิดเผย | ตั้งข้อสงสัยจากสิ่งคุ้นเคย | คำถามเดียวและป้ายภาพจำลอง | จากหน้าจอไปหาการทำงานเบื้องหลัง |
| API คืออะไร? | เปิดให้เห็นแอปส่งคำขอไปอีกระบบและรับผลกลับ ภาพแยกหน้าที่ของสองฝั่ง | อธิบายช่องทางและกติกาการคุยกันของซอฟต์แวร์ | ชื่อ API เมื่อภาพทำให้เข้าใจบริบทแล้ว พร้อมป้าย “ส่งคำขอ / รับผล” | จากแนวคิดทั่วไปสู่บริการที่ใช้ในตัวอย่าง |
| LangMind ช่วยตรงไหน? | ระบุปลายทางเป็นผู้ช่วย AI ที่ตั้งค่าใน LangMind คำถามเดิมเดินไปถึง | อธิบายว่า LangMind ให้บริการส่วนผู้ช่วย ส่วนหน้าจอเป็นของแอปเรา | “แอปของเรา / LangMind” | ตามคำถามเดิมไปจนได้ผลกลับ |
| แล้วคำตอบมาอยู่ในแอปได้อย่างไร? | ผลถูกส่งกลับ ผ่านระบบของแอป แล้วแสดงเป็นคำตอบบนหน้าจอ | อธิบายว่าแอปนำข้อมูลที่ได้รับมาแสดง ไม่ใช่ API สร้างแอปให้ทั้งชุด | เน้นเฉพาะผลที่ส่งกลับและตำแหน่งที่แสดง | เห็นการเชื่อมต่อครบหนึ่งรอบ |
| ถ้าอยากนำไปใช้ ต้องคิดอะไรต่อ? | ย้อน flow เดิม แล้วชี้โจทย์ของแอป ผู้ช่วยที่ต้องเตรียม และงานเชื่อมต่อของ developer | ชวนระบุว่าต้องการให้ AI ช่วยอะไร ก่อนให้ developer เชื่อมต่อและตรวจผล | คำถามนำไปคิดต่อหนึ่งข้อ ไม่กาง checklist เทคนิค | ปิดคำถามหลักและให้จุดเริ่มต้นเหมาะกับผู้ชม |

ภาพต้องแสดงการส่งต่อและการเปลี่ยนแปลง เสียงเล่าเหตุผลและความสัมพันธ์ ข้อความมีเฉพาะชื่อ/ใจความที่ต้องจำ ซับเป็นชั้นถอดเสียง ไม่ใช้ย่อหน้าบนภาพแทนการอธิบาย
Robot ใช้ช่วยชี้ตามหน้าที่ ยังไม่เลือกท่า ไม่เป็นตัวกำหนดเรื่อง

## 5. สิ่งที่ยืนยันแล้วและยังเปิด
ยืนยันแล้ว: เริ่มสำหรับคนที่ยังไม่รู้ว่า API คืออะไร
ยังเปิด: use case ผู้ช่วยตอบคำถามบริการ ช่องทาง ความยาว และระดับรายละเอียดของตัวอย่าง ไม่ใช้ค่าจากงานเก่าเป็นคำตอบ
ข้อเสนอถัดไป: ใช้เส้นทางส่งคำถามหนึ่งรอบข้างต้นเป็นแกน หากเปลี่ยน use case ให้เปลี่ยนข้อมูลตัวอย่างและหลักฐานที่พึ่งมันก่อนเลือก Catalog

## 6. ขั้นถัดไปและวิธีตรวจแผน
หลังทบทวน use case และโครงเรื่อง จึงเลือก Catalog ตามหน้าที่ส่งต่อข้อมูล เปิดให้เห็นเบื้องหลัง และพาสายตากลับหน้าจอ ดู preview จริงและบันทึกพฤติกรรม/ข้อจำกัดก่อนเลือก
ทำ W4 ตาม workflow: โครงทั้งตอน บทร่างลองอ่าน รายการ assets และแบบหน้าจอช่วง sample ที่ระบุข้อความ layout สถานะ crop/zoom และ continuity ก่อนเจน
เสนอเลือกช่วงคำขอ → LangMind → ผลกลับ → หน้าจอเป็น W5 sample เพื่อดูว่าผู้ชมเข้าใจว่าใครทำอะไรหรือไม่ ไม่เริ่มผลิตในรอบนี้
คำถามตรวจความเข้าใจ: “API ทำหน้าที่อะไร?”, “ส่วนไหนเป็นของแอป?”, “LangMind รับอะไรและส่งอะไรกลับ?” และ “API สร้างทั้งแอปให้หรือไม่?”
ตรวจเชิงเอกสารแล้ว: โครงเริ่มจากสิ่งคุ้นเคยก่อนศัพท์ ไม่ต้องอ่านโค้ด และทุกช่วงตอบคำถามหลัก ยังไม่ตรวจผู้ชมจริง ภาษาภาพ เวลาอ่าน จังหวะ หรือเสียง
