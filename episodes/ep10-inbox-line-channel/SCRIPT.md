# EP10 — บทร่างภาษาพูด 9 Beats (Inbox API & LINE Channel)

ผู้ชม: Developer และทีมซัพพอร์ตที่ต้องการดึงข้อมูลแชทจาก LINE เช็กสถานะแอดมินรับสาย และ Export รายงาน  
โครงสร้าง: 9 Beats (`b1–b9`) ตามแนวทาง EP04 v3 (เตรียม → เชื่อม 3 ครั้ง → ใช้ผล + ผู้สนับสนุน)  
ภาษา: ไทย โทนสนทนา กระชับ แยกบทพูด (`say`) ซับไตเติล (`cap`) และข้อความเน้นบนจอชัดเจน

---

## 1. บทเต็มและจุดแบ่งจังหวะ (Full Script & Beats)

| Beat | บทบรรยายภาษาพูด (`say`) | ข้อความเน้นบนจอ (แยกจากซับ) |
|---|---|---|
| **b1** | เมื่อเรานำ Agent ไปเชื่อมต่อกับลูกค้าทาง LINE คำถามที่ทีมหลังบ้านมักเจอคือ จะดึงรายการแชทมาดูในระบบของตัวเองได้ไหม รู้ได้อย่างไรว่าเคสไหนมีแอดมินคุยแทน AI อยู่ และจะดึงประวัติแชทออกมาเป็นไฟล์ Excel ได้อย่างไร ถ้าอยากทำทั้งหมดนี้ ต้องเตรียมอะไร เชื่อมตรงไหน และเอาผลไปใช้ยังไง มาดูกันครับ | ดึงแชท LINE เช็กแอดมินรับสาย & Export รายงาน |
| **b2** | ภาพรวมของฟีเจอร์นี้เชื่อมระหว่างแชทจากช่องทางภายนอก กล่องข้อความ Inbox ของ LangMind และระบบหลังบ้านของคุณ โดยระบบหลังบ้านจะเรียกอ่านข้อมูลสามจุดหลัก คือ ดึงรายการเธรดและจำนวนแชทแยกช่องทาง เช็กสถานะแอดมินรับสาย และสั่ง Export ประวัติเป็นไฟล์ครับ | รายการเธรด (`threads`) → สถานะรับสาย (`handover`) → ดึงไฟล์ (`export`) |
| **b3** | เริ่มจากสิ่งที่ต้องเตรียม อย่างแรกคือ Agent ที่เปิดใช้งานช่องทาง LINE เรียบร้อยแล้ว อย่างที่สองคือ API Key ที่มีสิทธิ์ inbox read สำหรับอ่านข้อมูลกล่องข้อความ และถ้าต้องการส่งข้อความแชทในนาม LINE user ผ่าน API ด้วย ก็เพิ่มสิทธิ์ chat invoke อย่างที่สามคือระบบหลังบ้านสำหรับเก็บ Key ครับ | สิ่งที่ต้องเตรียม:<br>1. Agent เปิดช่องทาง LINE<br>2. สิทธิ์ `inbox:read` (+ `chat:invoke`)<br>3. ระบบหลังบ้านเก็บ Key |
| **b4** | มาดูการเชื่อมครั้งที่หนึ่ง การดึงรายการเธรดและจำนวนแยกช่องทาง เรียก GET ไปที่ agents ตามด้วย agent ID และ inbox threads โดยกรอง channel เป็น line ได้ ระบบจะคืนรายการเธรดพร้อมชื่อแสดงผลและรูปโปรไฟล์ที่ดึงสดจาก LINE รวมถึงคืนค่า channel counts ที่นับจำนวนเธรดรวมของทุกช่องทางมาให้ในครั้งเดียว นำไปทำป้ายบอกจำนวนแชทได้ทันทีโดยไม่ต้องยิงซ้ำครับ | ครั้งที่ 1: ดึงรายการเธรด & จำนวนแชท<br>`GET /api/agents/{agent_id}/inbox/threads?channel=line`<br>คืน `display_name`, `avatar_url`, `channel_counts` |
| **b5** | ครั้งที่สอง การเช็กสถานะแอดมินรับสาย หรือ human handover เรียก GET ไปที่ inbox threads ตามด้วยรหัสเธรดและ handover ถ้าค่า active เป็น true พร้อมเวลาที่เหลือ expires in sec แปลว่าตอนนี้มีแอดมินคุมสายอยู่ ตัว AI จะหยุดตอบอัตโนมัติจนกว่าจะหมดเวลาหรือแอดมินกดจบงานครับ | ครั้งที่ 2: เช็กสถานะแอดมินรับสาย<br>`GET .../inbox/threads/{cid}/handover`<br>`active: true` = แอดมินคุมสายอยู่ (AI ไม่ตอบแทรก) |
| **b6** | ครั้งที่สาม การ Export ประวัติการสนทนา เรียก GET ไปที่ inbox export พร้อมระบุ format เป็น xlsx หรือ csv และเลือกกรองช่องทางหรือช่วงวันที่ได้ ระบบจะคืนไฟล์ไบนารีกลับมาให้ดาวน์โหลดตรงๆ สูงสุดสองหมื่นแถวต่อครั้งครับ | ครั้งที่ 3: Export ประวัติเป็น Excel/CSV<br>`GET .../inbox/export?format=xlsx&channel=line`<br>คืนไฟล์ตรงๆ (สูงสุด 20,000 แถว/ครั้ง) |
| **b7** | ผลที่ได้ช่วยให้เราทำหน้ามอนิเตอร์หลังบ้านและสรุปรายงานประจำวันได้สะดวกมาก และถ้าต้องการดึงข้อความรายบรรทัดในเธรด ก็เรียกที่ messages ซึ่งมีโครงสร้างเดียวกับ Chat API ทุกประการ แต่ข้อควรจำสำคัญคือ API Key ใช้ได้เฉพาะส่วนอ่านเท่านั้น การส่งข้อความตอบกลับลูกค้า หรือการกดเริ่มและจบ handover ต้องล็อกอินทำผ่านหน้าเว็บ เพื่อความปลอดภัยครับ | ขอบเขตที่ต้องรู้:<br>• อ่านข้อความเธรดได้ที่ `.../threads/{cid}/messages`<br>• ตอบกลับ / เริ่ม-จบ handover ต้องล็อกอินผ่านหน้าเว็บเท่านั้น |
| **b8** | สรุปครับ เตรียม Agent ที่เปิดช่องทาง LINE และ API Key สิทธิ์ inbox read เชื่อมสามจุด คือดูรายการเธรดที่ threads เช็กแอดมินรับสายที่ handover และดึงไฟล์รายงานที่ export ช่วยให้ทีมดูแลลูกค้าติดตามงานได้ครบทุกช่องทางครับ | สรุป: เตรียม → เชื่อม (`threads` · `handover` · `export`) → ใช้ผล |
| **b9** | คลิปนี้สนับสนุนโดย LangMind เริ่มสร้าง Agent เชื่อมต่อช่องทางแชทของคุณได้ที่ LangMind ดอท อิน ดอท ทีเอช | สนับสนุนโดย LangMind · `langmind.in.th` |

## 2. ข้อมูลตัวอย่างสำหรับหน้าจอและโค้ด (`illustrative` จากค่าตัวอย่างในคู่มือ)

* **เธรดตัวอย่าง (`APP-INBOX-THREADS`)**:
  * ชื่อลูกค้า: `"คุณสมชาย"` (`channel: "line"`, `message_count: 6`, `status: "open"`, ตรงกับตัวอย่างในคู่มือบรรทัด 1044–1056)
  * `channel_counts`: `{"line": 1, "web": 0}`
* **สถานะ Handover & Export (`APP-INBOX-HANDOVER`)**:
  * `active`: `true`, `expires_in_sec`: `1420` (ตรงกับตัวอย่างในคู่มือบรรทัด 1116–1117)
  * ปุ่มดาวน์โหลดไฟล์: `inbox-export.xlsx` (`format=xlsx&channel=line`)

## 3. Claim Ledger (ตรวจสอบข้อกล่าวอ้างเทียบกับคู่มือ)

| ข้อกล่าวอ้างในบท | สถานะหลักฐาน | แหล่งอ้างอิงใน [langmind-api.md](../../langmind-api.md) |
|---|---|---|
| Inbox API ใช้สิทธิ์ `inbox:read` สำหรับอ่านเท่านั้น ตอบกลับ/เริ่ม-จบ handover ทำผ่าน API Key ไม่ได้ ต้องล็อกอินผ่านเว็บ | **documented** | บรรทัด 114, 1020, 1031–1032 |
| `GET /api/agents/{agent_id}/inbox/threads` คืน `display_name`, `avatar_url` (ดึงสดจาก LINE/Webex/Telegram) และ `channel_counts` | **documented** | บรรทัด 1024, 1037–1066 |
| `GET /api/agents/{agent_id}/inbox/threads/{cid}/handover` คืน `active: true/false` และ `expires_in_sec` | **documented** | บรรทัด 1028, 1112–1119 |
| `GET /api/agents/{agent_id}/inbox/export` รับ `format=xlsx|csv` คืนไฟล์ไบนารีตรงๆ จำกัด 20,000 แถวต่อครั้ง | **documented** | บรรทัด 1030, 1124–1128 |
| `GET .../inbox/threads/{cid}/messages` มีรูปแบบเดียวกับ `GET /chat/conversations/{id}/messages` | **documented** | บรรทัด 1108 |
| หน้าจอ `APP-INBOX-THREADS` และ `APP-INBOX-HANDOVER` | **illustrative** | ออกแบบจำลองขึ้นเอง ติดป้าย "ภาพจำลอง" |
