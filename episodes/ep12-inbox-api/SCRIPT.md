## 1. บทเต็มและจุดแบ่งจังหวะ (Full Script & Beats)

เวลาเป็นค่าประมาณจากความยาวบท (11 ตัวอักษร/วินาที) เพราะยังไม่มีเสียงจริง รวม ~3:08 · เมื่อใส่เสียง Niwat −16% คาดว่าสั้นลงราว 15%

| Beat | เวลา (ประมาณ) | บทบรรยายภาษาพูด | ข้อความเน้นบนจอ (แยกจากซับ) |
|---|---|---|---|
| **b1** ปัญหา | 0:00–0:19 | ลูกค้าทักร้านทาง LINE ทุกวัน และ AI ของร้าน ก็ช่วยตอบให้แล้ว แต่ทีมหน้าร้านอยากเห็นแชททั้งหมด ในระบบหลังบ้านของร้านเอง ถ้าอยากทำหน้ากล่องแชทแบบนี้ ต้องเตรียมอะไร เชื่อมตรงไหน และเอาผลไปใช้ยังไง มาดูกันครับ | 3 คำถาม: เตรียมอะไร? · เชื่อมตรงไหน? · ใช้ผลยังไง? |
| **b2** ภาพรวม | 0:19–0:35 | แชทจาก LINE ที่ Agent ตอบ จะถูกเก็บไว้ในกล่องแชทของ Agent ใน LangMind Inbox API คือช่องทางให้ระบบหลังบ้านของคุณ ดึงแชทเหล่านั้นมาอ่าน แล้วเอาไปแสดงเป็นหน้ากล่องแชทของร้าน | ลูกค้า LINE → LangMind (กล่องแชท) → Inbox API → ระบบหลังบ้าน → หน้ากล่องแชทของร้าน |
| **b3** เตรียม | 0:35–0:51 | สิ่งที่ต้องเตรียม อย่างแรกคือ Agent ที่ต่อกับ LINE ไว้แล้ว และมีแชทจากลูกค้า อย่างที่สอง API Key ที่มีสิทธิ์ inbox read อย่างที่สาม ระบบหลังบ้านของร้าน ไว้เก็บ Key และเป็นคนเรียก API | 1. Agent ที่ต่อ LINE · 2. API Key `inbox:read` (อ่านอย่างเดียว) · 3. ระบบหลังบ้าน |
| **b4** เชื่อม 1 | 0:52–1:13 | มาดูการเชื่อม ครั้งที่หนึ่ง ดึงรายการแชท เลือกช่องทาง LINE หน้าละยี่สิบห้ารายการ ได้รายการแชท พร้อมชื่อลูกค้า และจำนวนข้อความ ส่วน channel counts นับแชททุกช่องทางให้แล้ว เอาไปทำแท็บได้เลย ถ้าจะค้นหา ใส่คำที่ต้องการใน search เช่น อเมริกาโน่ | `GET /api/agents/{id}/inbox/threads?channel=line&page=1&limit=25` → `items`, `total`, `channel_counts` · `&search=อเมริกาโน่` |
| **b5** เชื่อม 2 | 1:13–1:31 | ครั้งที่สอง เปิดแชทหนึ่งรายการ แล้วดึงข้อความในแชทนั้น ได้ข้อความเรียงกัน บอกว่าใครพูด ลูกค้าหรือ AI พร้อมเวลา ถ้า next cursor ไม่ว่าง แปลว่ายังมีข้อความเก่าอีก ส่งค่านี้กลับไปใน cursor เพื่อดึงหน้าถัดไป | `GET …/threads/{cid}/messages?limit=50` → `role`, `content`, `created_at` · `next_cursor` → `?cursor=` |
| **b6** เชื่อม 3 | 1:33–1:50 | ครั้งที่สาม เช็กว่าแชทนี้ มีแอดมินคุมสายอยู่หรือไม่ ถ้า active เป็น true แปลว่าแอดมินคุมอยู่ AI จะไม่ตอบ จนกว่าจะหมดเวลาหรือถูกจบ ถ้า active เป็น false แปลว่าไม่มีใครคุม AI ตอบตามปกติ | `GET …/threads/{cid}/handover` → `active: true` + `expires_in_sec` / `active: false, null` |
| **b7** เชื่อม 4 | 1:50–2:05 | ครั้งที่สี่ export ประวัติแชทเป็นไฟล์ xlsx หรือ csv เลือกช่องทาง และช่วงวันที่ได้ ได้ไฟล์กลับมาตรง ๆ ไม่ใช่ JSON ถ้าไม่ระบุวันที่ จะดึงทั้งหมด สูงสุดสองหมื่นแถวต่อครั้ง | `GET …/inbox/export?format=xlsx&channel=line&date_from=…&date_to=…` → ไฟล์ (ไม่ใช่ JSON) · สูงสุด 20,000 แถว |
| **b8** ใช้ผล | 2:05–2:26 | เอาผลไปทำหน้ากล่องแชท รายชื่อแชทพร้อมแท็บ นับตามช่องทาง ถ้าข้อความล่าสุดเป็นของลูกค้า ติดป้ายว่าลูกค้ารอตอบ เปิดแชทเพื่ออ่านย้อนหลัง และแสดงป้าย เมื่อแอดมินคุมสายอยู่ และปุ่มดาวน์โหลดประวัติ ก็เรียก export ที่ระบบหลังบ้าน | ฟิลด์ → ส่วนของหน้าจอ (`channel_counts` → แท็บ, `last_message_role` → ป้ายรอตอบ, `handover.active` → ป้ายคุมสาย, export → ปุ่ม ⬇ xlsx) |
| **b9** ข้อจำกัด | 2:26–2:40 | สิ่งที่ต้องรู้ คือ API Key ใช้ได้แค่อ่านข้อมูล การตอบลูกค้า และการเริ่มหรือจบการคุมสาย ต้องเข้าสู่ระบบผ่านเว็บ LangMind เพราะมีผลกับสิ่งที่ลูกค้าเห็นจริง | ✓ ด้วย Key: อ่าน · export / ✕ ต้องเข้าเว็บ: ตอบลูกค้า · เริ่ม/จบคุมสาย |
| **b10** สรุป | 2:41–2:58 | สรุปครับ เตรียม Agent ที่ต่อ LINE, API Key สิทธิ์ inbox read และระบบหลังบ้าน เชื่อมสี่แบบ รายการแชท ข้อความ สถานะคุมสาย และ export แล้วเอาไปทำหน้ากล่องแชทของร้าน ส่วนการตอบลูกค้า ทำในเว็บ LangMind | เตรียม → เชื่อม 4 แบบ → ใช้ผล |

## 2. ข้อมูลตัวอย่างสำหรับหน้าจอและ JSON (illustrative)

* **ร้าน**: ร้านกาแฟสมมติ มี Agent ตอบแชท LINE
* **ลูกค้าตัวอย่าง**: คุณสมชาย (ชื่อเดียวกับตัวอย่างในคู่มือ) และรายชื่อสมมติอื่น ๆ ในภาพหน้าจอ
* **ตัวเลข**: `total` / `channel_counts` (เช่น line 12, web 3), `message_count`, `expires_in_sec: 1420` (ตัวเลขจากตัวอย่างในคู่มือ)
* **คำค้น**: `search=อเมริกาโน่`
* **ช่วงวันที่ export**: `date_from=2026-11-01&date_to=2026-11-07` — ค่าตัวอย่าง คู่มือไม่ได้ระบุรูปแบบวันที่
* ภาพหน้าจอทั้งหมดติดป้าย “ภาพจำลอง” · ไม่ใช้โลโก้ LINE

## 3. Claim Ledger (ตรวจสอบข้อกล่าวอ้างเทียบกับคู่มือ)

| ข้อกล่าวอ้างในบท | สถานะหลักฐาน | แหล่งอ้างอิงใน [langmind-api.md](../../langmind-api.md) |
|---|---|---|
| Inbox API ดึง thread จากช่องทางภายนอก (LINE ฯลฯ) เฉพาะส่วนอ่าน | **documented** | บรรทัด 1019–1020 |
| สิทธิ์ `inbox:read` ใช้ดูรายการ thread/ข้อความ, export, ดูสถานะ handover | **documented** | บรรทัด 114 (Scopes) และคอลัมน์ Scope บรรทัด 1024–1030 |
| `GET /agents/{id}/inbox/threads` รับ `channel, search, page, limit` คืน `total`/`channel_counts` เสมอ | **documented** | บรรทัด 1024, ตัวอย่างบรรทัด 1038 |
| item มี `display_name` และจำนวนข้อความ | **documented** | ตัวอย่าง response บรรทัด 1054 |
| `display_name` มีเฉพาะ LINE, Webex, Telegram ช่องทางอื่นเป็น null | **documented** | บรรทัด 1066 |
| `channel_counts` นับทุก thread ของ agent ใช้ทำแท็บ/badge ได้โดยไม่ต้องยิงซ้ำ | **documented** | บรรทัด 1066 |
| `GET …/threads/{cid}/messages` รับ `cursor, limit` คืน items (`role`, `content`, `created_at`) + `next_cursor` | **documented** | บรรทัด 1026, 1071–1108 |
| ข้อความเรียงเก่า → ใหม่ · role เป็น user/assistant | **documented** | บรรทัด 855 (รูปแบบเดียวกับ Chat API ตามบรรทัด 1108) |
| ส่ง `next_cursor` กลับใน `?cursor=` เพื่อดึงหน้าถัดไป | **documented** (พารามิเตอร์ + ฟิลด์) | บรรทัด 1026, 1106 |
| `active: true` = แอดมินคุมสาย AI ไม่ตอบจนหมดอายุหรือถูกจบ · `active: false, expires_in_sec: null` = AI ตอบปกติ | **documented** | บรรทัด 1113–1119 |
| export xlsx/csv · `format, channel, date_from, date_to` | **documented** | บรรทัด 1030 |
| export คืนไฟล์ตรง (Content-Disposition: attachment) ไม่ใช่ JSON · ไม่ระบุวันที่ = ทั้งหมด · จำกัด 20,000 แถวต่อครั้ง | **documented** | บรรทัด 1126–1128 |
| ตอบลูกค้า / เริ่ม-จบ handover ใช้ API Key ไม่ได้ ต้อง login เว็บ เพราะเปลี่ยนสิ่งที่ end-user เห็น | **documented** | บรรทัด 1031–1032 |
| เก็บ API Key ไว้ฝั่ง server | **documented** | บรรทัด 20 |
| ป้าย “ลูกค้ารอตอบ” จาก `last_message_role = "user"` | **การออกแบบหน้าจอ** | ตีความฟิลด์เพื่อทำ UI ไม่ใช่ฟีเจอร์ของ API |
| ชื่อลูกค้า ข้อความ ตัวเลข และค่าวันที่ในตัวอย่าง | **illustrative** | ข้อมูลจำลองในภาพและกล่อง JSON |
| ความเร็ว / ความถี่ในการดึงข้อมูล (real-time, polling) | **unknown** | ไม่พูดถึงในบท ไม่อ้างว่า “เรียลไทม์” |

## 4. ข้อกำหนดซับไตเติลและจังหวะเสียง

* ซับ 31 ท่อน (ท่อนละ 1–2 บรรทัด) ขึ้นตรงกับเสียงพูดทีละท่อน ไม่แสดงทั้งประโยคล่วงหน้า
* เมื่อมีเสียงจริง จุดตัดซับมาจาก `assets/voice/<beat>.segments.json` (สร้างเสียงทีละท่อน) ถ้าไม่มีจะหาจากช่วงเงียบ
* เว้นจังหวะระหว่างท่อน 0.35 วินาที (LEAD 0.2 / GAP 0.35 / TAIL 0.6) · b5 ค้างกล่อง JSON เพิ่ม 1.5 วินาที (`hold`) ให้อ่านทัน
* คำศัพท์ API ในซับเขียนตามจริง (`inbox:read`, `channel_counts`, `next_cursor`, `?cursor=`) แต่ในบทพูดอ่านเป็นภาษาพูด (“inbox read”, “channel counts”, “next cursor”)
* เสียง: `th-TH-NiwatNeural` rate −16% (เหมือน EP04) สร้างด้วย `video/make-voice-samples.py` บนเครื่องผู้รับผิดชอบ
