# EP02 ระบบภาพและแบบผลิต r10

7 พฤศจิกายน 2026 · ออกแบบเสร็จสำหรับส่งต่อผลิต · ยังไม่ผลิต/ตรวจคลิป r10

ส่วน r10 ตั้งแต่ต้นไฟล์ถึง “ประวัติ r2” เป็น source of truth ของระบบภาพ component หน้าจอ และ assets ใช้คู่กับ [STORYBOARD r10](STORYBOARD.md) ซึ่งเป็น source of truth ของบท เวลา และลำดับ motion ไม่ใช้บท/เวลาร่าง r2 ท้ายไฟล์ทับ r10 เก็บประวัติเดิมทั้งหมดเพื่อรักษางานก่อนหน้า ดู [สถานะ](README.md), [ขอบเขต](PLAN.md), [ผลตรวจ](../../docs/plans/2026-11-07-ep02-continuity-r10.md)

## r10.1 โจทย์ หลักฐาน และทิศทาง

EP02 สอนวงจรเว็บแชทของเรา → server ของเรา → LangMind Agent → คำตอบ แล้วถามต่อด้วย conversation_id ผู้ชมรู้จักแชท AI แต่ยังแยกหน้าเว็บ/server/Agent ไม่คล่อง ดูจบควรแยก API key, Agent ID, conversation ID รู้ว่าอะไรเก็บที่ server และเริ่มทดลองกับ Agent ตนเอง ไม่สัญญาว่าได้ระบบ production จากการดูคลิป

ตัวอย่างเดียว: ทีมร้านขอร่างข้อความแจ้งส่งช้า แล้วขอฉบับสั้นสำหรับ LINE ไม่มีการส่ง LINE จริง ภาพคำตอบ/UI/ID เป็น illustrative ไม่ใช่ live evidence ไม่สร้างแอป/backend เพื่อถ่ายคลิป

Observed รอบนี้: อ่าน r9 source/config/manifest/REVIEW และเปิด export-contact.jpg ของคลิปล่าสุด เห็นพื้น #091D20 กรอบ #102C30 ไซแอน/ไลม์ Sarabun โลโก้จริง และโครงหัวข้อ/กรอบ/ซับซ้ำหลายช่วง script เดิมกำหนด cut ทั้ง38ช็อต ไม่ได้ดู MP4 เต็มหรือฟังครบในรอบนี้

Documented: r9 ยาว310.433333s 1080×1920/30fps H.264/AAC; API อ้าง [snapshot ต้นฉบับครบทุกหมวด](../../langmind-api.md) แยกจาก AlmondChat; URLแบรนด์ https://langmind.in.th มาจาก [brief](../../docs/PROJECT_BRIEF.md) ไม่ได้ตรวจสถานะเว็บออนไลน์รอบนี้

Inferred: การเปิดหัวข้อ/กรอบใหม่ทุกช็อตและสลับ code หลายหน้ามีส่วนให้รู้สึกเป็นสไลด์ แก้ด้วยการกระทำและวัตถุคงอยู่ ไม่อ้างผล retention ก่อนดูคลิปใหม่ Unknown: ความยาวเสียงใหม่ การอ่าน360px และoverlayช่องทางจริง

แนวเปิดที่พิจารณา:
1. “พิมพ์ว่า ขอสั้นลง แล้วแชทรู้ได้อย่างไรว่าหมายถึงข้อความไหน?” ให้ทายแล้วเฉลยด้วยรหัสบทสนทนา
2. “กดส่งหนึ่งครั้ง ข้อความเดินทางไปไหนก่อนกลับมา?” ชัดเรื่องระบบ แต่แรงสงสัยเรื่องถามต่อน้อยกว่า
3. “รหัส Agent กับ API key ใช้แทนกันได้ไหม?” มีคำตอบจริง แต่เริ่มด้วยศัพท์ก่อนประโยชน์

เลือกข้อ1 เพราะเป็นการกระทำที่คุ้น ทดลองกับrequest/responseเรื่องเดียวแล้วเฉลยB12ได้ตรงเนื้อหา ไม่ใช้clickbait ชื่อEP02/โลโก้เป็นรองช่วงเปิด โครงเรื่อง: ชวนคิด→เว้นทาย→ย้อนข้อความแรก→เตรียมและเดินข้อมูล→เห็นผล→ทดลองถามต่อ/เฉลย→ชวนลอง

Design Read: สื่ออธิบายแนวตั้งสำหรับคนเริ่มเชื่อมAPI ใช้สี LangMind r9 กับหน้าจอที่ติดตามต่อเนื่อง; ENERGY2 / RHYTHM3 / MOTION2 ไม่เพิ่มเกณฑ์interactive appให้MP4

### B01 · ทำไมต้องมีแชทในเว็บเรา · ร่าง 22 วินาที

คำถามก่อน: ใช้ ChatGPT อยู่แล้ว ทำไมต้องทำเว็บเอง? → เข้าใจเหตุผลว่าต้องการผู้ช่วยและเครื่องมือที่เข้ากับงานทีม

บท: “คุณอาจใช้ ChatGPT ช่วยร่างข้อความอยู่แล้ว แต่ถ้าอยากให้ทีมเปิดเว็บของร้าน แล้วใช้ผู้ช่วยที่กำหนดหน้าที่และน้ำเสียงไว้ พร้อมหน้าจอที่เข้ากับงานของเรา ต้องเชื่อมอะไรบ้าง? ตอนนี้เราจะพาจากการสร้าง API key ไปจนถึงส่งคำถาม รับคำตอบ และถามต่อ ด้วย LangMind API”

### B04 · เตรียมผู้ช่วยและแยกสองรหัส · ร่าง 28 วินาที

คำถามก่อน: Agent ID กับ key ใช้ต่างกันอย่างไร? → เลือกผู้ช่วยต่างจากยืนยันสิทธิ์

บท: “ก่อนเชื่อม ให้มี Agent ที่พร้อมใช้งาน และกำหนดหน้าที่ เช่น ร่างข้อความไทยสุภาพ ไม่แต่งวันส่งสินค้า จากนั้นเตรียมสองอย่าง รหัส Agent บอกว่าจะใช้ผู้ช่วยตัวไหน ส่วน API key ใช้ยืนยันสิทธิ์ในการเรียก เราจะสร้าง key แล้วนำไปตั้งค่า server คู่กับรหัส Agent”

ภาพ: D02 คำสั่งตัวอย่าง → กล่อง agent_id ‘เลือกผู้ช่วย’ และ API key ‘ยืนยันสิทธิ์’ แยกจังหวะ นี่คือภาพอธิบาย ไม่แต่ง dashboard การตั้งค่าโมเดลให้พร้อมเป็น prerequisite ไม่สอนตั้งระบบทั้งหมด

### B05 · สร้าง key และรู้ว่าตัวเลือกมีไว้ทำไม · ร่าง 45 วินาที

คำถามก่อน: เลือกอะไรแล้วได้อะไร? → รู้ชื่อ/อายุ/สิทธิ์และค่าที่นำไปใช้

บท: “เปิดหน้าจัดการ API แล้วสร้าง key ตั้งชื่อให้จำได้ว่าใช้กับแอปไหน ชื่อนี้เป็นป้ายกำกับ ส่วนอายุคือช่วงเวลาที่ key ใช้งานได้ และสิทธิ์กำหนดว่าเรียกงานอะไรได้ ตัวอย่างแชทใช้ chat:invoke ส่วนรหัส Agent เราจะคัดลอกจากหน้าผู้ช่วย จึงไม่ต้องเพิ่มสิทธิ์อ่านรายการเพื่อขั้นตอนนี้ เมื่อสร้างแล้ว เราจะนำค่า key ไปตั้งค่าให้ server ของแอป”

ภาพ: K01–05 จาก recording ผู้ใช้ ใช้ Feathered Spotlight หลัง crop เน้นชื่อ → อายุ → สิทธิ์ ทีละจุด ไม่แก้ label จริงหรือใส่ action ที่ไม่มี ไม่ทำ overlay เพื่อซ่อน key ผู้ใช้อนุญาตให้ key ปรากฏใน footage แล้ว ตัวอย่างสร้างใหม่ใช้ placeholder

ส่งต่อ: ป้าย ‘ค่าที่ได้จากการสร้าง key’ ไปช่อง LANGMIND_API_KEY ไม่คัดลอก secret ลงเอกสาร

### B06 · เอา key และ Agent ID ไปไว้ตรงไหน · ร่าง 42 วินาที

คำถามก่อน: สร้างแล้วเอาไปใช้ที่ไหน? → เห็นค่าจากหน้าเว็บผูกกับตัวแปรและโค้ด

บท: “ฝั่ง server เก็บ key เป็นค่าตั้งต้นชื่อ LANGMIND_API_KEY อีกค่าคือ LANGMIND_AGENT_ID สำหรับรหัสผู้ช่วย ให้เปิดหน้าของ Agent ที่เราสร้าง ดู URL ด้านบน แล้วคัดลอกเฉพาะรหัสยาวหลัง /agents/ ไม่ต้องคัดลอกทั้ง URL ในภาพตัวอย่าง .env ใช้แสดงตำแหน่งตั้งค่าสองค่านี้ ส่วนโค้ดฝั่ง server จะอ่านจากชื่อตัวแปร จึงไม่ต้องเขียน key จริงลงในหน้าเว็บ”

ภาพ: K06 หน้า Agent จากภาพผู้ใช้ → zoom address bar → เน้นเฉพาะส่วนหลัง /agents/ → รหัสเข้า LANGMIND_AGENT_ID ใน C01 คู่ key → F01 เน้น .env → เส้นชี้ process.env ใน C04 ทีละภาพ ใช้คำค่าตั้งต้นก่อน environment; Stepper แสดงจบเตรียมก่อนเปลี่ยนช่วง

หลักฐาน observed จากภาพและคำยืนยันผู้ใช้: หน้า Agent มี URL https://langmind.in.th/agents/a056aef2-3bfb-4564-8166-7abd28849c42 และ Agent ID เดิมคือ a056aef2-3bfb-4564-8166-7abd28849c42 (ผู้ใช้ยืนยันว่าใช้ไม่ได้แล้ว) ไม่ใช่ API key ไม่ใช่ conversation_id ใช้เป็นตัวอย่างตำแหน่งใน URL ผู้ชมต้องใช้ ID ของ Agent ตนเอง ภาพนี้เป็นผู้ช่วยเด็กฝึกงาน NECTEC ไม่ใช่ผู้ช่วยร้านตัวอย่าง จึง crop เน้น URL และระบุว่าเป็นตัวอย่างวิธีหารหัส ไม่อ้างว่าทั้งสองเป็น Agent เดียวกัน ไม่เรียก API หรือเปิดบัญชีจาก URL นี้

### C04 · server fetch · B09

```javascript
const BASE = 'https://langmind.in.th/api';

async function askAgent(query, conversationId) {
  const response = await fetch(
    `${BASE}/chat/message/blocking`,
    {
      method: 'POST',
      headers: {
        Authorization:
          `Bearer ${process.env.LANGMIND_API_KEY}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        agent_id: process.env.LANGMIND_AGENT_ID,
        query,
        conversation_id: conversationId,
      }),
    },
  );

  if (!response.ok) {
    throw new Error('ส่งข้อความไม่สำเร็จ');
  }
  return response.json();
}
```

แบ่งขึ้นภาพ C04a BASE/method, C04b headers, C04c body, C04d error/result ช็อตละ 4–7 บรรทัดเป้าหมาย แสดงเลขบรรทัดต่อเนื่องของไฟล์เดียวกัน ไม่ใช้ typing animation รอพิมพ์ทั้งไฟล์

Code Diff แสดงเฉพาะสอง field ที่เปลี่ยนจาก Q1/null เป็น Q2/ID พร้อมป้าย “แสดงเฉพาะส่วนที่เปลี่ยน; ยังส่ง agent_id เดิม” ไม่อ้างว่ารหัสตัวอย่างนำไปใช้จริงได้

### C09 · SSE protocol concept · หมายเหตุประกอบ B13 ไม่ขึ้นรายละเอียดในคลิปหลัก

```text
POST /api/chat/message
message_start → เก็บรหัสบทสนทนา
message       → เพิ่มส่วนคำตอบ
message_end   → คำตอบจบสมบูรณ์
```

เป็นแผนภาพ event ไม่ใช่ raw SSE payload หรือ parser แบบ executable หาก stream จบโดยไม่มี message_end ให้แสดง interrupted ไม่ถือว่าคำตอบครบ ไม่ทำ code-diff เปลี่ยนแค่ URL แล้วอ้างว่า frontend streaming ใช้งานได้ทันที

## 8. เสียง ซับ และจังหวะ

ผู้เล่าไทยน้ำเสียงชัด เป็นผู้สอนที่พาคิด ใช้คำถาม B01 ด้วยระดับเสียงขึ้นเล็กน้อย B03/B08 ช้าลงที่ศัพท์ใหม่ B12 ย้ำคำ “เดิม” ตอนกล่าวถึง ID ส่วน B16 สงบมั่นใจ ไม่โฆษณาเกินจริง

### F01 · ภาพแยกตำแหน่งโค้ด · B06–B10

เป็น diagram สำหรับวิดีโอ ไม่ใช่โครงสร้างโปรเจกต์ที่จะสร้างหรือแจก ไม่เลือก framework/runtime ไม่เพิ่ม dependencies หรือ server เพื่อถ่ายคลิป

แสดงสามแผงตามลำดับ: ‘ค่าตั้งต้นฝั่ง server’ (.env: LANGMIND_API_KEY=<API_KEY>, LANGMIND_AGENT_ID=<AGENT_ID>) → ‘โค้ดฝั่งหน้าเว็บ’ ส่งข้อความไป /api/chat → ‘โค้ดเชื่อมต่อฝั่ง server’ อ่านค่าตั้งต้นและเรียก LangMind ตาม contract ตัวอย่างชื่อไฟล์บนภาพเป็น label บอกหน้าที่ ไม่ใช่ไฟล์แอปที่มีจริง

สื่อสอนว่าผู้พัฒนาต้องเก็บ key ฝั่ง server และแยกบทสนทนาของผู้ใช้ โดย diagram และบทพากย์ ไม่อ้างว่าคลิปมี implementation นี้อยู่แล้ว ตัวอย่าง request/response คง placeholder และป้ายจำลอง
