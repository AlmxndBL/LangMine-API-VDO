# EP02 r10 (EP04 Style) — บทพากย์และซับสรุป

ใช้เสียง Kore r10 ชุด B01.wav–B16.wav ความยาวรวม 440 วินาที

## b01 (B01 · พิมพ์ว่า “ขอสั้นลง” แชทรู้ได้อย่างไร?) → assets/voice/B01.wav
พิมพ์ว่า ขอสั้นลง แชทรู้ได้อย่างไรว่าหมายถึงข้อความไหน? ต้องส่งเรื่องเดิมใหม่ หรือมีตัวเชื่อม? (ลองทายก่อน แล้วไปดูคำตอบพร้อมกัน)

## b02 (B02 · ย้อนดูข้อความแรกของทีมร้านค้า) → assets/voice/B02.wav
มาดูตัวอย่างทีมร้านค้า เราอยากมีหน้าเว็บให้ทีมใช้ร่างข้อความสุภาพ เริ่มจากขอแจ้งลูกค้าว่าสินค้าส่งช้า แล้วค่อยขอฉบับสั้นสำหรับ LINE ภาพนี้เป็นตัวอย่างอธิบาย ยังไม่ได้เรียก API จริง และยังไม่ได้ส่งข้อความให้ลูกค้า

## b03 (B03 · มองเป็น 3 ส่วน: หน้าเว็บ · Server · Agent) → assets/voice/B03.wav
มองเป็นสามส่วน หน้าเว็บคือที่พิมพ์และอ่าน server ของแอปรับข้อความและเก็บข้อมูลเชื่อมต่อ ส่วน LangMind Agent คือผู้ช่วยที่เราตั้งหน้าที่ไว้ คำถามเดินทางผ่าน server และคำตอบก็กลับมาทางเดิม หน้าจอกับส่วนเชื่อมต่อนี้เป็นส่วนที่เราพัฒนา ไม่ต้องให้หน้าเว็บถือ key ไปหา Agent เอง

## b04 (B04 · เตรียมผู้ช่วย และแยกสองค่า) → assets/voice/B04.wav
ก่อนเชื่อม ต้องมี Agent ที่พร้อมใช้งาน เช่น ผู้ช่วยร่างข้อความไทยสุภาพโดยไม่แต่งวันส่งสินค้า จากนั้นแยกสองค่า รหัส Agent ใช้เลือกว่าจะให้ผู้ช่วยตัวไหนตอบ ส่วน API key ใช้ยืนยันสิทธิ์ในการเรียก สองค่านี้ทำหน้าที่ต่างกัน และไม่ใช่รหัสบทสนทนาที่เราจะเห็นตอนถามต่อ

## b05 (B05 · สร้าง key สำหรับแอปเรา) → assets/voice/B05.wav
ในหน้าจัดการ API สร้าง key สำหรับแอปนี้ ตั้งชื่อเพื่อจำว่าใช้กับงานไหน อายุคือช่วงเวลาที่ key ใช้งานได้ ส่วนสิทธิ์บอกว่าเรียกงานอะไร ตัวอย่างแชทนี้ใช้ chat:invoke รหัส Agent เราจะคัดลอกจากหน้าผู้ช่วย จึงไม่ต้องเพิ่มสิทธิ์อ่านรายการสำหรับขั้นตอนนั้น เมื่อสร้างแล้วให้นำ key ไปตั้งค่าที่ server ภาพขั้นตอนเดิมนี้ไม่ได้ยืนยันว่า key ยังใช้ได้ในปัจจุบัน

## b06 (B06 · ตั้งค่าฝั่ง server) → assets/voice/B06.wav
เก็บ key เป็นค่าตั้งต้นฝั่ง server ชื่อ LANGMIND_API_KEY อีกค่าชื่อ LANGMIND_AGENT_ID ให้เปิดหน้า Agent ของคุณ แล้วคัดลอกเฉพาะรหัสหลัง /agents/ ไม่ใช่ทั้ง URL ในภาพใช้ค่าตัวอย่างเพื่อบอกตำแหน่ง โค้ด server อ่านค่าจากชื่อเหล่านี้ จึงไม่ต้องฝัง key จริงไว้ในหน้าเว็บที่ผู้ใช้เปิดดูได้

## b07 (B07 · หน้าเว็บส่งข้อความให้ /api/chat) → assets/voice/B07.wav
กลับมาที่ข้อความแรก เมื่อกดส่ง หน้าเว็บส่งข้อความไป /api/chat ซึ่งเป็นทางรับข้อความใน server ที่เราพัฒนา ไม่ใช่ endpoint ของ LangMind server ตรวจผู้ใช้และข้อความ แล้วหาบทสนทนาของผู้ใช้นั้น ก่อนส่งต่อไปยัง Agent หน้าเว็บจึงไม่ต้องรู้ key ของเรา

## b08 (B08 · แกะกล่อง POST Request) → assets/voice/B08.wav
server ส่ง POST ไปที่ API ของ LangMind เส้นทาง chat/message/blocking ซึ่งรอคำตอบเต็มก่อน ส่วนหัว Authorization ใส่ Bearer ตามด้วย key และบอกว่าข้อมูลเป็น JSON ใน body มี agent_id เลือกผู้ช่วย query คือคำถาม และ conversation_id ครั้งแรกเป็น null ตัวอย่างนี้ไม่ส่ง user_id จึงอย่าเหมารวมว่า null เริ่มเรื่องใหม่เสมอในทุกเงื่อนไข

## b09 (B09 · ส่งคำขอ แล้วตรวจผล) → assets/voice/B09.wav
ในโค้ดฝั่ง server ใช้ fetch ส่งคำขอนี้ ค่า key กับรหัส Agent อ่านจากค่าตั้งต้น ส่วนคำถามมาจากหน้าเว็บ และรหัสบทสนทนามาจากข้อมูลของผู้ใช้นั้น เมื่อได้ผลกลับมา ต้องตรวจว่าสำเร็จและรูปแบบข้อมูลถูกต้องก่อนนำไปใช้ โค้ดบนภาพเป็นส่วนอธิบาย ยังต้องเชื่อมระบบผู้ใช้และการเก็บข้อมูลจริง

## b10 (B10 · แสดงคำตอบ · เก็บรหัสบทสนทนา) → assets/voice/B10.wav
ผลตัวอย่างนี้มี answer คือข้อความคำตอบ และ conversation_id คือรหัสบทสนทนา server เก็บรหัสไว้คู่กับเจ้าของ แล้วส่งคำตอบไปให้หน้าเว็บแสดง ตอนนี้ข้อความแรกเดินทางครบแล้ว ลองจำรหัสบทสนทนานี้ไว้ เพราะอีกสักครู่เราจะใช้มันกับคำว่า ขอสั้นลง

## b11 (B11 · กรณีระหว่างรอ · ถ้าส่งไม่สำเร็จ) → assets/voice/B11.wav
ระหว่างรอ แอปควรบอกว่ากำลังรอคำตอบและกันกดส่งซ้ำ ถ้าส่งไม่สำเร็จ ให้บอกตรง ๆ และเก็บข้อความไว้ให้ลองใหม่ สถานะเหล่านี้เป็นส่วนที่เราต้องจัดการในแอป ไม่ใช่ข้อความที่ Agent ตอบ ตอนนี้กลับมาที่ตัวอย่างที่ได้รับคำตอบแล้ว เพื่อถามต่อกัน

## b12 (B12 · เฉลย: ถามต่อด้วย conversation_id เดิม) → assets/voice/B12.wav
ขอสั้นลง ต้องเปลี่ยนอะไร เก็บอะไรไว้? เราเปลี่ยน query เป็น ขอสั้นลงสำหรับส่งใน LINE แต่ส่ง conversation_id เดิมที่ได้จากรอบก่อน จึงเป็นการคุยต่อในบทสนทนาเดียวกัน ไม่ใช่เอา API key หรือรหัส Agent มาแทนรหัสนี้ server ยังต้องตรวจด้วยว่าบทสนทนานั้นเป็นของผู้ใช้คนนี้ คำตอบที่เห็นเป็นร่างให้ตรวจอีกครั้ง ยังไม่ได้ส่งเข้า LINE

## b13 (B13 · รอคำตอบครบ vs รับข้อมูลเป็นช่วง) → assets/voice/B13.wav
ตัวอย่างที่ผ่านมารอคำตอบครบแล้วค่อยแสดง ถ้าอยากให้ทยอยขึ้น มี endpoint แบบรับข้อมูลเป็นช่วง แต่ต้องปรับทั้ง server และหน้าเว็บ ไม่ใช่แค่ทำตัวอักษรค่อย ๆ ปรากฏ หรือเปลี่ยน URL อย่างเดียว

## b14 (B14 · ออกแบบหน้าจอให้เหมาะกับทีม) → assets/voice/B14.wav
เมื่อเข้าใจวงจรนี้ เราออกแบบหน้าจอให้เข้ากับทีมได้ มือถืออาจเน้นพิมพ์กับอ่าน ส่วนจอใหญ่เพิ่มพื้นที่แก้ข้อความก่อนนำไปใช้ การจัดพื้นที่และปุ่มเหล่านี้เป็นงานของแอปที่เราพัฒนา ส่วนการเรียก Agent ยังใช้หลักเดิม

## b15 (B15 · ทวนวงจร และแยก 3 ค่าสำคัญ) → assets/voice/B15.wav
ลองทวนจากข้อความเดียว หน้าเว็บส่งคำถาม server เชื่อมกับ Agent แล้วนำ answer กลับมาแสดง ส่วน conversation_id เก็บไว้ถามต่อ Agent ID เลือกผู้ช่วย API key ยืนยันสิทธิ์ และรหัสบทสนทนาเชื่อมเรื่องเดิม ถ้าคุณจะเริ่ม ลองเลือกข้อความหนึ่งเรื่องที่อยากให้ผู้ช่วยร่างก่อน

## b16 (B16 · ตาคุณลองแล้ว · LangMind) → assets/voice/B16.wav
ตาคุณลองแล้ว ใช้ Agent ของคุณร่างข้อความหนึ่งเรื่อง แล้วขอให้สั้นลงในแชทเดิม เริ่มสำรวจ LangMind ได้ที่ แลงมายด์ ดอต ไอเอ็น ดอต ทีเอช
