# EP13 — Short Links API: ลิงก์โปรของร้าน ย่อลิงก์และนับคลิกเอง

อัปเดต 9 พฤศจิกายน 2026 (Asia/Bangkok) · v1 ใช้ Short Links API ครบทุก endpoint ในคู่มือ (usage, สร้าง + ตัวเลือก, รายการ/อ่าน/แก้/ลบ, สถิติลิงก์เดียว/ภาพรวม/export CSV, error 3 รหัส) · ใช้โครงเดียวกับ EP12 (เล่าจากมุมคนดู: เตรียม → เชื่อม → ใช้ผล + ปิดท้ายผู้สนับสนุน)

## 1. โจทย์จากมุมคนดู (Audience & Purpose)
- **คนดู**: เจ้าของร้าน / ทีมการตลาด / dev ที่ดูแลระบบหลังบ้าน ร้านส่งโปรให้ลูกค้าทาง LINE เป็นประจำ
- **ปัญหา**: ลิงก์โปรยาว เต็มไปด้วยตัวแปร UTM และร้านไม่รู้ว่ามีลูกค้ากดลิงก์ไปกี่คน
- **ทำไมต้องดู**: อยากให้ระบบหลังบ้านของร้านสร้างลิงก์สั้นเองและดูจำนวนคลิกได้ แต่ไม่รู้ว่าต้องเตรียมอะไร เรียก endpoint ไหน และ API ให้ข้อมูลอะไรกลับมา
- **ดูจบแล้วต้องตอบได้**
  1. ต้องเตรียม 3 อย่าง: API Key สิทธิ์ `short_links:write` + `short_links:read`, ระบบหลังบ้าน, รู้แผนของบัญชี (โควตาเดียวกับหน้า “ลิงก์ย่อ” ในเว็บ)
  2. เชื่อม 4 แบบ: เช็กโควตา (`usage`) → สร้างลิงก์ (+ตัวเลือก) → จัดการลิงก์ (รายการ/แก้/ลบ) → ดูสถิติ (ลิงก์เดียว/ภาพรวม/CSV)
  3. ได้ฟิลด์อะไรกลับมา และเอาไปทำส่วนไหนของหน้าลิงก์โปร
  4. error ที่ต้องรับมือ: เกินโควตา (422/429) และปลายทางไม่ผ่านการตรวจความปลอดภัย (422)

## 2. แกนคำอธิบายและ Use Case
- **Use case**: ร้านกาแฟเดียวกับ EP12 ส่ง “โปรเดือนนี้” ทาง LINE ใช้ค่าจากตัวอย่างในคู่มือตรง ๆ (`https://shop.example.com/sale`, `utm.source=line`, `utm.campaign=oct`, ได้ `https://s3t.me/s/k7m2p9x`)
- **เส้นเรื่อง**: ระบบหลังบ้าน → Short Links API → ลิงก์สั้น → ส่งใน LINE → ลูกค้ากด → ระบบนับคลิก → ร้านดึงสถิติ
- ไม่อ้างเรื่อง redirect speed, ความแม่นของการนับ, หรือรายละเอียดสถิติที่คู่มือไม่ได้ระบุ (ประเทศ อุปกรณ์ ฯลฯ)

## 3. โครงเรื่อง 12 ช่วง
| Beat | คำถามคนดู | สิ่งที่เห็น |
|---|---|---|
| b1 | ปัญหาคืออะไร | แชท LINE ของร้าน: ลิงก์ยาวเต็มไปด้วย UTM → สลับเป็นลิงก์สั้นพร้อมพรีวิว · 3 คำถาม |
| b2 | ภาพรวม | ระบบหลังบ้าน → Short Links API → LangMind ได้ `s3t.me/s/…` → ลูกค้ากด → สถิติการคลิก |
| b3 | เตรียม | API Key `short_links:write` (สร้าง/แก้/ปิดใช้งาน/ลบ) + `short_links:read` (ดูลิงก์/โควตา/สถิติ) · ระบบหลังบ้าน · รู้แผน |
| b4 | เชื่อม 1 เช็กโควตา | `GET /api/short-links/usage` → ใช้ไปเท่าไรเทียบเพดาน + ฟีเจอร์ที่แผนเปิด |
| b5 | เชื่อม 2 สร้าง | `POST /api/short-links` (`target_url`, `title`, `utm`) → `code`, `short_url`, `target_url` (เติม UTM), `state: active`, `total_clicks: 0` |
| b6 | ตัวเลือกตอนสร้าง | `alias`, `tags`, `expires_at`, `max_clicks`, `password` · ป้าย “ตามแผน” |
| b7 | เชื่อม 3 จัดการ | `GET /api/short-links?q=&tag=&state=&sort=clicks&limit=&offset=` · `PATCH /{id}` (เฉพาะช่องที่แก้, `null` = ล้าง) · `DELETE /{id}` |
| b8 | เชื่อม 4 สถิติ | `GET /{id}/analytics?from_date=&to_date=` · `GET /analytics` · `GET /{id}/analytics/export` (CSV รายวัน) |
| b9 | ข้อควรระวัง | `SHORT_LINK_LIMIT_EXCEEDED` 422 · `SHORT_LINK_RATE_EXCEEDED` 429 · `SHORT_LINK_TARGET_BLOCKED` 422 + เหตุผล |
| b10 | ใช้ผล | หน้าลิงก์โปร: แถบโควตา, เรียงตามคลิก, ลิงก์+คัดลอก, สถานะ, คลิกรวม → หน้าสถิติ: กราฟรายวัน, ปุ่ม CSV |
| b11 | สรุป | เตรียม → เชื่อม 4 แบบ → ใช้ผล |
| b12 | ผู้สนับสนุน | โลโก้ LangMind · langmind.in.th |

## 4. Claim ledger (สรุป)
ตารางเต็มพร้อมเลขบรรทัดอยู่ที่ [SCRIPT.md](SCRIPT.md) หมวด 3 · ทุกข้อเกี่ยวกับ API มาจาก `langmind-api.md` บรรทัด 112–113 (Scopes) และ 1130–1165 (Short Links API)

สิ่งที่คู่มือ **ไม่ได้ระบุ** และคลิปไม่อ้าง:
- รูปแบบ response ของ `usage` และ `analytics` (คลิปพูดแค่ “ใช้ไปเท่าไรเทียบเพดาน”, “สถิติการคลิก” ไม่แสดงชื่อฟิลด์)
- ค่า `state` อื่นนอกจาก `active` และวิธี “ปิดใช้งาน” (scope บอกว่าทำได้ แต่ไม่บอกว่าใช้ฟิลด์ไหน)
- รูปแบบค่า `expires_at` และพฤติกรรมของ `password`
- ความหมายเจาะจงของ `SHORT_LINK_RATE_EXCEEDED` (คู่มือจัดไว้ใต้ “เกินโควตา”)
