# EP06 — Knowledge & Datasets API: เติมความรู้ให้ AI อัตโนมัติและเช็กผลค้นคืน (RAG)

สถานะ: ออกแบบ W3–W4 เสร็จสมบูรณ์ รอเริ่มสร้าง Sample (W5) และการผลิต (W6)  
อ้างอิง: [Workflow](../../docs/WORKFLOW.md), [ข้อกำหนด Storyboard](../../docs/STORYBOARD_GUIDELINES.md) และคู่มือ [langmind-api.md](../../langmind-api.md)

## 1. โจทย์จากมุมคนดู (Audience & Purpose)

* **ผู้ชมเป้าหมาย**: Developer, เจ้าของระบบ หรือทีมดูแลเว็บไซต์ที่มี Agent ตอบแชทอยู่แล้ว และต้องการอัปเดตเอกสารข้อมูลสินค้า/โปรโมชันเข้าคลังความรู้อัตโนมัติผ่าน API
* **พื้นฐานเดิมของผู้ฟัง**: รู้จักการเรียก API ด้วย Bearer Token (`lmpat_`) และมี Agent ตอบแชทพื้นฐานแล้ว แต่ยังไม่รู้วิธีส่งเอกสารเข้าคลังความรู้ผ่านโค้ดและวิธีทดสอบว่า AI ค้นเจอข้อมูลหรือไม่
* **ความต้องการหลัก**: อยากส่งไฟล์เอกสาร (PDF/DOCX), ลิงก์หน้าเว็บ หรือข้อความตรงเข้าคลังความรู้ (Dataset) ของ Agent อัตโนมัติ และเช็กผลค้นคืน (Retrieval) ได้โดยไม่ต้องเสียโควตาเรียก LLM
* **จุดติดขัด (Friction)**:
  * ต้องคอยล็อกอินเข้าเว็บไปอัปโหลดไฟล์ใหม่ทุกครั้งที่ข้อมูลสินค้าหรือโปรโมชันเปลี่ยน
  * ไม่รู้ว่าอัปโหลดไฟล์แล้วพร้อมใช้งานทันทีหรือไม่ (ความจริงคือทำงานแบบ background indexing)
  * เวลา AI ตอบไม่ตรง ไม่รู้ว่าเป็นเพราะค้นเอกสารไม่เจอ หรือเป็นเพราะ Prompt ของ LLM
* **เหตุผลที่ดู**: เห็นท่อการอัปเดตคลังความรู้ 3 ขั้นตอน (**อัปโหลดและเช็กสถานะ → ผูกคลังเข้ากับ Agent → ทดสอบค้นคืนด้วย `/retrieval/test`**)
* **สิ่งที่ดูจบแล้วนำไปทำต่อได้**: เขียนสคริปต์หรือระบบหลังบ้านอัปโหลดเอกสารเข้า Dataset, เช็กสถานะ `indexed`, ผูกเข้ากับ Agent และยิงทดสอบค้นคืนเพื่อดู `segments` กับ `score` ได้ถูกต้อง

## 2. แกนคำอธิบายและ Use Case ตัวอย่าง

* **Use Case ตัวแทน**: **"ระบบอัปเดตเมนูและโปรโมชันร้านกาแฟอัตโนมัติ (Cafe Promo Knowledge Updater)"**
  * *เหตุการณ์*: ผู้จัดการร้านอัปโหลดไฟล์ `โปรโมชันเดือนนี้.pdf` ในระบบหลังบ้านของร้าน ระบบส่งไฟล์เข้า LangMind Dataset รอจนสถานะเป็น `indexed` ผูกกับ Agent แล้วลองค้นคำว่า `"โปรโมชันอเมริกาโน่"`
  * *ผลลัพธ์*: ระบบแสดงส่วนของเอกสาร (`segments`) ที่ค้นเจอจากหน้าคู่มือพร้อมค่าความคล้าย (`score`) โดยยังไม่ต้องเสียโทเค็นเรียก LLM
* **ท่อการทำงาน 3 ครั้ง (เตรียม → เชื่อม 3 ครั้ง → ใช้ผล)**:
  1. **ครั้งที่ 1: สร้างคลังและอัปโหลดเอกสาร (`POST /datasets` & `POST /datasets/{id}/documents/upload`)**: ส่งไฟล์เข้าคลัง รับสถานะ `202` (`pending`) แล้ว poll ดู `GET /documents/{id}` จนเป็น `indexed`
  2. **ครั้งที่ 2: ผูกคลังความรู้เข้ากับ Agent (`PUT /agents/{id}/datasets`)**: นำ `dataset_id` ไปผูกกับ Agent พร้อมกำหนดน้ำหนัก (`weight`)
  3. **ครั้งที่ 3: ทดสอบค้นคืนโดยไม่เรียก LLM (`POST /retrieval/test`)**: ส่ง `agent_id` และคำค้น `query` เพื่อดู `segments` และ `score` ที่ดึงมาจาก RAGFlow
* **การแบ่งหน้าที่ชัดเจน (Separation of Concerns)**:
  * **LangMind API ทำหน้าที่**: จัดการ Dataset, แยกย่อยและทำดัชนีเอกสารเบื้องหลัง (RAGFlow facade), ผูกคลังกับ Agent และค้นคืนส่วนเอกสารที่เกี่ยวข้อง
  * **แอปพลิเคชัน (Developer) ทำหน้าที่**: ส่งไฟล์เมื่อข้อมูลร้านเปลี่ยน, poll เช็กสถานะจนเป็น `indexed` ก่อนใช้งาน และเก็บ API Key ไว้ที่ระบบหลังบ้าน

## 3. โครงเรื่อง 9 ช่วง (9-Beat Outline แบบ EP04 v3)

| Beat | คำถามคนดู | สิ่งที่เห็นในจอ |
|---|---|---|
| **b1** | ฟีเจอร์นี้แก้ปัญหาอะไร | หน้าจอหลังบ้านร้านกาแฟอัปโหลดไฟล์ `โปรโมชันเดือนนี้.pdf` แล้ว AI รู้เรื่องโปรใหม่โดยไม่ต้องเข้าเว็บไปอัปโหลดมือ · ตั้ง 3 คำถาม: เตรียมอะไร · เชื่อมตรงไหน · เอาผลไปใช้ยังไง |
| **b2** | ภาพรวมทั้งหมดทำงานยังไง | แผนผัง 3 ส่วน: ระบบหลังบ้านร้าน ⇄ LangMind Knowledge API ⇄ Agent · เรียกเชื่อมต่อ 3 ครั้ง: **1. อัปโหลดเอกสาร → 2. ผูกคลังกับ Agent → 3. ทดสอบค้นคืน** |
| **b3** | ต้องเตรียมอะไรบ้าง | 1. Agent ใน LangMind และผู้ดูแลระบบตั้งค่า RAG เรียบร้อย (ถ้าไม่ตั้งจะได้ `503 RAGFLOW_NOT_CONFIGURED`) · 2. API Key (`lmpat_`) สิทธิ์ `knowledge:write`, `knowledge:read`, `agents:write` · 3. ระบบหลังบ้านเก็บ Key |
| **b4** | ครั้งที่ 1: อัปโหลดเอกสารและเช็กสถานะ | สร้าง Dataset (`POST /api/datasets`) แล้วส่งไฟล์เข้า `POST /api/datasets/{id}/documents/upload` ได้ `202` สถานะ `pending` จากนั้น poll `GET /api/documents/{id}` จนเป็น `indexed` |
| **b5** | ครั้งที่ 2: ผูกคลังความรู้เข้ากับ Agent | ส่ง `PUT /api/agents/{id}/datasets` พร้อม `dataset_id` และ `weight: 1` เพื่อให้ Agent ใช้คลังข้อมูลนี้เวลาตอบคำถาม |
| **b6** | ครั้งที่ 3: ทดสอบค้นคืนโดยไม่เรียก LLM | ส่ง `POST /api/retrieval/test` ระบุ `agent_id` และ `query: "โปรโมชันอเมริกาโน่"` ได้ `segments` (`document_name`, `content`, `score`) และ `latency_ms` กลับมาแสดงบนจอ |
| **b7** | เอาผลไปใช้ยังไง | ใช้ตรวจว่าเอกสารที่อัปโหลดค้นเจอจริงก่อนเปิดให้ลูกค้าถาม · นอกจากการอัปโหลดไฟล์เดี่ยว ยังรองรับหลายไฟล์ (`upload-batch` ≤ 50 MB), ลิงก์เว็บ (`/url`), ข้อความตรง (`/text`) และไล่เก็บเว็บ (`/crawl`) · ย้ำว่า `score` คือค่าความคล้ายในการค้นคืน ไม่ใช่เปอร์เซ็นต์ความถูกต้อง |
| **b8** | สรุป | เตรียม Agent + ตั้งค่า RAG + Key 3 สิทธิ์ → เชื่อม 3 ครั้ง (อัปโหลดรอ `indexed` · ผูก Agent · ทดสอบ `retrieval/test`) → เอาผลไปเช็กคุณภาพคลังความรู้และอัปเดตข้อมูลอัตโนมัติ |
| **b9** | ผู้สนับสนุน | โลโก้ LangMind · `langmind.in.th` |

## 4. ขอบเขตคำตอบและหลักฐาน (Claim Ledger เทียบ `langmind-api.md`)

| สร้าง Dataset ด้วย `POST /api/datasets` (`knowledge:write`) | **documented** | บรรทัด 413, 440–458 |
| อัปโหลดไฟล์เข้า Dataset ด้วย `POST /api/datasets/{id}/documents/upload` คืน `202` เพราะทำ indexing เบื้องหลัง | **documented** | บรรทัด 421, 465–483 |
| สถานะเอกสารไล่ตาม `pending → processing → indexed` (หรือ `failed`) เช็กด้วย `GET /api/documents/{id}` | **documented** | บรรทัด 430, 495 |
| อัปโหลดหลายไฟล์ด้วย `upload-batch` (3–50 ไฟล์ตามแผน ขนาดรวมต่อคำขอ ≤ 50 MB) | **documented** | บรรทัด 423, 484–493 |
| รองรับการสร้างเอกสารจาก `/url`, `/text`, และ `/crawl` (คืน `status: "queued"`) | **documented** | บรรทัด 425–429, 497–521 |
| ผูก Dataset เข้ากับ Agent ด้วย `PUT /api/agents/{id}/datasets` (ส่ง `dataset_id` และ `weight`) | **documented** | บรรทัด 142–143, 363–385 |
| ทดสอบค้นคืนโดยไม่เรียก LLM ด้วย `POST /api/retrieval/test` (`knowledge:read`) คืน `segments`, `score`, `latency_ms` | **documented** | บรรทัด 436, 523–560 |
| หากผู้ดูแลระบบยังไม่ได้ตั้งค่า RAG จะได้ `503 RAGFLOW_NOT_CONFIGURED` | **documented** | บรรทัด 560 |
| `score` ในผลการค้นคืนไม่ใช่เปอร์เซ็นต์ความถูกต้องของคำตอบ | **documented (กฎโปรเจกต์)** | AGENTS.md หมวด API และความถูกต้อง |
| เก็บ API Key (`lmpat_`) ไว้ฝั่ง Server เท่านั้น | **documented** | บรรทัด 20, 90 และ AGENTS.md |
| หน้าจออัปเดตโปรโมชันร้านกาแฟ (`APP-RAG-UPLOAD` / `APP-RAG-TEST`) | **illustrative** | ออกแบบจำลองขึ้นเอง ติดป้าย "ภาพจำลอง" ชัดเจน |
