# EP09 — Analytics & Feedback API: ทำ Dashboard วัดผล คุมงบ Token และเก็บคะแนนคำตอบ

สถานะ: ออกแบบ W3–W4 เสร็จสมบูรณ์ รอเริ่มสร้าง Sample (W5) และการผลิต (W6)  
อ้างอิง: [Workflow](../../docs/WORKFLOW.md), [ข้อกำหนด Storyboard](../../docs/STORYBOARD_GUIDELINES.md) และคู่มือ [langmind-api.md](../../langmind-api.md)

## 1. โจทย์จากมุมคนดู (Audience & Purpose)

* **ผู้ชมเป้าหมาย**: Developer, Product Owner หรือเจ้าของธุรกิจที่ปล่อยฟีเจอร์แชท AI ขึ้นใช้งานจริงแล้ว และอยากวัดผลการใช้งาน คุมงบประมาณค่า Token และรู้ว่าลูกค้าพึงพอใจคำตอบหรือไม่
* **พื้นฐานเดิมของผู้ฟัง**: เชื่อมต่อ Chat API เป็นแล้ว (EP02) แต่ยังไม่เคยส่งคะแนน Feedback หรือดึงข้อมูลสถิติมาทำ Dashboard ในระบบหลังบ้านของตัวเอง
* **ความต้องการหลัก**: อยากรู้จำนวนผู้ใช้งานจริง ค่าใช้จ่าย (`cost_usd`) จำนวนโทเค็น อัตราสำเร็จ และคะแนนถูกใจ/ไม่ถูกใจของแต่ละ Agent
* **จุดติดขัด (Friction)**:
  * เรียก Chat API ด้วย API Key แล้วทำไมสถิตินับผู้ใช้เป็นแค่ 1 คน (เพราะไม่ได้ส่ง `user_id` ของผู้ใช้ปลายทาง)
  * ไม่รู้ว่า API รับคะแนน Feedback เป็นสเกลไหน (ความจริงคือรับแค่ `1` กับ `-1` ไม่ใช่สเกล 1–5)
  * อยากดึงตัวเลขเดียวกับหน้า Analytics บนเว็บมาแสดงในระบบหลังบ้านของบริษัทเอง
* **เหตุผลที่ดู**: เห็นท่อการเก็บข้อมูลและวัดผล 3 จังหวะ (**ส่ง `user_id` ตอนแชท → ส่งคะแนน `feedback` → ดึงรายงาน `analytics`**)
* **สิ่งที่ดูจบแล้วนำไปทำต่อได้**: ส่ง `user_id` อย่างถูกเงื่อนไข, ทำปุ่มกด 👍/👎 ส่งเข้า `/chat/messages/{id}/feedback` และดึงข้อมูลจาก `/analytics/agents` มาสร้าง Dashboard สรุปผลได้

## 2. แกนคำอธิบายและ Use Case ตัวอย่าง

* **Use Case ตัวแทน**: **"ระบบให้คะแนนคำตอบและ Dashboard สรุปงบผู้ช่วยร้านกาแฟ (Cafe AI Feedback & Cost Dashboard)"**
  * *เหตุการณ์*: ลูกค้ากดปุ่ม 👍 ให้คะแนนคำตอบเรื่องราคาสินค้าในหน้าแชท และผู้จัดการร้านเปิดหน้า Dashboard ดูสรุปจำนวนบทสนทนา โทเค็น ค่าใช้จ่าย และคะแนนบวก/ลบของเดือนนั้น
  * *ผลลัพธ์*: เห็นทั้งภาพรวมทุก Agent และเจาะลึกรายวัน (`daily`), แยกตามโมเดล (`models`), ช่องทาง (`channels`) และเครื่องมือ (`tools`)
* **ท่อการทำงาน 3 ครั้ง (เตรียม → เชื่อม 3 ครั้ง → ใช้ผล)**:
  1. **ครั้งที่ 1: ส่ง `user_id` ตอนเรียกแชท (`POST /api/chat/message` หรือ `/blocking`)**: ระบุรหัสผู้ใช้ปลายทางเพื่อให้ระบบนับ `active_user_count` แยกคนตามจริง
  2. **ครั้งที่ 2: บันทึกคะแนนคำตอบ (`POST /api/chat/messages/{id}/feedback`)**: ส่ง `rating: 1` หรือ `-1` พร้อม `comment`
  3. **ครั้งที่ 3: ดึงสถิติการใช้งาน (`GET /api/analytics/agents` & `/analytics/agents/{id}`)**: ดึงสรุปภาพรวมและข้อมูลแยกย่อยตามช่วงวันที่ (`from`, `to`)
* **การแบ่งหน้าที่ชัดเจน (Separation of Concerns)**:
  * **LangMind API ทำหน้าที่**: รวบรวมสถิติการสนทนา โทเค็น ค่าใช้จ่าย อัตราสำเร็จของ LLM/tool และคะแนน Feedback
  * **แอปพลิเคชัน (Developer) ทำหน้าที่**: จัดการ `user_id` และ `conversation_id`, สร้างปุ่มให้คะแนนบนหน้าแชท และแสดงผลกราฟใน Dashboard

## 3. โครงเรื่อง 9 ช่วง (9-Beat Outline แบบ EP04 v3)

| Beat | คำถามคนดู | สิ่งที่เห็นในจอ |
|---|---|---|
| **b1** | เปิดใช้แชทแล้ว รู้ได้ยังไงว่าคนใช้กี่คน เสียเงินเท่าไหร่ และตอบดีไหม | หน้าจอแชทมีปุ่ม 👍/👎 คู่กับหน้า Dashboard สรุปงบและจำนวนผู้ใช้ · ตั้ง 3 คำถาม: เตรียมอะไร · เชื่อมตรงไหน · เอาผลไปใช้ยังไง |
| **b2** | ภาพรวมทั้งหมดทำงานยังไง | แผนผัง: หน้าแชทลูกค้า ⇄ ระบบหลังบ้าน ⇄ LangMind · เชื่อม 3 จุด: **1. ส่ง `user_id` ตอนแชท → 2. ส่งคะแนน Feedback → 3. ดึงสถิติ Analytics** |
| **b3** | ต้องเตรียมอะไรบ้าง | 1. รหัสอ้างอิงผู้ใช้ปลายทาง (`user_id`) และ `message_id` ของคำตอบ · 2. API Key (`lmpat_`) สิทธิ์ `chat:invoke` และ `analytics:read` · 3. ระบบหลังบ้านเก็บ Key |
| **b4** | ครั้งที่ 1: ทำยังไงให้ระบบนับจำนวนผู้ใช้แยกคนได้จริง | ตอนส่งแชทเข้า `/api/chat/message` หรือ `/blocking` ให้ส่ง `user_id` ของผู้ใช้ปลายทาง (ถ้าไม่ส่ง ทุกคำขอจะถูกนับเป็นเจ้าของ API Key คนเดียว; และระวังว่าถ้าส่ง `conversation_id: null` พร้อม `user_id` ระบบอาจคุยต่อในเธรดที่เปิดอยู่ของผู้ใช้นั้น) |
| **b5** | ครั้งที่ 2: เก็บคะแนนถูกใจ/ไม่ถูกใจทำยังไง | ส่ง `POST /api/chat/messages/{id}/feedback` ระบุ `rating: 1` หรือ `-1` (รับเฉพาะ `1` กับ `-1` เท่านั้น ไม่ใช่สเกล 1–5) และ `comment` คืนสถานะ `204` |
| **b6** | ครั้งที่ 3: ดึงสรุปจำนวนแชท โทเค็น และค่าใช้จ่ายยังไง | เรียก `GET /api/analytics/agents?from=2026-08-01&to=2026-08-18` ดูสรุปทุก Agent และเรียก `GET /api/analytics/agents/{id}` เพื่อดูเจาะลึก `daily`, `models`, `channels`, `tools` |
| **b7** | เอาผลไปใช้ยังไง | นำ `conversation_count`, `active_user_count`, `total_tokens`, `cost_usd`, `avg_latency_ms`, `llm_success_rate` และ `feedback_positive / negative` ไปทำ Dashboard คุมงบและติดตามคุณภาพรายวัน |
| **b8** | สรุป | เตรียม `user_id` + Key (`chat:invoke`, `analytics:read`) → ส่ง `user_id` · เก็บ `feedback` · ดึง `analytics` → วัดผลและคุมต้นทุนได้ชัดเจน |
| **b9** | ผู้สนับสนุน | โลโก้ LangMind · `langmind.in.th` |
