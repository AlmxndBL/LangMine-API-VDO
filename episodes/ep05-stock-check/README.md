# EP05 — ลูกค้าถาม ของมีไหม? ให้ AI เช็กให้

ข้อมูลสมมติ ร้านเสื้อ คำถามเดียว “เสื้อสีดำ ไซซ์ M ยังมีไหม?”
ตารางตัวอย่างมี ดำ / S / 2, ดำ / M / 3, ขาว / M / 5 คำตอบ “สีดำ ไซซ์ M มี 3 ตัวค่ะ”
ความสามารถอ้างอิง https://langmind.in.th/features ส่วน Custom Tools / OpenAPI ระบบร้านต้องมีเครื่องมือหรือ API ที่เตรียมไว้

ลำดับภาพ คำถาม → LangMind เรียกเครื่องมือ → ระบบร้านคืนข้อมูล → แอปแสดงคำตอบ
ภาพร่าง 3 ช่องแนวนอน แต่ละช่องเป็น raster 4:5
ช่องแรกเป็น UI คำถาม พื้นขาว เขียวอ่อน หัว “ถามร้าน” กล่องคำถาม และสถานะ “ส่งคำถามแล้ว”
ช่องกลางเป็นตารางข้อมูลร้าน หัว “สต็อกตัวอย่าง” คอลัมน์ “สี / ไซซ์ / จำนวน” และสามแถวข้างต้น ไฮไลต์แถว ดำ M 3
ช่องท้ายเป็น UI เดียวกับช่องแรก เพิ่มกล่องคำตอบเท่านั้น
ป้ายภาพจำลองอยู่ภายนอก raster ตลอดเวลา ครอปแต่ละช่องเพื่อแสดงกว้าง 864 px บนจอ 1080×1920
HTML ทำกรอบภาพ diagram ป้ายชื่อและซับ ภาพแชทกับตารางทั้งหมดอยู่ใน raster

## W1 สำหรับฉบับขยาย · M มีของ และ L หมด

ยึดขอบเขต W0 ที่ตกลงกัน คลิป 60–90 วินาทีสำหรับเจ้าของร้านออนไลน์ ช่วงตั้งค่าใช้ภาษาที่ทำตามได้ เริ่มจากข้อมูลสินค้า เชื่อมเครื่องมือ และทดลองถามสองกรณี

| หน้าที่ภาพ | ตัวเลือกที่สำรวจ | ข้อสังเกตจาก preview และตัวอย่างเดิม |
|---|---|---|
| ให้คนดูตามแชทเดิมเมื่อเปลี่ยนไซซ์ | Browser Device Stage | บันทึก EP01 ระบุว่าช่อง screen slot ใช้วาง raster ได้ ควรถือกรอบนิ่งเพื่อให้เห็นคำถามต่อและคำตอบต่อเนื่อง |
| ให้เห็นคำขอกับผลเดินคนละทิศ | Hand-Drawn Flowchart (hw-pipeline) | ตัวอย่าง Catalog วาดเส้นไปข้างหน้า ส่วนเฟรม EP05 v2 ที่วินาที 10 และ 19 แสดงขาไปและกลับในแนวตั้งแล้ว ใช้เป็นเกณฑ์เทียบเมื่อลองเส้นทางในฉบับขยาย |
| ให้คนดูอ่านผลที่ระบบร้านคืน | ตาราง raster กับป้ายชี้แถว | เฟรม EP05 v2 ที่วินาที 16 อ่านแถว M = 3 ได้ที่ 360×640 ฉบับขยายต้องออกแบบแถวเสื้อดำ L = 0 เพิ่ม และให้ตัวเลขอ่านได้ด้วยตัวเอง |

หลักฐาน W1 รอบนี้มาจาก [บันทึก preview Catalog ของ EP01](../ep01-api-introduction/CATALOG.md) และ [เฟรม EP05 v2](preview-v2.jpg) ผลอ่านแถว L และจังหวะสลับแชทสองกรณียังต้องตรวจใน sample ฉบับขยาย

จังหวะ M เป็นรอบเต็ม แชทถาม → ส่งสีและไซซ์ → เห็นแถว M = 3 → เห็นผลกลับ → แชทตอบว่ามี 3 ตัว รอบ L เป็นคำถามต่อของคนเดิม เห็นคำถามใหม่ → แถว L = 0 → แชทตอบว่าหมด การเลือก component ที่ใช้จริงจะอิงหน้าที่ของแต่ละซีนเมื่อวางเรื่อง

## W3 · Use case ฉบับขยาย

**คำถามหลัก** ลูกค้าถามสต็อกในแชท ร้านจะให้ผู้ช่วยตอบจำนวนตามข้อมูลของร้านได้อย่างไร?

ผู้ชมคือเจ้าของร้านออนไลน์ที่ตอบคำถามเรื่องไซซ์และจำนวนบ่อย พื้นฐานที่ต้องรู้คือร้านมีข้อมูลสต็อกแยกตามรุ่น สี และไซซ์ คนดูควรจบคลิปแล้วรู้ว่าจะเตรียมข้อมูลอะไร เชื่อมเครื่องมือกับผู้ช่วยอย่างไรในภาพรวม และใช้คำถามสองแบบตรวจคำตอบได้อย่างไร

| ฝั่ง | หน้าที่ |
|---|---|
| ลูกค้าและแอปแชท | ลูกค้าพิมพ์คำถาม แอปส่งข้อความให้ผู้ช่วยและแสดงคำตอบในบทสนทนาเดิม |
| LangMind | ผู้ช่วยตีความรุ่น สี และไซซ์จากบทสนทนา เรียกเครื่องมือค้นสต็อกที่ร้านเชื่อมไว้ แล้วเรียบเรียงคำตอบจากผลที่ได้รับ |
| เครื่องมือและระบบร้าน | ใช้รหัสสินค้าหรือเงื่อนไขรุ่น สี และไซซ์ค้นรายการ ระบบร้านเก็บและคืนจำนวนคงเหลือ ผู้ดูแลร้านหรือทีมระบบเตรียมข้อมูลและตั้งค่าการเชื่อมต่อ |

ข้อมูลจำลองใช้เสื้อรุ่นเดียว สีดำ ไซซ์ M เหลือ 3 ตัว และไซซ์ L เหลือ 0 ตัว คำว่า “แล้วไซซ์ L ล่ะ?” สืบทอดรุ่นและสีจากคำถามก่อนหน้า ผล 0 หมายถึงค้นพบรายการและจำนวนเป็นศูนย์ ผลที่หาไม่เจอหรือระบบไม่ตอบเป็นอีกสถานะหนึ่ง แยกไว้นอกขอบเขตตัวอย่างนี้

หน้า [ฟีเจอร์ LangMind](https://langmind.in.th/features) ระบุว่าผู้ช่วยเรียกเครื่องมือ API ภายนอกระหว่างสนทนาได้และยกการเช็กสต็อกเป็นตัวอย่าง ส่วนจำนวนสินค้าและการตอบต่อเนื่องเป็นภาพจำลองเพื่ออธิบาย flow การเชื่อมต่อและพฤติกรรมกับระบบร้านจริงยังไม่ได้ทดสอบ

| เวลาคร่าว ๆ | ภาพ | เสียงบรรยาย | ข้อความเน้น |
|---|---|---|---|
| 0–10 วินาที | ลูกค้าถามในแชท | เปิดปัญหาที่ร้านเจอ | เสื้อสีดำ ไซซ์ M ยังมีไหม? |
| 10–28 วินาที | คำขอจาก LangMind ไปที่ระบบร้าน ไฮไลต์แถว M แล้วส่งผลกลับ | อธิบายบทบาทของเครื่องมือและแหล่งข้อมูล | สีดำ · M · 3 ตัว |
| 28–38 วินาที | แอปแสดงคำตอบในแชทเดิม | เชื่อมผลจากร้านกับคำตอบที่ลูกค้าเห็น | ไซซ์ M มี 3 ตัวค่ะ |
| 38–55 วินาที | คำถามต่อเรื่อง L ตามด้วยแถว L และคำตอบ | ย้ำว่าเป็นเสื้อสีดำตัวเดิมและเช็กใหม่ตามไซซ์ | L เหลือ 0 → ไซซ์ L หมดค่ะ |
| 55–75 วินาที | การ์ดเตรียมข้อมูล เชื่อมเครื่องมือ ทดลองถาม | บอกสิ่งที่เจ้าของร้านนำไปเริ่มทำได้ | เตรียม → เชื่อม → ลองถาม |
