# EP14 — Errors: อ่าน error ให้เป็น รับมือให้ถูก

อัปเดต 10 พฤศจิกายน 2026 (Asia/Bangkok) · v1 · **แยกจากหัวข้อ Rate Limit & Quota** ซึ่งไปอยู่ที่ [EP15](../ep15-rate-limit-quota/README.md) · เป้าความยาวไม่เกิน 3 นาที (draft ก่อนใส่เสียง 2:30)
ครอบคลุมหมวด Errors ในคู่มือครบ: error envelope + code ทั้ง 10 ตัว · ใช้ engine เดียวกับ EP12/EP13 · แถบความคืบหน้า **อ่าน → รับมือ → ใช้ผล**

## 1. โจทย์จากมุมคนดู (Audience & Purpose)
- **คนดู**: dev / ทีมที่ดูแลระบบหลังบ้านซึ่งเรียก LangMind API อยู่แล้ว (ต่อจาก EP04, EP12, EP13)
- **ปัญหา**: ระบบเรียก API แล้วพัง หน้าจอขึ้นแค่ “เกิดข้อผิดพลาด” ทีมไม่รู้ว่าพังเพราะอะไร ต้องแก้ตรงไหน หรือแค่รอแล้วลองใหม่
- **ดูจบแล้วต้องตอบได้**
  1. error ของ LangMind หน้าตาเดียวกันทุกตัว (`status`, `code`, `message`, `message_en`, `request_id`) และต้องเช็กที่ `code`
  2. code ทั่วไป 5 ตัว (401/403/404/422/429) และ code ของ Voice 5 ตัว แปลว่าอะไร แก้อย่างไร
  3. HTTP เดียวกันอาจคนละความหมาย (429 RATE_LIMIT_EXCEEDED ≠ 429 VOICE_QUOTA_EXCEEDED)
  4. แบ่งการรับมือเป็น 3 กลุ่ม: รอแล้วลองใหม่ · แก้คำขอก่อน · ตั้งค่าในเว็บ/ดูแพ็กเกจ
  5. เอาไปใช้ในระบบ: log status/code/request_id · ลองใหม่อัตโนมัติ · หน้าจอบอกทางแก้

## 2. Use case
ระบบหลังบ้านของร้านกาแฟ (ร้านเดียวกับ EP12/EP13) วันหนึ่งหน้ากล่องแชทขึ้น “เกิดข้อผิดพลาด” → ตอนจบทีมมีหน้า “บันทึก error” และหน้ากล่องแชทที่บอกทางแก้ (`403 FORBIDDEN` เพราะ Key ไม่มี `inbox:read`)

## 4. สิ่งที่ตัดออกไป EP15 และสิ่งที่คลิปไม่อ้าง
- **ย้ายไป EP15**: โควตาบัญชี, หน้า Credentials, ลิมิต Voice 60/300, หน่วยนับโควตาเสียง, `/me/voice-quota` แบบละเอียด, backoff, แนวทางใช้ Key อย่างปลอดภัย
- **คู่มือไม่ได้ระบุ**: header `Retry-After` / เวลารอหลัง 429 · การใช้ `request_id` ฝั่ง LangMind (คลิปแนะนำแค่เก็บใน log ของเรา) · แก้ scope ของ Key เดิมได้หรือไม่
- การแบ่ง 3 กลุ่มเป็นข้อสรุปของคลิป (ติดหมายเหตุบนจอ)
