## 1. คำถามและคำตอบของคลิป

- **ผู้ชม:** developer ที่รู้จักการเรียก API เบื้องต้นและกำลังทำหน้าจอแชต
- **คำถามหลัก:** ถ้าต้องการให้แอปทยอยแสดงคำตอบระหว่างรับข้อมูล ต้องเข้าใจ event แบบใด และแอปต้องทำอะไรเอง
- **คำตอบสั้น:** LangMind API ส่งข้อมูลแบบ SSE; Backend ของแอปเก็บ API key และอ่าน stream; UI เป็นส่วนที่แอปพัฒนาเพื่อเลือกวิธีแสดงผล
- **เหตุการณ์ตัวอย่าง:** ผู้ใช้ถามว่า “ช่วยแนะนำขั้นตอนเริ่มต้นให้หน่อย” ภาพและคำตอบบนจอเป็นภาพอธิบาย ไม่ใช่ผลเรียก API จริง

## 2. ขอบเขตและหลักฐาน

| ข้อความ | สถานะ | ขอบเขต |
|---|---|---|
| `POST /chat/message/blocking` ส่งคำตอบครบทั้งชุด | Documented | ใช้เปรียบเทียบรูปแบบรับผล |
| `POST /chat/message` ส่งข้อมูลด้วย Server-Sent Events (SSE) | Documented | ไม่เรียกว่า WebSocket และไม่รับประกันความเร็ว |
| ลำดับ event คือ `message_start → message → citations (ถ้ามี) → message_end` | Documented | อธิบายหน้าที่ของแต่ละ event ตาม API snapshot |
| `message_end` มีคำตอบฉบับเต็มและข้อมูล usage | Documented | ใช้ event นี้เป็นจุดที่ถือว่าคำตอบครบ |
| Backend เก็บ API key ส่งคำขอและอ่าน stream; UI จัดการสถานะและการแสดงผล | API integration responsibility | เป็น workflow ของแอป ไม่ใช่หน้าจอที่ API สร้างให้ |

| latency และเวลาเริ่มตอบ | Unknown | ไม่แสดงเป็นตัวเลขหรือคำรับประกัน |

## 3. บทพากย์และข้อความรายจังหวะ

### จังหวะ 1 — เริ่มจากคำถามเดียวกัน

- **ภาพ:** แชตจำลองแสดงคำถาม “ช่วยแนะนำขั้นตอนเริ่มต้นให้หน่อย” แล้วคงสถานะรอคำตอบ
- **เสียงพากย์:** ลองนึกถึงคนใช้แอปแชตแล้วถามว่า “ช่วยแนะนำขั้นตอนเริ่มต้นให้หน่อย” คำถามส่งไปแล้ว แต่หน้าจอยังรอคำตอบ
- **ข้อความเน้น:** คำถามถูกส่งแล้ว → กำลังรอคำตอบ
- **ป้าย:** `[ภาพจำลอง]`

### จังหวะ 2 — คำตอบแสดงได้สองจังหวะ

- **ภาพ:** คำถามเดียวกันอยู่เหนือภาพเปรียบเทียบ; ฝั่งหนึ่งเป็นชุดคำตอบที่รอจนครบ อีกฝั่งเป็นชิ้นข้อมูลสามชิ้นเรียงตามลำดับ
- **ภาพประกอบ:** `[ภาพอธิบาย]` `POST /chat/message/blocking` และ `POST /chat/message · SSE`; เป็นแผนภาพ ไม่ใช่ผลเรียกจริง
- **เสียงพากย์:** ถ้ารับแบบ blocking แอปจะรอผลลัพธ์ครบทั้งชุดก่อนนำไปแสดง ส่วน Streaming ส่ง event ผ่าน SSE มายัง Backend แล้วแอปจึงเลือกได้ว่าจะทยอยนำข้อความที่ได้รับไปแสดงอย่างไร
- **ซับร่างตามช่วงภาพ:** แบบรับครบ: รอคำตอบทั้งชุดก่อนแสดง / แบบ Streaming: รับข้อมูลเป็นลำดับ / แอปเลือกทยอยแสดงข้อความที่ได้รับ
- **หมายเหตุ:** ภาพนี้อธิบายรูปแบบการรับและการแสดงผล ไม่ได้สื่อว่าโมเดลตอบเร็วขึ้นหรือมีการรับประกันเวลา

### จังหวะ 3 — อ่าน event ที่จำเป็น

- **ภาพ:** การ์ด event เพิ่มตามลำดับ `message_start`, `message`, `citations (ถ้ามี)`, `message_end`
- **เสียงพากย์:** เริ่มด้วย `message_start` ซึ่งให้รหัสบทสนทนาและข้อความ จากนั้น `message` ส่งเนื้อหาคำตอบมาเป็นชิ้น ๆ อาจมี `citations` เป็นแหล่งอ้างอิง และ `message_end` ระบุคำตอบฉบับเต็มพร้อมข้อมูล usage
- **ข้อความเน้น:** `message` คือเนื้อหาที่ทยอยมา; `message_end` คือจุดที่คำตอบครบ
- **ซับร่าง:** `message_start: เริ่มต้นและให้รหัสบทสนทนา/ข้อความ` / `message: เนื้อหาคำตอบทยอยมาเป็นชิ้น (chunks)` / `citations: อาจมีแหล่งอ้างอิงประกอบ` / `message_end: คำตอบฉบับเต็มและข้อมูล usage`

### จังหวะ 4 — ใครส่ง ใครอ่าน ใครแสดง

- **ภาพ:** แยก LangMind API, App Backend และ Client UI; ลูกศรคำขอเดินทางไป API, SSE events กลับ Backend และข้อมูลที่แอปจัดการส่งต่อไป UI
- **เสียงพากย์:** Backend ของแอปเก็บ API key ส่งคำขอ และอ่าน stream แล้วส่งข้อมูลที่ UI ต้องใช้ต่อ ส่วน Client UI จัดการสถานะและเลือกวิธีแสดงผลเอง API ส่งข้อมูลกลับมา ไม่ได้สร้างหน้าจอให้
- **ข้อความเน้น:** API ส่งข้อมูล; แอปสร้างและจัดการหน้าจอ
- **ซับร่าง:** API ส่ง event กลับทาง SSE / Backend เก็บ key และอ่าน stream / UI แสดงผลตามที่แอปออกแบบ

### จังหวะ 5 — จำให้ได้สองจุด

- **ภาพ:** ทวนบทบาท Backend และ UI ก่อนปิดด้วย `message_end`
- **เสียงพากย์:** จำสองจุดไว้ Backend เก็บ key และอ่าน stream ส่วน UI เลือกแสดงข้อความตามที่แอปออกแบบ และถือว่าคำตอบครบเมื่อได้รับ `message_end`
- **ข้อความปิด:** Backend ส่งคำขอและอ่าน stream / UI เลือกวิธีแสดงข้อความ / คำตอบครบเมื่อได้รับ `message_end`

## 4. เสียงและซับ

- Animatic v3.1 ยาว 52 วินาที เป็นภาพเงียบและซับร่างภาษาไทยที่ค้างตาม visual stage; ยังไม่ sync กับเสียงพูด
- ยังไม่สร้างเสียงเต็มก่อนผู้ใช้เลือก voice audition; หลังเลือกเสียงให้ปรับบทและจังหวะซับตามเสียงจริง
- อธิบายศัพท์เมื่อใช้ครั้งแรก: SSE = Server-Sent Events, chunk = ชิ้นส่วนข้อความ, Backend = เซิร์ฟเวอร์ของแอป
- ไม่ให้อ่านชื่อ event ซ้ำทุกคำ; ให้เสียงเล่าเหตุผลและให้ป้ายบนจอช่วยระบุชื่อ
