## 2. โครงสร้างบทพากย์ ซับ และข้อความเน้น (Script Breakdown)

### ซีนที่ 1: ปัญหาของคนรอ (The Waiting Pain)
- **เป้าหมาย:** เชื่อมโยงความรู้สึกของผู้ใช้ เมื่อถามแชทบอทแล้วหน้าจอนิ่งค้างจนนึกว่าระบบพัง
- **ระยะเวลาร่าง:** ~15 วินาที

| เสียงพากย์ (Narration) | ซับไตเติล (Subtitles) | ข้อความเน้นบนจอ (On-Screen Text / Badges) |
|---|---|---|
| เคยเป็นไหมครับ? พิมพ์ถาม AI ไปแล้ว หน้าจอก็หมุนติ้วอยู่นิ่ง ๆ นานหลายวินาที จนเราเริ่มสงสัยว่าแอปค้าง หรือระบบล่มไปแล้วกันแน่ | เคยเป็นไหมครับ? พิมพ์ถาม AI ไปแล้ว หน้าจอก็หมุนติ้วอยู่นิ่ง ๆ | `Loading...` `(หน้าจอนิ่ง)` |
| ความจริงแล้วระบบไม่ได้ล่มครับ แต่เพราะการเรียก API แบบเดิม เซิร์ฟเวอร์ต้องรอให้ AI คิดคำตอบให้จบครบทั้งก้อนก่อน ถึงจะยอมส่งข้อมูลกลับมาให้เรา | แต่เป็นเพราะระบบแบบเดิม ต้องรอให้คิดคำตอบครบ 100% ถึงจะส่งกลับมาได้ | `Blocking API: รอจบก้อน` |

---

### ซีนที่ 2: เปลี่ยนมาใช้ Streaming API (The SSE Solution)
- **เป้าหมาย:** แนะนำ Endpoint `POST /chat/message` และให้เห็นความต่างของการพิมพ์ทีละคำ
- **ระยะเวลาร่าง:** ~20 วินาที

| เสียงพากย์ (Narration) | ซับไตเติล (Subtitles) | ข้อความเน้นบนจอ (On-Screen Text / Badges) |
|---|---|---|
| เพื่อแก้ปัญหานี้ LangMind มีทางออกที่ดีกว่า ด้วย Streaming API ผ่าน Endpoint chat/message ครับ | LangMind มีทางออกที่ดีกว่า ด้วย Streaming API ผ่าน chat/message | `POST /chat/message` `(Server-Sent Events)` |
| แทนที่จะต้องรอจนจบ ทันทีที่ AI เริ่มคิดคำแรกออก ข้อมูลจะเริ่มทยอยส่งมาที่หน้าจอแอปของเราทันที เหมือนมีคนกำลังนั่งพิมพ์ตอบให้เราอ่านแบบสด ๆ เลยครับ | ทันทีที่คิดคำแรกออก ข้อมูลจะเริ่มทยอยส่งมาบนหน้าจอทันที | `Real-time Streaming` `พิมพ์ตอบทันที` |

---

### ซีนที่ 3: กลไกเบื้องหลัง 3 Event สำคัญ (Event Stream Anatomy)
- **เป้าหมาย:** อธิบายลำดับของ Event SSE จาก LangMind API เพื่อให้ Dev นำไปเขียนดักฟังได้ถูก
- **ระยะเวลาร่าง:** ~25 วินาที

| เสียงพากย์ (Narration) | ซับไตเติล (Subtitles) | ข้อความเน้นบนจอ (On-Screen Text / Badges) |
|---|---|---|
| เบื้องหลังการทำงานนี้ ใช้เทคโนโลยี Server-Sent Events ส่งข้อมูลผ่านท่อเดียว มาเป็น 3 จังหวะสำคัญ | เบื้องหลังใช้ Server-Sent Events ส่งข้อมูลผ่านท่อเดียวเป็น 3 จังหวะ | `Event Stream (SSE)` |
| เริ่มจาก message_start ยืนยันว่าเริ่มคุย พร้อมส่งไอดีบทสนทนามาให้ ต่อด้วย message ส่งก้อนข้อความคำตอบย่อย ๆ วิ่งเข้ามาทีละท่อน | เริ่มจาก message_start ส่งไอดี ตามด้วย message ทยอยส่งชิ้นส่วนคำตอบ | `1. message_start` `2. message (chunks)` |
| และปิดท้ายด้วย message_end ที่ส่งคำตอบฉบับเต็มและจำนวน Token สรุปมาให้เพื่อบอกว่า คำตอบสมบูรณ์แล้ว | และจบด้วย message_end ที่ส่งคำตอบฉบับเต็มและสรุปจำนวน Token | `3. message_end` `(Terminal Event)` |

### ซีนที่ 4: สิ่งที่ Developer ต้องเขียนเพิ่ม (Developer Implementation)
- **เป้าหมาย:** อธิบายหน้าที่ของแอปพลิเคชัน ไม่ให้เข้าใจผิดว่า API จัดการหน้าบ้านให้เอง
- **ระยะเวลาร่าง:** ~20 วินาที

| เสียงพากย์ (Narration) | ซับไตเติล (Subtitles) | ข้อความเน้นบนจอ (On-Screen Text / Badges) |
|---|---|---|
| ในฝั่งแอปพลิเคชันของคุณ สิ่งที่ต้องทำเพิ่มก็แค่เปิดตัวรับสตรีม และนำชิ้นส่วนข้อความที่เข้ามา ไปทยอยต่อกันบนหน้าจอ | ฝั่งแอปพลิเคชัน แค่เปิดตัวรับสตรีม และนำชิ้นส่วนข้อความไปทยอยต่อบน UI | `SSE Client / Stream Reader` `String Buffer ➜ UI State` |
| ผู้ใช้ก็จะได้ประสบการณ์การใช้งานที่ลื่นไหล ตอบสนองทันใจ ไม่ต้องทนรอหน้าจอว่างเปล่าอีกต่อไปครับ | ผู้ใช้ก็จะได้ประสบการณ์ที่ลื่นไหล ตอบสนองทันใจ ไม่ต้องรอหน้าจอค้าง | `Fast UX · Low Perceived Latency` |

- **ระยะเวลาร่าง:** ~15 วินาที

| เสียงพากย์ (Narration) | ซับไตเติล (Subtitles) | ข้อความเน้นบนจอ (On-Screen Text / Badges) |
