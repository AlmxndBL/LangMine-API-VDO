## 2. โครงสร้างบทพากย์ ซับ และข้อความเน้น (Script Breakdown)

### ซีนที่ 1: อาการรอคำตอบ (Beat 1: Waiting State)
- **เป้าหมาย:** ตั้งคำถามจากประสบการณ์ของผู้ใช้เมื่อส่งคำขอแล้วหน้าจอยังไม่มีคำตอบปรากฏ
- **แนวทางภาพ:** หน้าจอแชทจำลองที่อยู่ระหว่างรอคำตอบ ไม่มีตัวเลขเวลานับถอยหลัง มีป้าย "ภาพจำลอง"

| เสียงพากย์ (Narration) | ซับไตเติล (Subtitles) | ข้อความเน้นบนจอ (On-Screen Badges) |
|---|---|---|
| เวลาที่เราส่งคำถามไปยังผู้ช่วย AI ในแอปพลิเคชัน บ่อยครั้งที่หน้าจอจะแสดงสถานะกำลังรอคำตอบอยู่ช่วงหนึ่ง ก่อนที่ข้อความทั้งหมดจะปรากฏขึ้นมาพร้อมกัน | เมื่อส่งคำถามไป หน้าจอมักจะอยู่ในสถานะรอคำตอบสักครู่ | `[ภาพจำลอง]` `สถานะ: กำลังรอการตอบกลับ` |
| นั่นเป็นเพราะการส่งคำขอในรูปแบบทั่วไป ระบบจะรอให้ได้คำตอบที่สมบูรณ์ครบทั้งชุดจากเซิร์ฟเวอร์ก่อน จึงจะเริ่มส่งข้อมูลกลับมาแสดงผล | เพราะรูปแบบทั่วไป จะรอให้ได้ผลลัพธ์ครบทั้งชุดก่อนแสดงผล | `รูปแบบ: รับผลครบก่อนแสดง` |

---

### ซีนที่ 2: สองรูปแบบการส่งข้อมูล (Beat 2: Blocking vs Streaming)
- **เป้าหมาย:** อธิบายความแตกต่างระหว่างการรอรับผลครบ กับการทยอยรับและแสดงผล โดยไม่เรียกแบบใดว่าเก่าหรือรับประกันความเร็ว
- **แนวทางภาพ:** แสดงภาพเปรียบเทียบสองรูปแบบ ไม่ใช้คำว่า "ทันที" หรือ "ทันใจ"

| เสียงพากย์ (Narration) | ซับไตเติล (Subtitles) | ข้อความเน้นบนจอ (On-Screen Badges) |
|---|---|---|
| ใน LangMind API มีทางเลือกการเชื่อมต่อสองรูปแบบหลัก รูปแบบแรกคือการรับผลครบก่อนแสดง และอีกรูปแบบหนึ่งคือการใช้ Streaming API ผ่าน Endpoint chat/message | LangMind API มีทางเลือกทั้งแบบรับผลครบ และแบบ Streaming ผ่าน chat/message | `POST /chat/message` `Server-Sent Events` |
| เมื่อใช้ Streaming ระบบจะเริ่มทยอยส่งชิ้นส่วนข้อความออกมาเป็นระยะ ทำให้ฝั่งแอปพลิเคชันสามารถนำข้อมูลที่เริ่มได้รับไปทยอยแสดงผลบนหน้าจอได้ | ระบบจะทยอยส่งข้อมูลออกมาเป็นระยะ ให้แอปนำไปทยอยแสดงผลได้ | `รูปแบบ: ทยอยรับและแสดง` `(ทยอยส่งตามชุดข้อมูล)` |

---

### ซีนที่ 3: ลำดับ Event ในท่อ SSE (Beat 3: Event Stream Flow)
- **เป้าหมาย:** อธิบายลำดับของ Event ตาม snapshot ให้ถูกต้อง ครบถ้วน รวมถึง citations และ terminal event
- **แนวทางภาพ:** แผนภาพแสดงข้อมูลไหลจาก API ➜ Server ของแอป ➜ Client ตามลำดับ

| เสียงพากย์ (Narration) | ซับไตเติล (Subtitles) | ข้อความเน้นบนจอ (On-Screen Badges) |
|---|---|---|
| ข้อมูลที่สตรีมผ่าน Server-Sent Events จะส่งมาเป็นชุดเหตุการณ์ตามลำดับ เริ่มจาก message_start ซึ่งส่งรหัสบทสนทนาและข้อความมาเพื่อยืนยันการเริ่มต้น | ข้อมูลสตรีมส่งมาเป็นลำดับ เริ่มจาก message_start ยืนยันการเริ่มบทสนทนา | `1. message_start` `(Conversation & Message ID)` |
| จากนั้นตามด้วย event ชนิด message ซึ่งจะทยอยส่งชิ้นส่วนข้อความหรือ chunk เข้ามา และอาจมี event citations ส่งมาประกอบหากมีการอ้างอิงเอกสาร | ตามด้วย message ที่ทยอยส่ง chunk และอาจมี citations ประกอบ | `2. message (Chunks)` `(citations: แหล่งอ้างอิง ถ้ามี)` |
| และสำคัญที่สุดคือ event สุดท้าย message_end ที่จะส่งคำตอบฉบับสมบูรณ์พร้อมสรุปจำนวน Token มาให้ ซึ่งเราต้องรอจนได้รับ event นี้ จึงจะถือว่าคำตอบสมบูรณ์แล้ว | ปิดท้ายด้วย message_end ที่ส่งคำตอบฉบับเต็มและสรุป Token | `3. message_end (Terminal Event)` `คำตอบสมบูรณ์เมื่อได้ event นี้` |

---

### ซีนที่ 4: หน้าที่ของ Developer และระบบฝั่งแอป (Beat 4: Developer Responsibilities)
- **เป้าหมาย:** อธิบายสถาปัตยกรรมที่ถูกต้อง: Backend ถือ Key, Parse stream, แล้วส่งให้ UI; API ไม่ได้ทำ UI ให้
- **แนวทางภาพ:** แผนภาพ Backend ของแอปที่มีกุญแจ API Key และตัวอ่าน Stream

| เสียงพากย์ (Narration) | ซับไตเติล (Subtitles) | ข้อความเน้นบนจอ (On-Screen Badges) |
|---|---|---|
| ในฝั่งการพัฒนา สิ่งสำคัญคือเราต้องเก็บ API Key ไว้ที่ฝั่งเซิร์ฟเวอร์หรือ Backend ของแอปเราเสมอ ห้ามใส่ไว้ในโค้ดฝั่งหน้าบ้านหรือเบราว์เซอร์เด็ดขาด | ต้องเก็บ API Key ไว้ที่เซิร์ฟเวอร์ฝั่งแอปเสมอ ห้ามใส่ในเบราว์เซอร์ | `Security: เก็บ API Key ที่ Server` `ห้ามเปิดเผย Key ใน Client` |
| Backend ของเราจะทำหน้าที่รับและอ่าน Event Stream จาก LangMind แปลงข้อมูล และส่งเฉพาะข้อความที่ต้องการไปยังหน้าบ้าน เพื่อนำไปจัดการสถานะและแสดงผลต่อไป | Backend รับและ parse stream แล้วส่งต่อข้อมูลให้หน้าบ้านไปแสดงผล | `Backend: Parse Stream` `Client UI: Update State` |

---

### ซีนที่ 5: สรุปและการนำไปใช้ (Beat 5: Summary)
- **เป้าหมาย:** สรุปย้อน flow จากคำขอจนถึง terminal event และข้อควรระวัง
- **แนวทางภาพ:** แผนภาพสรุป flow แบบกระชับ โลโก้ LangMind และตัวละครหุ่นยนต์

| เสียงพากย์ (Narration) | ซับไตเติล (Subtitles) | ข้อความเน้นบนจอ (On-Screen Badges) |
|---|---|---|
| สรุปก็คือ การใช้งาน Streaming ช่วยให้เรานำข้อความที่ทยอยได้รับไปแสดงผลได้ โดยเริ่มส่งคำขอจาก Backend รับชิ้นส่วนข้อความ และสิ้นสุดเมื่อได้รับ message_end | การสตรีมช่วยให้ทยอยแสดงผลได้ โดยรับข้อมูลจาก Backend จนถึง message_end | `สรุป Flow: Request ➜ Stream ➜ message_end` |
| ลองนำรูปแบบการรับส่งข้อมูลนี้ไปออกแบบระบบแชทในแอปของคุณดูนะครับ แล้วพบกันใหม่ในตอนต่อไป สวัสดีครับ | นำรูปแบบการรับข้อมูลนี้ไปออกแบบแอปของคุณดูนะครับ สวัสดีครับ | `LangMind API` `https://langmind.in.th` |

## 3. สถิติบทและการควบคุมความถูกต้อง
- **จำนวนคำบรรยายภาษาไทย:** ประมาณ 290 คำ (ความยาวกำลังพอดีสำหรับการอ่านชัดถ้อยชัดคำ)
- **ศัพท์เทคนิคและการออกเสียง:**
  - `LangMind` (แลง-มายด์)
  - `Streaming API` (สตรีม-มิ่ง เอ-พี-ไอ)
  - `Server-Sent Events` หรือ `SSE` (เซิร์ฟ-เวอร์-เซนต์-อี-เวนต์ส / เอส-เอส-อี)
  - `message_start` (เมส-เซจ-สตาร์ต)
  - `message` (เมส-เซจ)
  - `citations` (ไซ-เท-ชันส์)
  - `message_end` (เมส-เซจ-เอ็นด์)
  - `chunk` (ชังก์ / ชิ้นส่วนข้อความ)
  - `terminal event` (เทอร์-มินอล-อี-เวนต์ / เหตุการณ์สิ้นสุด)
