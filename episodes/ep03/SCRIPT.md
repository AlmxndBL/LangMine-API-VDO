# บทพากย์และข้อความ — EP03 ฉบับปรับให้อธิบายง่าย

Episode ID: ep03-streaming-chat  
Revision: ปรับหลังทบทวน animatic v2 วันที่ 8 พฤศจิกายน 2026  
สถานะ: ร่างเนื้อหา; เสียงพากย์ยังรอผู้ใช้เลือก voice audition

## 1. คำถามและคำตอบที่คลิปสัญญาไว้

- **ผู้ชม:** developer ที่กำลังทำหน้าจอแชตและรู้จักการเรียก API เบื้องต้น
- **คำถามหลัก:** ถ้าอยากให้แอปทยอยแสดงข้อความระหว่างรับคำตอบ ต้องเข้าใจอะไร และแอปต้องทำส่วนไหนเอง
- **คำตอบสั้น:** LangMind API ส่ง SSE events; Backend ของแอปเก็บ API key และอ่าน stream; UI เป็นส่วนที่แอปพัฒนาเพื่อเลือกวิธีแสดงผล
- **ตัวอย่างเดียวตลอดคลิป:** ผู้ใช้ถามว่า “ช่วยแนะนำขั้นตอนเริ่มต้นให้หน่อย” ภาพและคำตอบในแชตเป็นภาพจำลอง ไม่ใช่ผลเรียก API จริง

## 2. ขอบเขตและหลักฐาน

| ข้อความ | สถานะ | ขอบเขต |
|---|---|---|
| **POST /chat/message/blocking** ส่งผลเมื่อได้คำตอบครบทั้งชุด | Documented | ใช้เป็นด้านเปรียบเทียบตาม API snapshot |
| **POST /chat/message** ส่งข้อมูลแบบ Server-Sent Events (SSE) | Documented | ไม่เรียกว่า WebSocket และไม่รับประกันความเร็ว |
| ลำดับ event คือ **message_start → message → citations (ถ้ามี) → message_end** | Documented | message_start ให้ conversation/message ID; message ให้ answer chunks; message_end ให้ answer ฉบับเต็มและ usage |
| ต้องได้รับ **message_end** จึงถือว่าคำตอบสมบูรณ์ | Documented | ถ้าไม่มี terminal event ห้ามสรุปว่าคำตอบครบ |
| Backend เก็บ API key และอ่าน/parse stream; UI จัดการการแสดงผล | Documented / app responsibility | API ส่งข้อมูล ไม่ได้สร้างหน้าจอให้ |
| คำถามและแผนภาพการแสดงผล | Illustrative | ใส่ป้ายภาพจำลองให้เห็นชัด ไม่ใช้เป็นคำตอบจริงจาก LangMind |
| latency, เวลาเริ่มตอบ และความเร็ว | Unknown | ไม่ใส่ตัวเลขหรือคำรับประกัน |

## 3. บทและข้อความรายจังหวะ

### จังหวะ 1 — คำถามเดียว

- **ภาพ:** แชตตัวอย่างแสดงคำถาม “ช่วยแนะนำขั้นตอนเริ่มต้นให้หน่อย” และสถานะกำลังรอ
- **เสียงพากย์:** ลองนึกถึงคนใช้แอปแชตแล้วถามว่า “ช่วยแนะนำขั้นตอนเริ่มต้นให้หน่อย” คำถามส่งไปแล้ว แต่คำตอบยังไม่แสดง หน้าจอจึงอยู่ในสถานะรอ
- **ข้อความเน้น:** **คำถามถูกส่งแล้ว** → **กำลังรอคำตอบ**
- **ป้ายภาพ:** **[ภาพจำลอง]**

### จังหวะ 2 — คำตอบแสดงคนละแบบ

- **ภาพ:** วางคำถามเดียวกันเหนือสองภาพอธิบาย ฝั่งหนึ่งซ่อนคำตอบไว้จนได้รับครบ อีกฝั่งค่อยเผยข้อความเป็นชิ้น
- **เสียงพากย์:** ถ้าใช้แบบรับผลครบ แอปจะแสดงคำตอบหลังได้รับทั้งชุด ส่วน Streaming ที่ **POST /chat/message** ใช้ SSE ส่ง event ให้ Backend เป็นลำดับ จากนั้นแอปจึงเลือกนำข้อความที่ได้รับไปทยอยแสดงได้
- **ซับร่าง:** **รับครบก่อนแสดง** / **ทยอยแสดงข้อความที่ได้รับ**
- **ข้อความกำกับ:** **POST /chat/message/blocking** เทียบกับ **POST /chat/message · SSE**
- **หมายเหตุ:** ภาพอธิบายวิธีรับและแสดงผล ไม่ได้บอกว่าโมเดลคิดเร็วขึ้นหรือรับประกันเวลา

### จังหวะ 3 — อ่าน event ที่จำเป็น

- **ภาพ:** เพิ่ม event ทีละใบตามลำดับ พร้อมคำแปลสั้น ๆ
- **เสียงพากย์:** จำลำดับนี้ไว้ เริ่มจาก **message_start** ที่ให้รหัสบทสนทนาและข้อความ ตามด้วย **message** ที่ส่งเนื้อหาเป็นชิ้น ๆ อาจมี **citations** เป็นแหล่งอ้างอิง และปิดท้ายด้วย **message_end** ที่มีคำตอบฉบับเต็มกับ usage
- **ซับร่าง:** **message คือชิ้นส่วนข้อความ** / **message_end คือสัญญาณว่าคำตอบครบ**
- **ข้อความกำกับ:** **citations — ถ้ามี** และ **ครบเมื่อได้รับ message_end**

### จังหวะ 4 — ใครทำอะไร

- **ภาพ:** เส้นทางสามส่วน LangMind API → App Backend → Client UI; แยกข้อมูลไหลจาก API กับข้อมูลที่ Backend ส่งต่อให้ UI
- **เสียงพากย์:** Backend ของแอปเป็นผู้เก็บ API key ส่งคำขอ และอ่านหรือ parse event stream แล้วส่งข้อมูลที่แอปต้องใช้ให้ UI ส่วน UI จัดการสถานะและเลือกวิธีแสดงผลเอง LangMind API ส่งข้อมูล ไม่ได้สร้างหน้าจอให้
- **ซับร่าง:** **API ส่ง event** / **Backend เก็บ key และอ่าน stream** / **UI แสดงผลตามที่แอปกำหนด**

### จังหวะ 5 — สรุปจากคำถามเดิม

- **ภาพ:** ย้อนเส้นทางของคำถามเดิมเป็นสามขั้น: Backend ส่งคำขอ → UI ทยอยแสดง chunks → คำตอบครบเมื่อ **message_end**
- **เสียงพากย์:** สรุปให้จำสองเรื่อง Backend เก็บ key และอ่าน stream; ส่วน UI เลือกนำ chunks ไปแสดงตามที่แอปออกแบบไว้ และถือว่าคำตอบสมบูรณ์เมื่อได้รับ **message_end**
- **ข้อความปิด:** **ทยอยแสดงได้** / **คำตอบครบเมื่อได้ message_end**

## 4. แนวทางเสียงและซับ

- บทนี้เป็นข้อความร่างสำหรับ voice audition; ยังไม่สร้างเสียงเต็มก่อนผู้ใช้เลือกเสียง
- animatic v3 มีซับร่างภาษาไทยฝังในภาพ แบ่งตาม visual stage เพื่อให้เห็นสาระระหว่างทบทวนเนื้อหา; เวลาค้างของแต่ละซับยังเป็นช่วงภาพ ไม่ใช่ timing ตามเสียง
- หลังเลือกเสียง ให้ปรับถ้อยคำและจังหวะขึ้น/ลงของซับตามเสียงจริง ไม่ยึดเวลา 52 วินาทีเป็นความยาวสุดท้าย
- อธิบายศัพท์เมื่อเจอครั้งแรก: SSE = Server-Sent Events, chunk = ชิ้นส่วนข้อความ, Backend = เซิร์ฟเวอร์ของแอป
- ไม่ให้เสียงอ่านชื่อ event ซ้ำกับซับทุกคำ; ให้เสียงเชื่อมเหตุผล ส่วนชื่อ event อยู่ใกล้ภาพที่กำลังอธิบาย
