# Storyboard — EP03 v3.1

Episode ID: `ep03-streaming-chat`<br>
Revision: 9 พฤศจิกายน 2026 — เพิ่มภาพอธิบายและ motion ของ HyperFrames Catalog ในซีนเปรียบเทียบ<br>
สถานะ: storyboard/animatic ฉบับปรับ; ยังไม่ใช่การตรวจรับจากผู้ใช้

## 1. เป้าหมายการเล่า

Animatic v3.1 ยังคงใช้คำถามเดียวและลำดับเหตุการณ์เดิม แต่ปรับซีน 2 จากการ์ดข้อความสองชุดให้มีภาพอธิบายที่เห็นความต่างได้ก่อนอ่านศัพท์: เอกสารที่รอเป็นชุดหนึ่งภาพ เทียบกับเนื้อหาที่ทยอยมาสามชิ้น ภาพเป็นภาพจำลอง ไม่มีคำตอบจริง ตัวเลขเวลา หรือข้อมูล provider

- ใจความหลักหนึ่งข้อต่อจังหวะ
- คำถามเดิมพาเรื่องตั้งแต่ต้นจนจบ
- ภาษาไทยบอกหน้าที่; endpoint และชื่อ event เป็นป้ายประกอบ
- แยกสิ่งที่ API ส่งออกจากส่วนที่แอปพัฒนาเอง
- ความยาว 52 วินาทีเป็น story hold สำหรับ animatic เงียบ ไม่ใช่ final timing

## 2. ลำดับเหตุและผล

| จังหวะ | ภาพหลัก | ใจความ |
|---|---|---|
| 1. คำถาม | คำถามในแชตและสถานะรอ | ผู้ใช้ส่งคำถามแล้ว แต่ยังไม่เห็นคำตอบ |
| 2. เปรียบเทียบ | ชุดคำตอบครบฝั่งหนึ่ง; ชิ้นข้อมูลเรียงลำดับอีกฝั่ง | รูปแบบรับข้อมูลต่างกัน; แอปเลือกวิธีแสดง |
| 3. Events | การ์ด event เพิ่มตามลำดับ | `message` มีเนื้อหาที่ทยอยมา; `message_end` ใช้ยืนยันว่าครบ |
| 4. หน้าที่ | LangMind API → App Backend → Client UI | Backend อ่าน stream; UI เลือกวิธีแสดงผล |
| 5. สรุป | Backend, UI และ `message_end` | จำหน้าที่แอปและจุดที่คำตอบครบ |

## 3. Storyboard รายซีน

### ซีน 1 — คำถามเดียวกัน (8 วินาที)

- **เป้าหมาย:** เริ่มจากเหตุการณ์ที่คุ้นเคย
- **ภาพ:** crop จาก `assets/ui/scr-01-chat-loading.png` เฉพาะส่วน header คำถาม และสถานะรอ; ป้าย `[ภาพจำลอง]` แยกจาก raster
- **องค์ประกอบ:** Robot จาก shared assets เป็นตัวประกอบ ไม่บังคำถาม; ใช้ alpha เดิมและไม่ใส่กรอบขาว
- **ข้อความ:** คำถามถูกส่งแล้ว → กำลังรอคำตอบ
- **การเปลี่ยน:** คงคำถามไว้ แล้วเปลี่ยนแถบซับตามช่วงภาพ

### ซีน 2 — คำตอบแสดงได้สองจังหวะ (11 วินาที)

- **เป้าหมาย:** ให้เห็นรูปแบบก่อนเจอคำว่า SSE
- **หน้าจอหลัก:** คำถามเดียวกันเป็นหัวร่วมเหนือกรอบเปรียบเทียบภาพเดียว แบ่งซ้าย–ขวาด้วยเส้น divider
- **ฝั่งรับครบ:** raster `assets/illustrations/v3.1/batch-complete.png`; กองเอกสารลงท้ายด้วยเอกสารพร้อมเครื่องหมายถูก; ป้าย `รับคำตอบครบ`; endpoint `POST /chat/message/blocking`
- **ฝั่ง Streaming:** raster `assets/illustrations/v3.1/stream-chunks.png`; กล่องข้อมูล 1 → 2 → 3 เชื่อมด้วยลูกศร; ป้าย `ทยอยแสดง`; endpoint `POST /chat/message · SSE`
- **ข้อความกำกับ:** `ภาพอธิบาย · ไม่ใช่ผลเรียก API จริง`
- **ซับร่างตามเวลา:** 0–3.66 วินาที `แบบรับครบ: รอคำตอบทั้งชุดก่อนแสดง`; 3.66–7.33 วินาที `แบบ Streaming: รับข้อมูลเป็นลำดับ`; 7.33–11 วินาที `แอปเลือกทยอยแสดงข้อความที่ได้รับ`
- **ตำแหน่ง/ขนาด:** master 1080×1920; panel x=50, y=420, w=980, h=820; raster 980×800 แสดงแบบ contain และจัดกึ่งกลาง จึงคงสัดส่วนและไม่ครอป
- **คงเดิม:** คำถามตัวอย่างและความแตกต่างระหว่างรับครบกับ Streaming
- **เปลี่ยนจาก v3:** ใช้ภาพอธิบายที่สร้างจริง 2 ไฟล์และ motion wipe; ไม่ใช้แผงการ์ดข้อความสองก้อนเป็นภาพหลัก

### ซีน 3 — ลำดับ event (13 วินาที)

- **เป้าหมาย:** ทำให้ชื่อ event มีความหมายและย้ำ terminal event
- **องค์ประกอบ:** การ์ดเรียงแนวตั้ง; เผยทีละใบ; `citations` ใช้เส้นประและระบุว่าอาจมี
- **ข้อความ:** `message_start` = เริ่มและให้รหัสบทสนทนา/ข้อความ; `message` = เนื้อหาที่ทยอยมาเป็นชิ้น (`chunks`); `citations` = อาจมีแหล่งอ้างอิง; `message_end` = คำตอบฉบับเต็มและข้อมูล `usage`
- **การเปลี่ยน:** ไฮไลต์ `message_end` เมื่อเผยครบ; ไม่ใช้ข้อความที่ดูเหมือนคำตอบจริง

### ซีน 4 — ใครส่ง ใครอ่าน ใครแสดง (12 วินาที)

- **องค์ประกอบ:** LangMind API, App Backend และ Client UI แยกเป็นสามกล่อง
- **ลูกศร:** Backend → API เป็นคำขอ; API → Backend เป็น SSE events; Backend → UI เป็นข้อมูลที่แอปส่งต่อ
- **ข้อความ:** Backend เก็บ API key และอ่าน stream; UI จัดการสถานะและแสดงผล
- **ข้อจำกัด:** ไม่สื่อว่า LangMind API สร้างหน้าจอให้

### ซีน 5 — จำสองจุด (8 วินาที)

- **ภาพ:** สรุป Backend → UI → `message_end`; ใช้โลโก้และ Robot จาก shared assets โดยไม่แก้ source
- **ข้อความปิด:** Backend ส่งคำขอและอ่าน stream; UI เลือกวิธีแสดง; คำตอบครบเมื่อได้รับ `message_end`

## 4. HyperFrames Catalog ที่เลือก

เลือกหลังเปิดดู preview ของ Catalog แล้ว และปรับเข้ากับจังหวะของคลิป ไม่ได้เพิ่มเพียงเพราะมีอยู่ใน registry

| รายการ | ชนิดและหน้าที่ใน preview | การใช้ใน v3.1 | ข้อจำกัด/สถานะ |
|---|---|---|---|
| [Before After Wipe](https://hyperframes.heygen.com/catalog/components/before-after-wipe) | Component; สอง content slots; ภาพ before คงเป็นฐาน ส่วน after เปิดจากซ้ายและหยุดที่สัดส่วนที่กำหนด โดย preview ใช้ divider ค้างหลัง wipe | ใช้เทียบ raster สองภาพที่ 50%; เริ่มที่ 0.25s, เคลื่อน 1.05s, มี stage settle 0.32s; คงภาพไว้ตลอดซีน | เหมาะกับการเปรียบเทียบภาพนิ่ง; ไม่ได้แสดง stream จาก API จริง; source ปรับให้ใช้ assets/GSAP ในเครื่อง |
| [Soft Blur In](https://hyperframes.heygen.com/catalog/components/soft-blur-in) | Component; เผย element ด้วย opacity, blur และการเลื่อนขึ้น; ค่าเริ่มต้น 28px/18px และ 0.8s `power3.out` | ใช้กับหัวข้อทั้งคำ/ทั้งบรรทัด ไม่แยก animation ตามตัวอักษร | ใช้กับหัวข้อเดียวเพื่อลดการเคลื่อนไหว; source snippet อยู่ใน compositions/components/ และ timeline ถูกประกอบใน build.mjs |

**หลักฐานและการปรับ source:** preview ของทั้งสองรายการถูกเปิดและดูจริง; source ทางการระบุไว้ใน header ของไฟล์ component. ปรับ HTML/CSS ให้ใช้ภาพอธิบาย local และ GSAP ที่มากับโปรเจกต์ ไม่โหลด CDN. `hyperframes lint` ผ่านโดยไม่มี error; runtime check เปิด browser URL localhost ไม่ได้ใน environment นี้ จึงไม่ถือว่า component ผ่าน runtime ของ HyperFrames

## 5. ซับและ motion

- ซับร่างอยู่ในแถบกลางช่วงล่าง x=72–1008, y=1560–1792; Sarabun Bold สีขาวบนพื้นกรม; ข้อความหนึ่งใจความต่อ visual stage
- ซับค้างตามเวลาของ stage เพื่อทบทวนเนื้อหา; ยังไม่ sync กับเสียง
- ซีน 2 ใช้ wipe ตาม Catalog และเปิดหัวข้อด้วย Soft Blur In; ไม่ animate สระหรือวรรณยุกต์แยกตัว
- event cards ในซีน 3 เพิ่มทีละใบ; citations เป็นรายการที่อาจไม่มี
- ไม่มีตัวเลข latency, เวลาเริ่มตอบ หรือคำรับประกันความเร็ว
- เสียงพากย์ยังรอ voice audition; หลังเลือกเสียงจึง retime และปรับซับตามเสียงจริง
