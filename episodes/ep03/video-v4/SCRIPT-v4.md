# EP03 v4 — บทพากย์และข้อความบนจอ

สถานะ: บทร่างสำหรับทดลองอ่าน; ยังไม่ใช่บทเสียงที่จับเวลาแล้ว  
แกนเรื่อง: ผู้ใช้ขอให้ Agent ร่างข้อความแจ้งเลื่อนประชุม แล้วถามต่อให้สั้นลง  
ผู้ชม: เริ่มด้วยมุมผู้ใช้ทั่วไป แล้วต่อไปถึง developer ที่ต้องการเชื่อม Chat API

## หลักการอ่านและป้ายหลักฐาน

- บทสนทนาและข้อความตอบทั้งหมดเป็น **ภาพตัวอย่างจำลอง** ไม่ใช่ผลจากการเรียก API และไม่ใช่หน้าจอทางการของ LangMind
- ใช้คำว่า “ผู้ช่วย/Agent” อธิบายประสบการณ์ผู้ใช้ ไม่อ้างว่า Agent ทุกตัวตั้งค่าหรือให้คำตอบเหมือนตัวอย่าง
- สคริปต์ code เป็น `curl` ใน Bash และเรียกจากเครื่อง/สภาพแวดล้อมฝั่ง server; `LM_TOKEN` เป็น secret placeholder
- ยังไม่ใส่เวลาต่อ beat เพราะต้องอ่านบทต่อเนื่องและจับ timing จากเสียงจริงก่อน

## บทตามลำดับ beat

### B1 — คำถามที่คนคุ้นเคย

**พากย์:** เคยขอให้ผู้ช่วยช่วยเขียนข้อความ แล้วอยากให้แก้ต่ออีกนิดไหม? คลิปนี้จะพาจากคำถามแรก ไปจนถึงการถามต่อในบทสนทนาเดิม

**ข้อความเน้น:** `ขอร่างข้อความ` → `ขอแก้ต่อ`

**ซับ:** ใช้ตามบทพากย์จริงหลังบันทึกเสียง ไม่แยกเสียงเป็นรายบรรทัดซับ

### B2 — แชทจากมุมผู้ใช้ทั่วไป

**พากย์:** ในแชท ผู้ใช้พิมพ์สิ่งที่อยากให้ Agent ช่วย แล้วอ่านคำตอบ ตัวอย่างนี้เป็นภาพจำลองเพื่ออธิบายแนวคิด ไม่ใช่หน้าจอจริงหรือคำตอบจาก API

**ภาพจำลองบทสนทนา:**

- ผู้ใช้: `ช่วยร่างข้อความแจ้งทีมว่าเลื่อนประชุมเป็น 15:00 น. ให้สุภาพ`
- Agent: `ขอแจ้งเลื่อนประชุมเป็นเวลา 15:00 น. ขอบคุณครับ`
- ป้ายคงที่: `ภาพจำลอง`

### B3 — ถามต่อในเรื่องเดิม

**พากย์:** ถ้าอยากปรับคำตอบ ก็พิมพ์ถามต่อได้ เช่น ขอให้สั้นลง โดยยังคุยเรื่องเดิมอยู่ ส่วนนี้คือสิ่งที่ผู้ใช้เห็น; เดี๋ยวเราค่อยดูว่าฝั่ง API ส่งต่อบทสนทนานี้อย่างไร

**ภาพจำลองบทสนทนา:**

- ผู้ใช้: `ขอให้สั้นลงอีกนิด`
- Agent: `ประชุมเลื่อนเป็น 15:00 น. นะครับ`
- ป้ายคงที่: `ภาพจำลอง`

### B4 — เบื้องหลังแอปกับ Chat API

**พากย์:** เมื่อเชื่อม API แอปส่งคำขอจากระบบหลังบ้านไปยัง LangMind แล้วนำข้อมูลตอบกลับมาแสดง Key ควรอยู่ฝั่ง server; API ส่งข้อมูลกลับมา ส่วนหน้าตาแชทเป็นหน้าที่ของแอป

**ข้อความเน้นใน diagram:**

- `แอป` — รับคำถาม / แสดงคำตอบ
- `Backend` — เก็บ API Key / เรียก API
- `LangMind Agent` — รับคำถาม / ส่งผลกลับ
- เส้นทาง: `ผู้ใช้ → แอป → Backend → Chat API → Backend → แอป`

### B5 — Endpoint สำหรับส่งและควบคุมคำตอบ

**พากย์:** Chat API มีเส้นส่งข้อความแบบ stream เป็นค่าเริ่มต้น และแบบ blocking ที่รอ JSON ทั้งก้อน นอกจากนี้ยังมี preview ใน Agent Builder ซึ่งใช้ published version และมี endpoint สำหรับหยุด stream ที่กำลังทำงาน

**ข้อความบนจอ:**

- `POST /api/chat/message` — SSE stream
- `POST /api/chat/message/blocking` — JSON เต็ม
- `POST /api/chat/preview` — Agent Builder · SSE · channel `web`
- `POST /api/chat/messages/{id}/stop` — หยุด stream
- `scope: chat:invoke`

### B6 — Endpoint สำหรับบทสนทนา

**พากย์:** เมื่อต้องดูประวัติ มี endpoint สำหรับรายการบทสนทนา รายละเอียด และข้อความในบทสนทนา การอ่านหรือแก้บทสนทนาต้องระบุ agent ID ด้วย ส่วนการลบบทสนทนาเป็นการลบถาวร

**ข้อความบนจอ:**

- `GET /api/chat/conversations` — รายการ · `agent_id`, cursor, limit
- `GET /api/chat/conversations/{id}` — รายละเอียด · `agent_id`
- `GET /api/chat/conversations/{id}/messages` — ข้อความ · `agent_id`, cursor, limit
- `PATCH /api/chat/conversations/{id}` — เปลี่ยนชื่อ/สถานะ · `agent_id`
- `DELETE /api/chat/conversations/{id}` — ลบถาวร · `agent_id`

### B7 — Endpoint เสริมหลังคำตอบ

**พากย์:** ยังให้คะแนนคำตอบได้สองค่า คือหนึ่งหรือหนึ่งติดลบ และดาวน์โหลดไฟล์ที่ Agent สร้างได้ ทุก endpoint ในกลุ่ม Chat ใช้ scope chat invoke ตามเอกสารอ้างอิง

**ข้อความบนจอ:**

- `POST /api/chat/messages/{id}/feedback` — rating `1` หรือ `-1`
- `GET /api/chat/messages/{id}/generated-files/{file_id}` — ดาวน์โหลดไฟล์
- `scope: chat:invoke`

### B8 — เตรียม Key และส่งคำถามแรก

**พากย์:** ก่อนเรียก ให้สร้าง Personal API Key ที่มี scope chat invoke แล้วเก็บเป็น secret ในระบบหลังบ้าน ตัวอย่างนี้มี agent ID อยู่แล้ว จึงส่ง ID คำถาม และ conversation ID ว่างเพื่อเริ่มบทสนทนาใหม่

**ข้อความเน้น:** `Key อยู่ฝั่ง server` · `มี agent_id แล้ว` · `conversation_id: null = เริ่มใหม่`

**ตัวอย่างคำสั่งบนจอ (ใช้ placeholder เท่านั้น):**

```bash
export LM_TOKEN="lmpat_..."
curl --no-buffer -X POST "https://langmind.in.th/api/chat/message" \
  -H "Authorization: Bearer ${LM_TOKEN}" \
  -H "Content-Type: application/json" \
  --data '{"agent_id":"<AGENT_ID>","query":"ช่วยร่างข้อความแจ้งทีมว่าเลื่อนประชุมเป็น 15:00 น. ให้สุภาพ","conversation_id":null,"attachment_ids":[]}'
```

**ป้าย:** `ตัวอย่างคำสั่ง · placeholder · ไม่ได้เรียก API จริง`

### B9 — อ่านผลแบบ SSE

**พากย์:** คำตอบ stream กลับมาเป็น event: message start ส่ง ID ของข้อความกับบทสนทนา, message ส่งข้อความเป็นช่วง, citations อาจมีเมื่อเกี่ยวข้อง และ message end ส่งคำตอบฉบับเต็มพร้อม usage ให้แอปจัดการต่อ

**ลำดับที่แสดง:**

```text
message_start  → ได้ conversation_id และ message_id
message        → ข้อความทยอยมา
citations      → อาจมี
message_end    → คำตอบเต็มและ usage
```

**เส้นทางภาพ:** `Chat API → Backend → แอป`

**ป้าย:** `ลำดับตัวอย่างจำลอง · ไม่ใช่ผลเรียกจริง`

### B10 — ส่งคำถามต่อด้วยบทสนทนาเดิม

**พากย์:** ถ้าผู้ใช้ขอให้สั้นลง แอปส่งคำถามใหม่พร้อม conversation ID เดิม แล้วแสดงผลตามที่แอปออกแบบไว้ สรุปคือเลือก endpoint ให้ตรงงาน เก็บ Key ไว้ฝั่ง server และเก็บ conversation ID เมื่อต้องการคุยต่อ

**ตัวอย่าง body สำหรับคำถามต่อ:**

```json
{
  "agent_id": "<AGENT_ID>",
  "query": "ขอให้สั้นลงอีกนิด",
  "conversation_id": "<CONVERSATION_ID>",
  "attachment_ids": []
}
```

**สรุปบนจอ:** `เลือก endpoint` → `ส่งข้อความ` → `เก็บ conversation_id เพื่อคุยต่อ`

## ช่วงสำหรับ voice audition

ใช้ย่อหน้าต่อเนื่องนี้ทดสอบเสียงก่อนทั้งตอน; ยังไม่มีไฟล์เสียง sample:

> เคยขอให้ผู้ช่วยช่วยเขียนข้อความ แล้วอยากให้แก้ต่ออีกนิดไหม? ตัวอย่างนี้เริ่มจากขอร่างข้อความแจ้งเลื่อนประชุม แล้วถามต่อให้สั้นลง จากนั้นเราจะดูว่าแอปส่งคำถามไปยัง Chat API และรับคำตอบกลับมาอย่างไร

**คำออกเสียงสำหรับผู้พากย์:** LangMind อ่าน “แลงมายด์”; SSE อ่าน “เอสเอสอี”; API Key อ่าน “เอพีไอคีย์”; `agent_id` และ `conversation_id` ไม่จำเป็นต้องอ่านออกเสียงเต็ม ให้ใช้ “รหัส Agent” และ “รหัสบทสนทนา” ในคำพากย์

## สิ่งที่ต้องตรวจในการอ่านบท

- ให้ `message_start`, `message`, `citations`, `message_end` ตรงกับตัวอย่างเอกสารและไม่พูดเกินว่าทุก response มี citations
- ถ้อยคำของภาพจำลองต้องไม่ฟังเหมือนผล API จริง
- อ่านชื่อ route และ scope ให้ผู้ชมเข้าใจโดยไม่อ่าน URL ทุกเส้นออกเสียง
- วัดเวลาและวางซับจากเสียงจริงหลังเลือกเสียง ไม่ล็อกความยาวจากคลิป EP04
