## 1. โจทย์จากมุมคนดู (Audience & Purpose)

* **ผู้ชมเป้าหมาย**: Developer, วิศวกรซอฟต์แวร์ หรือเจ้าของแอปพลิเคชันที่มี Agent ใน LangMind แล้ว และต้องการเชื่อมต่อระบบแชทเข้ากับโมบายล์แอปหรือเว็บของตัวเอง
* **พื้นฐานเดิมของผู้ฟัง**: รู้จักการเรียก HTTP Request และมี Agent ใน LangMind แล้ว แต่ยังไม่เคยต่อ Chat API จริง ไม่คุ้นเคยกับ SSE Stream และไม่แน่ใจว่าจะทำให้แชตคุยต่อเนื่องจำเรื่องเดิมได้อย่างไร
* **ความต้องการหลัก**:
  1. อยากให้แอปแสดงผลข้อความคำตอบแบบพิมพ์สดทีละคำ (Streaming) ผู้ใช้ไม่ต้องรอโหลดทั้งก้อน
  2. อยากให้ AI จำบริบทการสนทนาเดิมได้เวลาผู้ใช้ถามคำถามต่อเนื่อง (Multi-turn Context)
  3. อยากเข้าใจความปลอดภัยว่าควรเก็บ API Key และส่งคำขอผ่านสถาปัตยกรรมแบบใด
* **จุดติดขัด (Friction)**:
  * ถ้าเรียกแบบเดิมคำตอบจะมาช้ามากเพราะต้องรอโมเดลคิดจนจบประโยค
  * ถามคำถามที่สองแล้ว AI ลืมเรื่องที่เพิ่งคุยไป กลายเป็นคนละเรื่อง
  * ไม่รู้ว่าระหว่าง SSE กับ Blocking ต่างกันอย่างไร และควรเลือกใช้ตอนไหน
* **เหตุผลที่ดู**: เห็นภาพรวมชัดเจนใน 9 Beat ตั้งแต่เตรียมระบบ เชื่อมต่อ 3 ครั้ง จนถึงข้อควรระวังในการนำไปใช้จริง
* **สิ่งที่ดูจบแล้วนำไปทำต่อได้**: เขียนโค้ดเชื่อมต่อ `POST /api/chat/message`, จัดการ `conversation_id`, อ่าน Event ของ SSE (`message_start`, `message`, `message_end`) และสลับไปใช้ Blocking ได้ถูกต้อง

## 2. แกนคำอธิบายและ Use Case ตัวอย่าง

* **Use Case ตัวแทน**: **"ผู้ช่วย AI บริการลูกค้าในแอปพลิเคชันร้านค้า (Customer Service Assistant)"**
  * *เหตุการณ์รอบที่ 1*: ลูกค้าพิมพ์ถามในแอป `"สินค้าชิ้นนี้มีของไหมครับ"` → เซิร์ฟเวอร์ส่งคำขอเปิดห้องแชตใหม่ → ได้รับคำตอบสตรีมมิ่งพิมพ์สดทีละคำจนจบ
  * *เหตุการณ์รอบที่ 2*: ลูกค้าถามต่อเนื่อง `"ถ้าสั่ง 2 ชิ้น มีส่วนลดไหมครับ"` → เซิร์ฟเวอร์ส่ง `conversation_id` เดิมไปด้วย → AI จำได้ทันทีว่าเป็นสินค้าชิ้นไหนและตอบเรื่องส่วนลดได้ถูกต้อง
* **ท่อการทำงาน 3 ครั้ง (เตรียม → เชื่อม 3 ครั้ง → ใช้ผล)**:
  1. **ครั้งที่ 1 (เริ่มห้องแชตใหม่)**: ส่ง `POST /api/chat/message` พร้อม `conversation_id: null` เพื่อเปิดเธรดใหม่ และรับ `conversation_id` ประจำห้องจาก event `message_start`
  2. **ครั้งที่ 2 (รับสตรีมคำตอบสด)**: อ่านข้อมูล SSE events `message` ที่ทยอยส่งคำตอบทีละท่อนจนถึง event `message_end` พร้อม usage token
  3. **ครั้งที่ 3 (ถามต่อในห้องเดิม)**: ส่ง `POST /api/chat/message` พร้อมระบุ `conversation_id` เดิม ทำให้ AI จำประวัติและบริบทการคุยได้
* **การแบ่งหน้าที่ชัดเจน (Separation of Concerns)**:
  * **แอปพลิเคชัน (Frontend)**: แสดงผล UI หน้าแชต, คลี่ตัวอักษรที่สตรีมมาสด ๆ, รับคำถามจากผู้ใช้
  * **เซิร์ฟเวอร์หลังบ้าน (Backend Server)**: เก็บรักษา API Key (`lmpat_`) อย่างปลอดภัย, ทำหน้าที่ยิงคำขอไปยัง LangMind API และส่งต่อสตรีมให้แอป
  * **LangMind Chat API**: รับคำถาม, ค้นหาข้อมูล/ประมวลผลผ่าน Agent, จัดการ Memory และสตรีมคำตอบกลับ

## 3. โครงเรื่อง 9 ช่วง (The 9-Beat Blueprint)

| Beat | คำถามคนดู | สาระสำคัญและสิ่งที่เห็นบนจอ |
|---|---|---|
| **b1** | ฟีเจอร์นี้แก้ปัญหาอะไร | หน้าจอแชตบริการลูกค้าในแอปมือถือ + Robot สงสัย (`01-question.png`) + แชตบอตตอบช้าหรือลืมเรื่องเดิม + ชิป 3 คำถามลอย: `เตรียมอะไร?`, `เชื่อมตรงไหน?`, `ใช้ผลยังไง?` |
| **b2** | ภาพรวมระบบเป็นยังไง | แผนภาพ 3 ส่วน: แอปผู้ใช้ ⇄ เซิร์ฟเวอร์หลังบ้าน ⇄ LangMind Chat API + ป้ายลำดับ 3 ขั้นตอน: `1 เริ่มห้องใหม่`, `2 สตรีมคำตอบ`, `3 ถามต่อในห้องเดิม` |
| **b3** | ต้องเตรียมอะไรบ้าง | การ์ด 3 ใบ: 1. `agent_id` ที่พร้อมใช้ใน LangMind, 2. API Key (`lmpat_`) พร้อม Scope `chat:invoke`, 3. Backend Server เก็บกุญแจปลอดภัย (ห้ามใส่ใน Client) |
| **b4** | ครั้งที่ 1: เริ่มห้องใหม่ | Minimap เขียว (ครั้งที่ 1) + ยิง `POST /api/chat/message` พร้อม `conversation_id: null` + รับ event `message_start` ที่ให้ `conversation_id` ประจำห้อง |
| **b5** | ครั้งที่ 2: สตรีมคำตอบสด | Minimap ทอง (ครั้งที่ 2) + หน้าจอแชตแสดงตัวอักษรพิมพ์สดทีละท่อนตาม event `message` จนถึง `message_end` + ชิปแนะนำทางเลือก Blocking (`/blocking`) สำหรับสคริปต์ |
| **b6** | ครั้งที่ 3: ถามต่อเรื่องเดิม | Minimap เขียวน้ำทะเล (ครั้งที่ 3) + ลูกค้าถามต่อ `"สั่ง 2 ชิ้นมีส่วนลดไหม"` + ส่ง `conversation_id` เดิมกลับไป + AI ตอบต่อเนื่องในบริบทเดิมได้แม่นยำ |
| **b7** | นำผลไปใช้ & ข้อควรระวัง | 4 ประเด็น: 1. ส่ง `user_id` เพื่อนับผู้ใช้จริง, 2. สั่งหยุดสตรีมด้วย `/chat/messages/{id}/stop`, 3. ตรวจประวัติย้อนหลังด้วย `/messages`, 4. ย้ำเรื่องความปลอดภัย API Key |
| **b8** | สรุปเนื้อหา | การ์ด 3 เสาหลัก: 1. เตรียม (Agent + Key + Server) → 2. เชื่อม (เปิดห้องใหม่ · สตรีมสด · ถามต่อด้วย ID) → 3. ใช้ผล (ควบคุมสตรีมและนำไปต่อยอด) |
| **b9** | ผู้สนับสนุน & CTA | โลโก้ LangMind เด่นตรงกลาง + ข้อความ "คลิปนี้สนับสนุนโดย LangMind" + เว็บไซต์ `langmind.in.th` |
