# Storyboard และแบบหน้าจอ — EP03 ฉบับปรับให้อธิบายง่าย

Episode ID: ep03-streaming-chat  
Revision: ปรับหลังทบทวน animatic v2 วันที่ 8 พฤศจิกายน 2026  
สถานะ: ร่าง storyboard สำหรับ animatic v3; ยังไม่ใช่การตรวจรับจากผู้ใช้

## 1. เหตุผลในการปรับ

Animatic v2 วาง endpoint, event และหน้าที่ของ Backend/UI ไว้หลายชั้นในเวลาใกล้กัน ผู้ชมจึงต้องอ่านศัพท์ก่อนเห็นเหตุและผล รอบนี้ใช้คำถามเดียวตั้งแต่ต้นถึงท้าย แสดงความต่างของผลที่หน้าจอเห็นก่อน แล้วค่อยแนะนำชื่อ event และบทบาทระบบ

หลักการ:

- หนึ่งจังหวะมีใจความหลักหนึ่งข้อ
- คำถามเดิมเป็นเส้นเรื่องต่อเนื่อง ไม่เปลี่ยน use case กลางคลิป
- ภาษาไทยอธิบายหน้าที่; ชื่อ event และ endpoint เป็นป้ายใกล้ภาพที่อธิบาย
- คำตอบในแชตเป็นภาพจำลอง/แผนภาพ ไม่ทำให้ดูเหมือนผล API จริง
- ข้อความหลักบนจอเป็น key takeaway แยกจากซับเสียงพากย์; animatic v3 เพิ่มซับร่างในแถบเฉพาะด้านล่างเพื่อให้ตามเนื้อหาได้แม้ยังไม่มีเสียง
- ความยาว 52 วินาทีเป็น story hold สำหรับ animatic เงียบ ไม่ใช่เวลา final

## 2. ลำดับเหตุและผล

| จังหวะ | คนดูเห็นอะไร | ใจความหนึ่งข้อ | คำถามที่พาไปต่อ |
|---|---|---|---|
| 1. คำถามเดียว | คำถามเข้าแชตและหน้าจอรอ | ผู้ใช้ส่งคำถาม แต่ยังไม่เห็นคำตอบ | ทำไมหน้าจอจึงแสดงผลต่างกันได้ |
| 2. สองวิธีรับ | ผลเดียวกันรอครบเป็นชุด หรือปรากฏเป็น chunks | Streaming เปลี่ยนรูปแบบการรับข้อมูล; แอปเลือกวิธีแสดง | stream มีข้อความชนิดใดบ้าง |
| 3. ลำดับ event | event เพิ่มตามลำดับ พร้อมคำอธิบายไทย | message คือเนื้อหา; message_end บอกว่าคำตอบครบ | ใครอ่าน stream และวาด UI |
| 4. แบ่งหน้าที่ | API → App Backend → Client UI | Backend ถือ key และอ่าน stream; UI เป็นงานของแอป | สรุป flow จากคำถามเดิม |
| 5. จำสองจุด | backend ส่งคำขอ → UI แสดง chunks → message_end | ข้อความทยอยแสดงได้; ถือว่าครบเมื่อได้ message_end | จบ |

## 3. Storyboard รายซีน

### ซีน 1 — คำถามเดียว (ประมาณ 8 วินาที)

- **เป้าหมาย:** เริ่มจากสถานการณ์ที่ผู้ชมคุ้นเคย
- **การกระทำ:** คำถามตัวอย่างปรากฏในแชต; สถานะรออยู่ใต้คำถาม
- **เสียง:** อ่านตัวอย่างคำถามและบอกว่าหน้าจอยังรอ
- **ข้อความหลัก:** **คำถามถูกส่งแล้ว** → **กำลังรอคำตอบ**
- **ภาพรอง:** Robot ท่าสงสัยขนาดอ่านเห็นได้ชัด ชี้กลับเข้าหน้าจอ ไม่บังคำถาม และใช้พื้นโปร่งใสไม่มีกรอบขาว
- **ป้าย:** **[ภาพจำลอง]**
- **ออกจากซีน:** คงคำถามเดิมไว้ แล้วแยกเป็นสองวิธีแสดงผล

### ซีน 2 — คำตอบแสดงคนละแบบ (ประมาณ 11 วินาที)

- **เป้าหมาย:** ให้เห็นความต่างก่อนเจอคำศัพท์ SSE
- **ภาพ:** สองแผงเรียงบน/ล่างเพื่อให้อ่านได้บนมือถือ; ใช้คำถามเดียวกันเป็นหัวร่วม
  - แผงบน: ช่วงรอ → คำตอบทั้งก้อนปรากฏเมื่อได้รับครบ
  - แผงล่าง: ข้อความตัวอย่างปรากฏเป็นชิ้น 1 → 2 → 3
- **ป้ายภาพ:** **[ภาพอธิบาย]** บนทั้งสองแผง; ไม่ใช้ข้อความที่เหมือนผล LangMind จริง
- **ข้อความ:** **รับครบก่อนแสดง** เทียบกับ **ทยอยแสดงข้อความที่ได้รับ**
- **เสริมหลังภาพเข้าใจแล้ว:** **POST /chat/message/blocking** เทียบกับ **POST /chat/message · SSE**
- **เสียง:** อธิบายว่า Backend รับ event จาก Streaming API และแอปจึงเลือกทยอยแสดงข้อความได้
- **ห้ามสื่อ:** ความเร็วที่รับประกัน, โมเดลคิดเร็วขึ้น, หรือคำว่า “ทันที”
- **ออกจากซีน:** ยุบความต่างสองแบบเหลือเส้นทาง stream

### ซีน 3 — event ที่ต้องจำ (ประมาณ 13 วินาที)

- **เป้าหมาย:** ทำให้ชื่อ event มีความหมายและย้ำ terminal event
- **เริ่มภาพ:** ป้าย **POST /chat/message · Server-Sent Events (SSE)**
- **เผยทีละใบตามเสียง:**
  1. **message_start** — เริ่มและให้ conversation/message ID
  2. **message** — เนื้อหาคำตอบเป็น chunks
  3. **citations** — แหล่งอ้างอิง ถ้ามี; ใช้เส้น/กรอบแบบไม่ใช่ขั้นบังคับ
  4. **message_end** — คำตอบฉบับเต็มและ usage
- **ข้อความหลักเมื่อจบ:** **message = เนื้อหาที่ทยอยมา** / **message_end = คำตอบครบ**
- **ภาพ:** ไฮไลต์ message_end เมื่อถึงลำดับสุดท้าย พร้อมป้าย **คำตอบสมบูรณ์เมื่อได้รับ event นี้**
- **ออกจากซีน:** เส้นข้อมูลต่อจาก API มายัง Backend

### ซีน 4 — ใครทำอะไร (ประมาณ 12 วินาที)

- **เป้าหมาย:** แยก API, Backend และ UI ออกจากกันโดยไม่ซ้ำศัพท์
- **องค์ประกอบตามลำดับ:**
  1. **LangMind API:** ส่งกลับ SSE events
  2. **App Backend:** เก็บ API key, ส่งคำขอ, อ่าน/parse stream
  3. **Client UI:** รับข้อมูลที่แอปส่งต่อ, จัดการสถานะและแสดงผล
- **ลูกศร:** คำขอจาก Backend ไป API; SSE events กลับมายัง Backend; ข้อมูลจาก Backend ไป UI
- **ข้อความกำกับ:** **API ส่งข้อมูล** / **แอปเป็นผู้สร้างและจัดการหน้าจอ**
- **ภาพประกอบ:** Robot ชี้เฉพาะ Backend/UI; ไม่บังลูกศรหรือป้าย
- **ออกจากซีน:** เน้นเส้นทาง Backend → UI ในภาพสรุป

### ซีน 5 — จำสองจุด (ประมาณ 8 วินาที)

- **เป้าหมาย:** ปิดด้วยสิ่งที่ developer นำไปทำต่อได้
- **ภาพ:** เล่นซ้ำคำถามเดิมเป็นสามจังหวะ: Backend ส่งคำขอ → UI เลือกแสดง chunks → คำตอบครบเมื่อ **message_end**
- **ข้อความปิด:** **Backend เก็บ key และอ่าน stream** / **UI แสดงผลตามที่แอปกำหนด** / **ครบเมื่อได้ message_end**
- **เสียง:** สรุปสองข้อคือขอบเขตหน้าที่ และเงื่อนไขที่ใช้ถือว่าคำตอบสมบูรณ์
- **โลโก้:** ใช้ไฟล์กลางโดยไม่แก้สี สัดส่วน หรือครอปเพิ่ม; ตรวจพบว่า source PNG มีคำ LANG MIND ชิดขอบล่าง ให้บันทึกเป็นข้อจำกัดของ asset

## 4. แบบหน้าจอทุกภาพก่อนทำ plate

ขนาด master: 1080×1920, 30 fps, portrait ตามโครงการเดิม  
ฟอนต์ข้อความใหม่: Sarabun จาก asset ตอน; ไม่ฝังข้อความไทยใหม่ใน HTML เป็น UI จำลอง  
แนวจัดวาง: heading ด้านบน; เนื้อหาหลักในพื้นที่กลาง; key takeaway อยู่ใกล้ภาพที่อธิบายและไม่ทับ raster; ข้อความสำคัญออกแบบให้เห็นได้เมื่อย่อดู 360×640

### แถบซับร่าง v3

- **ตำแหน่ง:** แถบกลางแนวนอน x=72–1008, y=1560–1792 ใน master 1080×1920; เว้นขอบล่าง 128 px และแยกจากข้อมูลหลัก
- **ลักษณะ:** พื้นกรมทึบมุมมน ข้อความ Sarabun Bold สีขาว จัดกึ่งกลาง; ใช้ 42 px และลดได้ถึง 30 px เมื่อจำเป็นเพื่อให้อยู่ไม่เกิน 2 บรรทัด
- **ข้อความ:** หนึ่งใจความสั้นต่อ visual stage; รายการข้อความอยู่ใน `video-v3/timing.json` เพื่อให้ภาพและเวลาใน animatic ใช้ชุดเดียวกัน
- **เวลา:** แสดงตลอดช่วงของ stage นั้นเพื่อใช้ตรวจเนื้อหาในคลิปเงียบ; ยังไม่ใช่ timing ตามเสียง และต้องปรับหลังเลือก voice audition

### การวางตัวละคร

- ใช้ไฟล์ PNG character เดิมโดยคง alpha; ตัดเฉพาะขอบโปร่งใสรอบตัวออกตอนวางลงฉาก ไม่วางบน matte สีขาว
- ขยายตัวละครเป็นองค์ประกอบรองให้เห็นท่าทางได้ในเฟรม 360×640; เว้นระยะจากการ์ดเนื้อหาและแถบซับ

### SCR-V3-01 — คำถามและสถานะรอ

- **ที่มา:** ใช้ raster **assets/ui/scr-01-chat-loading.png** เดิมโดยไม่แก้ source
- **ข้อความ:** คำถามเดิม “ช่วยแนะนำขั้นตอนเริ่มต้นให้หน่อย”; สถานะ “กำลังรอการตอบกลับ”; ป้ายภาพจำลองแยกจากภาพ
- **Layout:** raster อยู่กลางเฟรม มีหัวข้อ “ผู้ใช้ถาม 1 ครั้ง”; Robot ขยายเป็นตัวชี้ ไม่บังคำถาม
- **Crop/zoom:** crop เฉพาะ header, คำถาม และ loading state จากต้นฉบับ (x=0–1080, y=0–800); ใส่ป้าย [ภาพจำลอง] แยกบนภาพเพื่อขยายส่วนที่ต้องอ่าน
- **คงเดิม:** คำถามและชื่อ UI จำลอง
- **เปลี่ยน:** ใส่คำถามก่อน แล้วค่อยเน้นสถานะรอ

### SCR-V3-02 — เทียบรับครบกับทยอยแสดง

- **ชนิด:** ภาพอธิบายแบบ raster สองแผง ไม่อ้างเป็น UI ของผลิตภัณฑ์
- **ข้อความคงที่:** คำถามเดียวกันในทั้งสองแผง; ป้าย **[ภาพอธิบาย]**
- **แผงรับครบ:** **รอรับข้อมูล** → เผยกล่อง **คำตอบทั้งชุด** เมื่อจังหวะสุดท้ายมาถึง
- **แผง Streaming:** เผยข้อความจำลอง 3 ชิ้นตามลำดับ พร้อมป้าย **ตัวอย่างการแสดงผล**
- **Layout:** สองแผงกว้างเต็มเฟรมและเรียงตามแนวตั้ง; label และ endpoint อยู่ใกล้ชื่อวิธี ไม่ใส่เนื้อหาคำตอบสมมติ
- **Crop/zoom:** แสดงสองแผงเต็ม; ข้อความสำคัญไม่ถูกบีบเป็นคอลัมน์แคบ
- **คงเดิม:** คำถามเดียวกันทั้งซีน
- **เปลี่ยน:** สถานะซ้ายจากรอเป็นคำตอบครบ; ข้อความขวาจาก 1 เป็น 3 ชิ้น

### SCR-V3-03 — SSE event stream

- **ชนิด:** Diagram แบบ raster/กราฟิกใน scene; ไม่ใช่หน้าจอ API จริง
- **ข้อความ:** endpoint และชื่อ event ตามลำดับในซีน 3 พร้อมคำไทยสั้น ๆ ตามรายการด้านบน
- **Layout:** เส้นทางแนวตั้งหนึ่งเส้น; event cards เรียงตามลำดับ; citations ใช้เส้นขอบประเพื่อสื่อว่าอาจไม่มี
- **Crop/zoom:** ให้ชื่อ event และคำแปลอยู่ในกรอบทั้งหมด; เน้น message_end ด้วยสีเดียวกับ accent
- **คงเดิม:** ลำดับ event ตลอดซีน
- **เปลี่ยน:** เพิ่มการ์ดทีละใบ; ปิดด้วยข้อความจำสองชื่อ

### SCR-V3-04 — API, Backend, UI

- **ชนิด:** Diagram แบบ raster/กราฟิกใน scene; ไม่ใช่ official architecture UI
- **ข้อความ:** หน้าที่สั้นตามรายการ 3 กล่อง; เก็บ API key เฉพาะในกล่อง Backend
- **Layout:** API อยู่บน, Backend กลาง, UI ล่าง; ลูกศร Backend → API (คำขอ), API → Backend (SSE), Backend → UI (ข้อมูลแอปส่งต่อ)
- **Crop/zoom:** ลูกศรและป้ายกำกับไม่ทับกล่อง
- **คงเดิม:** ตำแหน่งระบบทั้งสาม
- **เปลี่ยน:** เผยลูกศรกับหน้าที่ทีละช่วง

### SCR-V3-05 — สรุปเส้นทางคำถาม

- **ชนิด:** Diagram สรุปแบบ raster/กราฟิก
- **ข้อความ:** Backend ส่งคำขอ → UI แสดง chunks ตามการออกแบบแอป → message_end แปลว่าคำตอบครบ
- **Layout:** สามจังหวะแนวตั้ง; โลโก้จริงและ Robot ขนาดใหญ่ขึ้นเป็นองค์ประกอบรอง โดยไม่บังข้อความหรือซับ
- **Crop/zoom:** ไม่ครอปโลโก้เพิ่ม; ใช้ภาพเต็มตามสัดส่วน
- **คงเดิม:** คำถามตัวอย่างและลำดับปลายทาง
- **เปลี่ยน:** ไฮไลต์ message_end เป็นผลสุดท้าย ไม่เพิ่มข้อสรุปใหม่

## 5. แผน motion และข้อจำกัด

- คำถามปรากฏก่อนสถานะรอ; ไม่มีตัวเลขนับเวลา
- เปรียบเทียบซ้าย/ขวาโดยรักษาคำถามเดียวกัน; ชิ้นข้อความเผยตามลำดับ ไม่จำลองจำนวนวินาที
- event cards เผยเมื่อมีการกล่าวถึง; citations มีสถานะ optional
- scene 4 ใช้ทิศลูกศรและคำกำกับเพื่อแยก request, SSE stream และการส่งต่อในแอป
- scene 5 ทวนเฉพาะสิ่งที่กล่าวก่อนหน้า; ไม่เพิ่มผลทดสอบหรือคำรับประกัน
- Animatic ไม่มีเสียง; ซับร่างค้างตาม visual stage ไม่ได้ sync บทพูด ต้องทำ voice audition และ retime/ปรับการแบ่งบรรทัดจากเสียงที่ผู้ใช้เลือกก่อนฉบับเต็ม
- ไม่เรียก live/paid API, ไม่สร้าง provider resources และไม่ publish
