## 1. เกณฑ์การคัดเลือกตามหน้าที่ของซีน

ในคลิป EP08 มี 3 หน้าที่หลักที่ต้องการแอนิเมชันช่วยอธิบาย:
1. **แสดงหน้าจอเว็บแชทที่มีแถบประวัติและข้อความย้อนหลัง (Device Hosting)**: ให้เห็นรายการบทสนทนา ข้อความเก่า–ใหม่ และการเปลี่ยนชื่อ/ปิดห้องแชท
2. **แสดงลำดับการดึงรายการและข้อความ (Thread & Message Reveal)**: ให้เห็นการทำงานของ `next_cursor` และการเรียงข้อความจากเก่าไปใหม่
3. **เน้นพารามิเตอร์บังคับ `?agent_id=` และการอัปเดตด้วย PATCH (Code & Marker Highlight)**: ให้เห็นว่าทุกคำขอต้องแนบ `?agent_id=` และ `PATCH` ส่งเฉพาะฟิลด์ที่ต้องการเปลี่ยนได้

## 2. รายการ Catalog ที่เลือกใช้ตามหน้าที่

| รหัส / ชื่อ Catalog | หน้าที่ในซีน | Beat ที่ใช้ | เหตุผลและข้อจำกัด |
|---|---|---|---|
| **#hf-195 Browser Device Stage** | ครอบภาพหน้าจอจำลอง `APP-HISTORY-LIST` และ `APP-HISTORY-DETAIL` | b1, b4, b5, b6 | ใช้ host ภาพ raster ของหน้าเว็บแชทที่มีแถบประวัติสนทนา |
| **#hf-183 Message Thread Reveal (หรือ #hf-221 Thread Message Stack)** | แสดงจังหวะการเรียงข้อความจากเก่าไปใหม่ (`user` → `assistant`) | b5 | สื่อสารลำดับการดึงประวัติข้อความย้อนหลังได้ชัดเจน |
| **#hf-113 Code Highlight Sweep** | ไฮไลต์ `?agent_id=01J8...`, `next_cursor`, และ body ของ `PATCH` (`title`, `status: "closed"`) | b4, b5, b6 | ดึงสายตาไปยังพารามิเตอร์สำคัญโดยไม่ต้องแสดง JSON ทั้งหมด |
| **#hf-072 Marker Highlight** | เน้นกติกา `?agent_id=` บังคับทุกเส้น, `DELETE` ลบถาวร (`204`), และ endpoint เสริม `stop` / `generated-files` | b3, b6, b7 | ช่วยเน้นจุดที่นักพัฒนามักพลาดเวลาเชื่อมต่อจริง |

## 3. สิ่งที่ต้องทดสอบใน Sample (W5)

* **ความชัดเจนของการสลับภาพ `APP-HISTORY-LIST` ไปยัง `APP-HISTORY-DETAIL` (`b4–b6`)**: ตรวจสอบว่าเห็นการเปลี่ยนชื่อหัวข้อจาก `"ราคาสินค้า A"` เป็น `"สอบถามราคาสินค้า A"` และป้ายสถานะจาก `"open"` เป็น `"closed"` ได้ชัดเจนบนมือถือ
* **ขนาดตัวอักษรของ URL ที่มี `?agent_id=...` ใน Code Highlight Sweep**: ตรวจสอบการตัดบรรทัดของ URL บนจอ 9:16 ไม่ให้ล้นกรอบ
