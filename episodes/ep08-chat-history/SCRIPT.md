# EP08 — บทร่างภาษาพูด 9 Beats (Chat Conversations & History API)

ผู้ชม: Developer ที่ต้องการทำระบบประวัติแชท โหลดข้อความย้อนหลัง และจัดการห้องสนทนาในเว็บหรือแอปของตัวเอง  
โครงสร้าง: 9 Beats (`b1–b9`) ตามแนวทาง EP04 v3 (เตรียม → เชื่อม 3 ครั้ง → ใช้ผล + ผู้สนับสนุน)  
ภาษา: ไทย โทนสนทนา กระชับ แยกบทพูด (`say`) ซับไตเติล (`cap`) และข้อความเน้นบนจอชัดเจน

## 1. บทเต็มและจุดแบ่งจังหวะ (Full Script & Beats)

| Beat | บทบรรยายภาษาพูด (`say`) | ข้อความเน้นบนจอ (แยกจากซับ) |
|---|---|---|
| **b1** | พอเราทำหน้าเว็บแชทให้คุยกับ AI ได้แล้ว คำถามถัดมาคือ ถ้าผู้ใช้ปิดหน้าเว็บไป แล้วเปิดกลับมาใหม่ จะดึงรายการแชทเก่ามาแสดงด้านข้าง กดอ่านข้อความย้อนหลัง หรือเปลี่ยนชื่อห้องแชทได้อย่างไร ถ้าอยากทำระบบประวัติแชทให้ครบแบบนี้ ต้องเตรียมอะไร เชื่อมตรงไหน และเอาผลไปใช้ยังไง มาดูกันครับ | ทำระบบประวัติแชท & จัดการห้องสนทนา |
| **b2** | ภาพรวมของฟีเจอร์นี้เชื่อมระหว่างหน้าเว็บแชท ระบบหลังบ้านของคุณ และ Chat API ของ LangMind โดยระบบหลังบ้านจะเรียกใช้งานสามขั้นตอนหลัก คือหนึ่ง ดึงรายการบทสนทนาทั้งหมด สอง ดึงข้อความย้อนหลังในห้องที่เลือก และสาม เปลี่ยนชื่อ ปิด หรือลบบทสนทนาครับ | ดึงรายการห้องแชท → โหลดข้อความย้อนหลัง → เปลี่ยนชื่อ/ปิด/ลบ |
| **b3** | เริ่มจากสิ่งที่ต้องเตรียม อย่างแรกคือรหัส agent ID ซึ่งสำคัญมาก เพราะทุก endpoint ของการจัดการบทสนทนาและข้อความ บังคับให้ส่ง agent ID เป็น query parameter เสมอ เพื่อยืนยันว่าเป็นบทสนทนาของ Agent ตัวนั้นจริง อย่างที่สองคือ API Key ที่มีสิทธิ์ chat invoke เพียงตัวเดียวก็ใช้ทั้งอ่านและเปลี่ยนชื่อห้องแชทได้เลย อย่างที่สามคือระบบหลังบ้านสำหรับเก็บ Key และเช็กสิทธิ์เจ้าของแชทครับ | สิ่งที่ต้องเตรียม:<br>1. `?agent_id=` (บังคับส่งทุกครั้ง)<br>2. สิทธิ์ `chat:invoke`<br>3. ระบบหลังบ้านเก็บ Key |
| **b4** | มาดูการเชื่อมครั้งที่หนึ่ง การดึงรายการบทสนทนา เรียก GET ไปที่ chat conversations พร้อมส่ง agent ID และจำนวน limit ระบบจะคืนรายการบทสนทนาในชื่อ items ซึ่งมีทั้งรหัสห้อง ชื่อหัวข้อ สถานะ จำนวนข้อความ และคืนค่า next cursor กลับมา ถ้ามีหน้าถัดไปก็นำค่านั้นส่งกลับไปเป็น cursor ได้เลย แต่ถ้าเป็น null แปลว่าครบทุกรายการแล้วครับ | ครั้งที่ 1: ดึงรายการบทสนทนา<br>`GET /api/chat/conversations?agent_id=...&limit=50`<br>คืน `items` & แบ่งหน้าด้วย `next_cursor` |
| **b5** | ครั้งที่สอง การดึงข้อความในบทสนทนา เมื่อผู้ใช้กดเลือกห้องแชท ให้เรียก GET ไปที่ chat conversations ตามด้วยรหัสห้อง และ messages พร้อมส่ง agent ID ระบบจะคืนข้อความเรียงจากเก่าไปใหม่เสมอ แยก role เป็น user และ assistant พร้อมแหล่งอ้างอิง citations จำนวนโทเค็นขาเข้าขาออก และเวลาประมวลผล latency ms ครับ | ครั้งที่ 2: โหลดข้อความย้อนหลัง (เก่า → ใหม่)<br>`GET /api/chat/conversations/{id}/messages?agent_id=...` |
| **b6** | ครั้งที่สาม การเปลี่ยนชื่อ ปิด หรือลบบทสนทนา ถ้าต้องการเปลี่ยนชื่อหัวข้อหรือปิดห้องแชท ให้ส่ง PATCH ไปที่ chat conversations ตามด้วยรหัสห้องและ agent ID โดยส่งเฉพาะฟิลด์ที่จะแก้ เช่น title เป็น สอบถามราคาสินค้า A และ status เป็น closed ส่วนถ้าต้องการลบทิ้ง ให้ส่ง DELETE ไปที่เส้นเดียวกันโดยไม่ต้องมี body ระบบจะตอบกลับสองศูนย์สี่และลบถาวรทันทีครับ | ครั้งที่ 3: เปลี่ยนชื่อ / ปิด / ลบห้องแชท<br>`PATCH .../conversations/{id}?agent_id=...` (`title`, `status`)<br>`DELETE` → `204` (ลบถาวร) |
| **b7** | นอกจากนี้ยังมีรายละเอียดที่ช่วยให้ทำหน้าแชทได้สมบูรณ์ขึ้น คือค่าโทเค็นและ latency บนข้อความย้อนหลัง จะมีค่าจริงเฉพาะฝั่ง assistant ส่วนฝั่ง user จะเป็นศูนย์และ null เสมอ และถ้าระหว่างคุยต้องการปุ่มกดหยุดข้อความที่กำลังไหลอยู่ ก็ส่ง POST ไปที่ chat messages ตามด้วย message ID และ stop ได้เลย รวมถึงดาวน์โหลดไฟล์ที่เอเจนต์สร้างผ่าน generated files ได้ด้วยครับ | ฟีเจอร์เสริมในหมวดเดียวกัน:<br>• หยุดข้อความสด: `POST /chat/messages/{id}/stop` (`204`)<br>• ดาวน์โหลดไฟล์ที่ AI สร้าง: `GET .../generated-files/{file_id}` |
| **b8** | สรุปครับ เตรียม agent ID และ API Key สิทธิ์ chat invoke เชื่อมสามจุด คือดึงรายการห้องที่ conversations โหลดข้อความที่ messages และแก้ไขหรือลบด้วย PATCH และ DELETE เพียงเท่านี้เว็บแชทของคุณก็มีระบบประวัติการสนทนาที่ครบถ้วนแล้วครับ | สรุป: เตรียม `agent_id` + `chat:invoke` → เชื่อม 3 จุด → ระบบประวัติแชทครบวงจร |
| **b9** | คลิปนี้สนับสนุนโดย LangMind เริ่มสร้างเว็บแชทและเชื่อมต่อ Agent ของคุณได้ที่ LangMind ดอท อิน ดอท ทีเอช | สนับสนุนโดย LangMind · `langmind.in.th` |

## 2. ข้อมูลตัวอย่างสำหรับหน้าจอและโค้ด (`illustrative` จากค่าตัวอย่างในคู่มือ)

* **รายการบทสนทนา (`APP-HISTORY-LIST`)** (ตรงตาม [langmind-api.md](../../langmind-api.md) บรรทัด 770–853):
  * รหัสห้อง: `01J8XM...`, ชื่อหัวข้อเดิม: `"ราคาสินค้า A"`, สถานะ: `"open"`, จำนวนข้อความ: `4 ข้อความ`
  * ข้อความในห้อง (เรียงเก่า → ใหม่):
    * `user`: `"ราคาสินค้า A เท่าไร"`
    * `assistant`: `"สินค้า A ราคา 590 บาทค่ะ"` (อ้างอิง: `"คู่มือ.pdf"`, `score: 0.82`, `tokens_in: 320`, `tokens_out: 48`, `latency_ms: 1200`)
* **หลังอัปเดตด้วย PATCH (`APP-HISTORY-DETAIL`)** (ตรงตามบรรทัด 862–865):
  * ชื่อหัวข้อใหม่ (`title`): `"สอบถามราคาสินค้า A"`
  * สถานะใหม่ (`status`): `"closed"`

## 3. Claim Ledger (ตรวจสอบข้อกล่าวอ้างเทียบกับคู่มือ)

| ข้อกล่าวอ้างในบท | สถานะหลักฐาน | แหล่งอ้างอิงใน [langmind-api.md](../../langmind-api.md) |
|---|---|---|

| ใช้สิทธิ์ `chat:invoke` ไม่ต้องขอ write scope ของ agent เพื่อเปลี่ยนชื่อ conversation | **documented** | บรรทัด 21, 667–678 |

| `GET /api/chat/conversations/{id}/messages` เรียงเก่า→ใหม่เสมอ; `tokens_in/out` และ `latency_ms` มีค่าจริงเฉพาะ `assistant` | **documented** | บรรทัด 810–855 |
