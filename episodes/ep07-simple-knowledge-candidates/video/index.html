  "skipped": [],
  "export_batch_id": "batch_20260818_01" } ส่งเข้า Dataset จริงเรียบร้อย
ส่งเข้าคลังสำเร็จ:
รายการที่ approved เข้า Dataset ทันที
รายการ pending จะถูก skipped ป้องกันข้อมูลผิด

3ใช้ผลข้อควรรู้ตาม Contract

เลือก Match Type ให้เหมาะexact ตรงคำเป๊ะ · contains มีคำนั้น · pattern จับคู่ตามรูปแบบ
กฎความปลอดภัยและการเช็กค่าpattern ต้องมี {variable} (ไม่มีได้ 422) · keyword ซ้ำใน Agent ได้ 409
ระบบคัดกรอง Promote ปลอดภัยเฉพาะ status=approved เท่านั้นที่เข้าคลัง รายการที่รอตรวจจะอยู่ใน skipped

เชื่อม API 3 จุด: 1 ตั้งกฎคำตอบด่วน
→ 2 ตรวจอนุมัติ → 3 ดันเข้า Dataset
สิ่งที่ต้องเตรียม อย่างแรกคือ Agent ID
และรหัส Dataset ID ปลายทาง
อย่างที่สอง API Key ที่มีสิทธิ์
knowledge:write และ knowledge:read
อย่างที่สาม ระบบหลังบ้านของแอป
สำหรับเก็บ Key และให้แอดมินจัดการข้อมูล
ครั้งที่ 1: ตั้งกฎคำตอบด่วน
POST /api/simple-knowledge
ระบุ keyword: "เวลาทำการ", response
และ match_type: "exact"
เมื่อลูกค้าถามตรงคำ ระบบตอบกลับทันที
โดยไม่เรียกโมเดลภาษา (LLM)
ครั้งที่ 2: ตรวจอนุมัติคำถามที่รออยู่
ใน Knowledge Candidates
POST /api/knowledge-candidates/review
ระบุ ids และ action: "approve"
สถานะเปลี่ยนเป็น approved
พร้อมส่งเข้า Dataset ปลายทาง
ครั้งที่ 3: ดันเข้า Dataset จริง
POST /api/knowledge-candidates/{id}/promote
ระบุ ids และ dataset_id ปลายทาง
เฉพาะที่ approved จะถูกส่งเข้าคลัง
คืน promoted: ["6b2e..."] และ export_batch_id
ส่วนที่ไม่อนุมัติจะอยู่ใน skipped
Simple Knowledge เลือก match_type ได้ 3 แบบ:
exact · contains · pattern
pattern ต้องมี {variable} (ถ้าไม่มีได้ 422)
และ keyword ซ้ำจะได้รหัส 409
ฝั่ง Promote: เฉพาะ approved เท่านั้น
รายการที่ยังไม่อนุมัติจะถูก skipped อัตโนมัติ
สรุป: เตรียม Agent ID, Dataset ID
และ API Key สิทธิ์ knowledge
เชื่อม 3 จุด: simple-knowledge
→ review (approve) → promote (Dataset)

จากคำถามจริงอย่างปลอดภัยครับ
