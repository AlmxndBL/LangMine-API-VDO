# Video style guide — ระดับซีรีส์

## ทิศทางและสถานะ
Reference ของผู้ใช้เป็นงานหน้าจอเด่นร่วมกับตัวละคร พื้นสมุด/กระดาษ กรอบเข้มขอบขาว ป้ายขอบหยัก รอยระบาย ลูกศรและข้อความสั้นที่สัมพันธ์กับสิ่งที่เล่า
ทิศทางนี้ยังต้องพัฒนาเป็นระบบภาพที่ทดสอบใน sample ไม่ถือ v3 หรือค่าที่เคยเสนอว่าเป็นแบบที่ผู้ใช้รับแล้ว
เปิดให้ปรับภาพรวมตามโจทย์ผู้ชมและเนื้อหาคลิป Reference เป็นข้อมูลอ้างอิง Robot เป็นองค์ประกอบประกอบ ไม่กำหนด art direction หรือเรื่องจากบุคลิกของตัวละคร
ใช้ [Sources](reference/SOURCES.md) แยกภาพจริงที่ดูจากข้ออนุมาน motion; ห้ามนำ TikTok UI/watermark/play/search เข้าคลิป

## บทบาทภาพและข้อความ
หน้าจอ/เหตุการณ์เป็นตัวเอก ภาพต้องแสดงสิ่งที่เปลี่ยน ข้อความช่วยชี้หรืออธิบายสิ่งที่ภาพสื่อไม่ได้
แยก heading, captions และ emphasis ตรวจความซ้ำเชิงความหมาย ไม่วางบทอธิบายหลายชั้นเพราะพื้นที่เหลือ
crop/zoom จุดสำคัญตั้งแต่แผน asset ไม่ใช้ screenshot ทั้งใบทุกช่วง
ออกแบบหน้าจอทุกภาพก่อนเจนตาม [ข้อกำหนดรายภาพ](STORYBOARD_GUIDELINES.md) แล้วตรวจผลจริงกับแบบและสถานะคู่กัน ทั้งภาพเต็มและบริเวณที่ใช้ในคลิป
เว้นที่ว่างเพื่อแยกจุดสนใจ แต่ไม่ปล่อยองค์ประกอบขาดความสัมพันธ์เหมือนภาพวางบนสไลด์

## หน้าที่ภาพ เสียง ข้อความ และซับ
| องค์ประกอบ | หน้าที่ |
|---|---|
| ภาพ | แสดงลำดับ ความสัมพันธ์ ความแตกต่าง ตำแหน่ง หรือผลของการกระทำ |
| เสียงบรรยาย | อธิบายเหตุผล บริบท เงื่อนไข และเชื่อมความคิด |
| ข้อความบนจอ | ระบุชื่อ ป้าย คำสำคัญ ค่าที่ต้องอ่าน และข้อจำกัดสำคัญ |
| ซับไตเติล | ถ่ายทอดคำพูดเมื่อฟังไม่ได้หรือไม่ชัด แบ่งตามจังหวะอ่านและไม่บังสาระ |
นับภาระอ่านรวมข้อความใน raster ป้าย และซับ ไม่ประเมินแยกชั้นจนหน้าจอแน่น และไม่ลดซับจำเป็นเพื่อให้คำดูน้อย
หนึ่งจังหวะมีหนึ่งใจความหลัก ให้เห็นสิ่งที่กำลังอธิบายก่อนพาไปประเด็นถัดไป ขณะอ่านข้อมูลสำคัญให้บริเวณนั้นนิ่งพอและเสียงไม่เล่าอีกประเด็นแข่งขันกัน
เผยข้อมูลตามลำดับความเข้าใจ ไม่ต้องแสดงทุกขั้นพร้อมกัน เปลี่ยนซีนเมื่อคำถาม บริบท หรือมุมมองเปลี่ยน ภาพนิ่งใช้ได้เมื่อสื่อสารเพียงพอ
กำหนดจุดสนใจและหน้าที่ก่อนเลือก motion ตรวจเวลาอ่านจากภาพจริงร่วมเสียง/ซับใน sample ไม่ใช้จำนวนคำหรือเวลาเดียวตายตัว

## ระบบภาพที่ต้องทดลอง
| ส่วน | ทิศทาง | จุดตรวจ |
|---|---|---|
| พื้น | กระดาษ/สมุดลายบางรองรับเรื่อง | ไม่แย่งข้อความ ไม่จำเป็นต้องเหมือนทุกฉาก |
| กรอบจอ | เส้นเข้ม ขอบขาว มีบุคลิกวาดมือ | ไม่บัง raster ขอบไม่รบกวนการอ่าน |
| ป้ายหัวข้อ | สั้น สีชัด ขอบ/texture มีเหตุผล | ไม่กินพื้นที่ demo โดยไม่จำเป็น |
| Typography | ไทยอ่านง่าย แยกน้ำหนัก/ขนาดตามหน้าที่ | ฟอนต์และสิทธิ์ใช้ต้องตรวจจริง ไม่ล็อก Noto เป็นเอกลักษณ์ถาวร |
| สี | ประสาน logo และ robot ขาว/เขียว ใช้ accent ชี้จุด | palette เดิม cream/teal/yellow เป็นข้อมูลทดลอง ไม่ใช่สีแบรนด์ที่ยืนยัน |
| Doodle/ลูกศร | ชี้ เชื่อม ตอบสนอง หรือแบ่งจังหวะ | ไม่เติมกระจายโดยไม่มีหน้าที่ |
| Motion | ใช้ชุด Catalog ที่เข้ากันแล้ว restyle | พาสายตาและเห็นเหตุผล ไม่ใช้เอฟเฟกต์ทุกชิ้น |

## ตัวละคร
ใช้ [robot 44 ท่า](../shared/assets/characters/robot/README.md) ที่ผู้ใช้ระบุเป็นตัวละครกลางสำหรับงานใหม่ ไม่ใช่ presenter คนเดิมของ v3
เป็นภาพเรนเดอร์มีมิติ ตรวจว่าอยู่ร่วมกับภาษาภาพที่เลือกได้ ไม่อ้างว่าเหมือนตัวละคร 2D ใน reference และไม่บังคับใช้กระดาษวาดมือทุกคลิป
เลือก pose ตามบทบาทและตรวจทิศชี้ จุดยืน ขอบ alpha กับขนาดแสดงจริง เปลี่ยนท่าได้ ไม่ทำ lip sync/rigging ล่วงหน้า
ไม่บังคับอยู่ทุกฉาก ไม่ใส่ bubble ถ้าเพิ่มข้อความซ้ำ ไม่กลับด้านไฟล์ที่มีตัวอักษร/สัญลักษณ์โดยไม่ตรวจ
ไฟล์เก่าใน episodes คงเดิม ไม่แทนที่ robot ย้อนหลัง

## แบรนด์และขนาด
ใช้ [โลโก้จริง](../shared/assets/brand/README.md) คงสี สัดส่วนและชื่อ ทุกคลิปต้องมี แต่ไม่บังคับ watermark ตลอด
9:16, 1080×1920/30fps เป็นค่าเริ่มต้น ปรับตามช่องทางก่อนผลิต ตรวจภาพที่ 360×640 และ master
ขนาดตัวอักษร/ขอบปลอดภัยกำหนดจากการอ่านจริงและ overlay ของช่องทาง ไม่ใช้ค่าหนึ่งเป็น universal safe area
ซับไม่เกินสองบรรทัดเป็นจุดเริ่มต้น ปรับตามการตัดคำและเวลาพูด ไม่บังคำตอบ

## เสียงและสถานะจำลอง
เสียงผู้ชายไทยโทนคุยเป็นทิศทางเดิม ยังไม่เลือกบริการหรือผู้พากย์ ไม่ถือ silent preview เป็นจังหวะสุดท้าย
เสียงชั่วคราว/เสียงจริงและเพลงต้องมีสิทธิ์และอยู่ในขอบเขตที่อนุญาต ปรับเวลาตามเสียง ไม่เร่งข้อความเพื่อให้ลงเวลาเดิม
ใช้ป้ายภาพจำลอง/คำตอบสมมติที่เข้าใจได้ ผล API replay ระบุว่าเป็นผลบันทึก ย่นเวลารอให้บอก ไม่เติม citations/metrics

## เกณฑ์ประเมินแยกกัน
1. Technical: assets resolve, seek/playback, layout และ export ตาม scope
2. Visual: ลำดับสายตา ขนาดมือถือ framing typography character และภาษาภาพสัมพันธ์ reference
3. Storytelling: เห็นเหตุการณ์และเหตุผล ภาพกับเสียงช่วยกัน ไม่มีภาระอ่านซ้ำ ช่วง hold มีเหตุผล
4. Audio: เสียง/ซับตรง อ่านทัน เพลงไม่กลบ ตรวจเมื่อมี audio
5. Evidence: claims และป้ายจำลองตรงแหล่ง ไม่มี secret
ไม่ให้ lint/contrast pass แทน visual acceptance ไม่เพิ่ม keyboard/form checklist ให้ MP4
