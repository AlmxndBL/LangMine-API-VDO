# HyperFrames Catalog Usage Map

## 1. ขอบเขตและผลสำรวจ

- วันที่สำรวจ **6 พฤศจิกายน 2569 (Asia/Bangkok)**
- ต้นทาง [HyperFrames Catalog](https://hyperframes.heygen.com/catalog) และ [Sitemap ทางการ](https://hyperframes.heygen.com/sitemap.xml)
- พบ **448 รายการใน 11 หมวดหลัก** จากลิงก์ในเมนู Catalog และ URL รายการใน Sitemap ทั้งสองชุดตรงกันเมื่อเทียบ URL แบบไม่ซ้ำ นับเฉพาะหน้า /catalog/blocks/ และ /catalog/components/ ส่วน Featured เป็นทางเข้าของ Catalog
- เมนูด้านข้างขยายหมวดหลักและหมวดย่อยเพื่อเปิดรายการได้ หน้าเว็บมีช่อง Search ของเอกสารและป้ายจำนวนรายหมวด ไม่พบปุ่มแบ่งหน้าหรือ Load more ในส่วนเมนูที่ตรวจ การนับอาศัยเมนูและ Sitemap จึงไม่ขึ้นกับจำนวนการ์ด Featured ที่เห็นในครั้งแรก
- เปิดเอกสาร Markdown ทางการผ่าน HTTP เป็นชุดและตรวจหัวเรื่องของทั้ง **448 หน้า** อ่านคำอธิบายและช่องปรับที่เกี่ยวข้องเพื่อเขียนรายละเอียดเชิงลึก **40 รายการ** โดยเริ่มจาก Code และงานที่เกี่ยวข้องกับภาพจริง Caption Diagram และข้อมูล
- ใช้เบราว์เซอร์ใน Codex และ HyperFrames Player บนหน้าเว็บ เปรียบเทียบเฟรมและเวลาเล่นสำหรับ **3 รายการ** ได้แก่ Code Typing, Code Diff และ Code Terminal Run ส่วน **445 รายการ** ยังไม่ได้ดู motion ทีละรายการ
- **408 รายการ** มีทะเบียนชื่อ หมวด ชนิด และลิงก์ต้นทาง ส่วนการอ่านเชิงลึกและการเปิดตัวเล่นรายรายการยังค้าง รายการเชิงลึกอีก 37 รายการตรวจจากเอกสาร
- หลักฐานมาจากหน้าเว็บสาธารณะและตัวอย่างของเว็บไซต์ การดูตัวเล่นยังไม่ยืนยัน integration, render, ประสิทธิภาพ หรือความเข้ากันได้กับ asset ของโปรเจกต์

## 2. วิธีใช้เอกสาร

เริ่มจากหน้าที่ที่ซีนต้องสื่อในส่วน 4 หรือค้นชื่อและรหัสในส่วน 3 วางโครงซีนคร่าว ๆ ก่อนเลือกรายการ เปิดลิงก์ต้นทางตรวจ preview และข้อจำกัดอีกครั้ง จากนั้นลองกับภาพและข้อความจริงก่อนยืนยันใช้ในงานผลิต ใช้รายการนี้เป็นแผนที่ค้นตัวเลือก โดยเก็บผลติดตั้งและผล integration แยกจากทะเบียนนี้

| สถานะหลักฐาน | ความหมาย |
|---|---|
| observed | เห็นการเปลี่ยนจากหลายช่วงเวลาบนตัวเล่นของเว็บไซต์ |
| documented | อ่านจากหน้า รายการ ชื่อ หรือค่าที่ต้นทางแสดง |
| assessed | ประเมินประโยชน์กับงาน LangMind API หรือสิ่งที่ผู้วางแผนควรเตรียม |
| unknown | ยังไม่เห็นหรือยังไม่มีหลักฐานพอ |

## 4. ดัชนีตามหน้าที่ในการสื่อสาร

กลุ่มต่อไปนี้จัดเพื่อช่วยค้นโดยผู้สำรวจ ทุกแถวเป็น **assessed** ตัวเลือกขึ้นอยู่กับหน้าที่ของซีนและผลทดลองจริง

| หน้าที่ | รายการที่อาจใช้ | เหตุผลที่ประเมินว่าเหมาะ | เงื่อนไขหรือสิ่งที่ต้องทดลอง |
|---|---|---|---|
| เปิดเรื่องและตั้งคำถาม | [Titlecard Calm](#hf-091), [Glass Shard Title](#hf-005), [Per-Word Crossfade](#hf-077) | เผยชื่อบทหรือคำถามทีละจังหวะ | ใช้ข้อความไทยจริงและตรวจความอ่านง่ายหลัง motion |
| แสดงลำดับขั้น | [Code Typing](#hf-118), [Screen Flow Carousel](#hf-204), [Marker Checklist Card](#hf-242) | แยกการเขียนโค้ด ลำดับภาพ หรือรายการตรวจ | เทียบ cue กับเสียงและจังหวะอ่าน |
| แสดงความสัมพันธ์และการไหล | [Hand-Drawn Flowchart](#hf-418), [Flowchart](#hf-408), [Flowchart Vertical](#hf-409), [Hand-Drawn Arrow](#hf-322) | เส้นเชื่อมและลูกศรช่วยแยกลำดับจากทางเลือก | เช็กการจัดกิ่งและป้ายเมื่อเปลี่ยนสัดส่วน |
| เปรียบเทียบก่อน–หลัง | [Code Diff](#hf-112), [Code Morph](#hf-114), [Comparison Split](#hf-312) | เลือกการเปลี่ยน token หรือการเผยภาพอีกด้านตามชนิดหลักฐาน | จัดแนวภาพจริงให้เทียบกันได้และอย่าใช้สีอย่างเดียว |
| เน้นรายละเอียดหน้าจอ | [Annotate Cursor](#hf-266), [Zoom Follow Cursor](#hf-272), [UI Focus Zoom](#hf-374), [Scribble Callout Circle](#hf-325) | ดึงสายตาไปยังบริเวณเดียว | แปลงพิกัดหลัง crop และตรวจ slot กับ raster จริง |

## 6. ช่องว่างและข้อจำกัดสำหรับโปรเจกต์

- **มีหลักฐานแล้ว** Block ตัวอย่างมีขนาดและเวลาที่ระบุเป็นรายรายการ เช่น Code Typing และ Code Diff ใช้ตัวอย่าง 1920×1080 ส่วน Flowchart Vertical ระบุ 1440×2560 ขนาดตัวอย่างแนวตั้งต่างจาก 1080×1920 ของค่าตั้งต้นโปรเจกต์
- **มีหลักฐานแล้ว** Screen Flow Carousel และ UI Focus Zoom อธิบายการใช้ slot พร้อมตัวอย่างตั้งต้น ส่วน Zoom Follow Cursor แสดงตัวแปรภาพและพิกัดคลิก เอกสารนี้จึงชี้ตำแหน่งที่ควรทดลองแทนด้วยภาพ demo จริง
- **ยังไม่รู้และต้องทดลอง** ทดสอบสระและวรรณยุกต์ไทย การแบ่งคำและซับยาว ตัวอักษรโค้ดแบบ monospace, การจัดวาง 9:16 ที่ 1080×1920 และ 30fps, การรักษา alpha ของ robot PNG และความคมของภาพ raster เมื่อ crop หรือซูม
- **ยังไม่รู้และต้องทดลอง** การประกอบหลายเลเยอร์พร้อมกัน เช่น ภาพ demo + ลูกศร + ตัวละคร + caption รวมถึงการส่งผ่านข้อมูลหรือไฟล์จริงเข้าตัวอย่างที่เอกสารแสดงเพียง slot
- **ยังไม่พบในการอ่านเชิงลึกครั้งนี้** รายการที่มีหลักฐานว่าสามารถวาง robot PNG โปร่งใสทับ raster demo พร้อม caption ภาษาไทยแนวตั้งและรักษาความชัดครบทั้งหมดในตัวเดียว ความต้องการนี้ยังเปิดให้ตรวจ Catalog เพิ่มตามโจทย์ของซีน
- **ข้อกำหนดการใช้กับงานนี้** ใช้ raster demo ที่เตรียมไว้เป็นหน้าจอจริง จัดฉากด้วย HTML ได้ และใช้ diagram, caption, ป้าย ลูกศร หรือ motion ประกอบ ตัวอย่าง terminal/โค้ดใช้แยกเมื่อซีนต้องอธิบายโค้ด การนำ UI ตัวอย่างหรือ chat bubbles จาก Catalog มาใช้แทนภาพ demo อยู่นอกแนวทางที่กำหนด
